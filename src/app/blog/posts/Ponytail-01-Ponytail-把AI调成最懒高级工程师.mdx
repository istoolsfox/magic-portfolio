# Ponytail：把 AI 调成「最懒高级工程师」模式（173k star 实录）

> 你让 AI「加个小功能」，它给你搭了一套抽象层、三个配置类和一个没人用的插件接口——500 行干完了 50 行的活。Ponytail 是一组开源提示词技能，装上后 AI 立刻切换成「房间里最懒的资深工程师」：能删就删、能一行不写两行、标准库能解决就不引依赖。本文把它拆开讲清楚：六个技能各管什么、背后的纪律、数据真假、怎么装。

## 一、先看一个熟悉的场景

你让 AI「加个小功能」，它给你搭了一套抽象层、三个配置类和一个没人用的插件接口——500 行干完了 50 行的活。事后你问它为什么这么写，它说「为了未来扩展性」。

而那个未来从来没来。代码库就是这么被 AI 一点点喂胖的：每个文件都「合理」，合起来没人敢动。

这不是提示词写得好不好运气问题，是模型的默认天性：训练数据里的「优秀代码」多是库和框架——它们天然倾向搭结构。要对抗这个天性，最有效的办法不是反复劝，而是**给它一个现成的人格**：一个见过所有过度工程现场、凌晨三点被告警叫醒过的老工程师。Ponytail 干的就是这件事。

## 二、结论先行

**Ponytail 是一组开源提示词技能（MIT 协议），一句话定位：让 AI 像最懒的资深工程师一样思考——最好的代码是你永远不用写的代码。**

几个硬数据（2026-10-23 查证）：

- GitHub 173.6k star，还在活跃更新（最近提交 10-18）
- 适配 20 个 agent 平台：Claude Code、Codex、Cursor、Kimi、OpenClaw、Windsurf、Pi 等
- 有 npm 包、官方 benchmark、简体中文 README
- 核心形态极轻：就是几个 SKILL.md 提示词文件，拷进技能目录即用

## 三、六个技能各管什么

| 技能 | 干什么 | 一句话记忆 |
|---|---|---|
| ponytail | 主模式：lite / full / ultra / off 四档 | 把整场会话切成「懒人模式」 |
| ponytail-review | 只针对过度工程的代码评审（看 diff） | 只猎复杂度，不管对错 |
| ponytail-audit | 全仓库过度工程审计，输出删/简/换清单 | 「这个仓库能删什么」 |
| ponytail-debt | 把 `ponytail:` 注释收割成债务台账 | 懒可以，烂尾不行 |
| ponytail-gain | 展示实测收益记分板 | 省了多少代码/钱/时间 |
| ponytail-help | 全部模式与命令的速查卡 | 忘了就喊它 |

设计上最妙的是 **ponytail-debt**：懒人模式必然留下「故意走 shortcuts」的痕迹，它在代码里留 `ponytail:` 注释，之后一条命令全部收进台账——拖延被显式记录，而不是烂在「以后再说」里。

## 四、它背后的三条「懒」纪律

**1. 阶梯原则（The Ladder）**：能用标准库就不自己写，能用平台原生能力就不引第三方依赖，能一行就不写五十行。每写一行新代码前先问：这行是不是在重新发明轮子。

**2. 诚实收尾（新版加入）**：每次回复末尾必须用一两行交代——我跳过了什么、没查什么、有什么你必须知道的风险。这条是新版 SKILL.md 里加的，价值极高：懒人模式最大的风险是「省过头」，显式交代边界等于自带验货单。

**3. 懒而不烂尾**：shortcut 全部走 `ponytail:` 标记 + 台账收割，省下的复杂度有账可查，欠的债能被追讨。

## 五、官方数据很漂亮，但注意是自测

README 的 v5 头图写着：**代码量 -53%、耗时 -41%、成本 -26%、token -45%；带测试的高风险逻辑占比从 68% 提升到 98%**。测法是同 agent 开关对比：39 个任务、含一个真实 FastAPI + React 仓库、5 轮取中位数。

怎么看这组数：方法（同 agent A/B、真实仓库、多轮）是认真的，但毕竟是**官方自测、任务集自己挑的**，当参考值别当承诺值。它真正可靠的证据其实是另一个：173k star 是几十万开发者用脚投的票，而提示词技能没有任何锁死效应——不好用早就被卸了。

## 六、怎么装（三条路）

| 路线 | 适合谁 | 做法 |
|---|---|---|
| 官方插件 | Claude Code / Codex 用户 | `/plugin install ponytail@ponytail`（带 hooks 联动，需 PATH 里有 node） |
| **拷技能文件（推荐）** | ZCode 及一切支持 skills 的 agent | 把 6 个 `skills/*/SKILL.md` 拷进 `~/.agents/skills/`，即刻生效 |
| AGENTS.md 兜底 | 不支持技能的 agent | 把仓库的 AGENTS.md 拷进项目根目录 |

两条经验：

- 拷文件式安装**吃不到 hooks 联动**（那是 Claude Code/Codex 插件体系的东西），但技能本体全部生效——对多数人这就够了。
- 升级方式就是重新拷一遍 SKILL.md，没有锁死效应。装之前记一下当天日期，之后瞄一眼仓库推送就知道该不该更。

## 七、和「AI 编程大神路径」的关系

如果你读过本站那套《AI 编程大神路径手册》，会发现 Ponytail 是「约束定义力」的现成提示词化：你不用每次手写「保持简单、别过度设计」，装上它，约束内置于人格。两者正好互补：

- **Ponytail 管「少写」**：压住模型的过度工程天性
- **验收清单管「敢收」**：交付前逐条核对，配合它新加的诚实收尾，一懒一严刚好闭环
