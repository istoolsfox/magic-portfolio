# 124-AI驱动的安全进化

> 这是云栖第一天下午的阿里云云安全专场，满员开讲。阿里云云安全产品线安全总监雷涛先给出总纲——"用 AI 对抗 AI，依托云安全数据飞轮构建持续进化防御体系"，随后代码安全、Agentic BAS/ASM、WAAP、Agentic SOC、安全运维 Agent 五条产品线负责人逐个拆解 Agentic 化实践，中间穿插古茗安全总监刘星光的甲方实战。一句话价值：这场把"攻击被 AI 提速后防御怎么办"从理念、架构、Harness 工程到甲方落地数据完整走了一遍，"召回率 50%→83%、准确率 55%→90%""156 秒还原 HF 攻击链""误杀率 1.8%→0.2%"等数字可直接当选型参考。

## 这场为什么开（背景与定位）

整场成立于一组攻防剪刀差：漏洞数量呈 3-4 倍增长，攻击速度越来越短；雷涛强调官方 CVE 数据还低估了现实——阿里云自监全球开源代码库发现，有漏洞被修掉都没有 CVE 编号，甚至有官方组织不再接受 CVE 申请，"真实的曲线甚至比这个曲线要更加陡峭"。攻击侧因 Agent 普及而平民化：零基础小白也能指挥 Agent 发起复杂攻击、7×24 不间断变种。防御侧却是安全团队不增反减、AI coding 让代码量翻倍审核失控。所以本场只回答一个命题：攻击进入 AI 量级后，安全产品必须整体 Agentic 化——事前代码安全、事中运行时与流量安全、事后安全运营、红蓝对抗持续检测全部重做，底座是三年"三体战略"（基础数据、多云一体化、云产品一体化）攒下的数据飞轮。

## 逐环节超详细还原

### 环节一：雷涛 — 开场主旨：用 AI 对抗 AI 的产品全景图

雷涛先抛结论：AI 速度的时代需要新产品新理念，即"用 AI 对抗 AI，依托云安全数据飞轮构建持续进化防御体系"。两个产品观点：一，云安全所有产品已全部 Agentic 化，从事前代码安全、事中 RunTime 与流量安全到事后安全运营、红蓝对抗 AI BAS 无一例外；二，所有 Agent 都在讲 context，云安全的上下文来自三年前欧阳新提出的"三体战略"（做基础数据、多云一体化、云产品一体化），三年数据迭代构成今天数据飞轮的基础。代码安全是端到端产品：从代码理解、扫描、验证、修复到上线，客户用 Qoder 一个斜杠命令走完全流程；其规则检测"不是正则"，是 15 年攻防经验沉淀的确定性体系（Graph、CodeQL、AST、污点类工具），还在规则层实验更小模型以更低成本解决已知问题，解不掉再上大模型；另一关键设计是漏洞利用条件评估——"烧足够 token 一天能扫一两百个漏洞，怎么修才是问题"，只给真正打得进的漏洞排优先级。流量侧要把含 skill/MCP/多轮对话的完整 session 串起来研判——餐饮客户"托米"用一个 session 还原所有对话、研判不再靠员工猜。BAS 三差异：Plan 极复杂——基于云上资产计算 Secret Graph 与攻击路径，组合 15 年漏洞/在野/攻击事件情报编排攻击计划；Harness 防"过度思考"——他自用千问 3.8 Max、GPT 6 发现模型易在不可能链路 dead loop 烧 token，故建面向 DAG 状态图的工程；蓝军贡献——很多 Harness 和 skill 由阿里蓝军亲手所写。NG SOC 能把云上云下资产、全部安全产品及三方产品串起来，以"数据压制"把 1G 数据压到 100M 控成本——"不少客户用最强模型自建 SOC 仍然买我们的产品"；安全运维 Agent 长在开源框架上，可经 A2A 协议调用户自研 Agent，云上产品 MCP 与全球主流 skill 均已适配。

### 环节二：魏根会 — 代码安全：召回率 50%→83%、准确率 55%→90%

魏根会从年初"代码安全概念爆火"讲起：高频拜访头部企业安全负责人，痛点出奇一致——检测滞后（传统 SAST 卡在 CI/CD，AI coding 后代码量成倍暴增审不过来）、准召率低（基于规则的静态扫描）、闭环难（只给生硬修复建议加参考链接）。产品大图四步：代码接入（Jenkins/GitLab，与 Qoder IDE/CLI 原生集成）→ 上下文资产化（数据调用流、控制面、业务语义、身份资源关系）→ 双引擎协同（规则引擎管已知高确定性问题，大模型管未知与业务逻辑类）→ 审核输出（审核 Agent 以安全专家视角复核，输出代码级修复建议）。与 Qoder 联合发布的原生检测产品把闭环放进研发工作区，与 CI/CD 检测互补而非替代——前者平衡效果与效率，后者从合规角度卡控"不能带伤上线"。Qoder 设置里有独立 security 面板，三层扫描：L1 静态扫描（专家经验沉淀为本地规则，纯本地免费）、L2 轻量扫描（增量代码，约 10 秒）、L3 深度扫描（增量+调用链回溯，分钟级）。在检出率上大模型补上传统 SAST 死角：越权/未鉴权类业务逻辑漏洞规则覆盖不了（不知道身份与资源映射），大模型能识别访问者与订单归属（current user、owner id/租户 id）、通读代码仓发现同模式调用（查个人信息加了鉴权但订单查询没加）、判断路径可达再报；净化函数绕过方面，大模型能看到"检测变量与执行变量不是同一个"、追踪双层编码进 read file 的完整链路，并主动构造绕过验证防护有效性。他强调"准确率可能要比检出率还要重要"——不准确破坏安全与研发的信任；传统 SAST 走宁误报不漏报路线，准确率仅约 50%。三步保准确：大模型输出含引入点、执行点、调用链、业务语义的风险包；审核 Agent 复核、找反例、生成 PoC payload；置信度中等的再进沙箱真实复现，复现才输出。大模型三大病全靠 Harness 治：结论波动（"跟段誉的六脉神剑一样时灵时不灵"）→ 固定任务协议、双引擎、定期数据集回放；全仓上下文贵/慢/证据稀释（整仓扔给大模型跑两三个小时）→ 先建函数调用图谱、按需查询、输出最小证据集；幻觉臆想 → 审核 Agent+PoC 兜底。闭环上 Qoder 检测到风险返回其主 Agent、结合业务上下文与企业 Wiki 修复、修完回调复测。数字：召回率 50%→83%、准确率 55%→90%，修复从天级到十几分钟（Qoder 环境约一分钟）。案例：某头部零售企业 AI coding 转型后代码量翻几倍，测多家竞品准确率仅 50-55%；改用后准确率 90%+、基本无人工介入，集成 GitLab 增量+周度全量扫描、markdown 回写闭环，覆盖 40 多个项目、发现超百个高危/严重漏洞。未来三方向：更懂业务（用户可上传需求文档、鉴权知识）、生成即安全（发现回流模型与 coding agent）、持续联防（漏洞一键在 WAF 生成拦截规则、Swagger 反哺 API 安全）。

### 环节三：陈恒屹 — Agentic ASM + Agentic BAS：把资产变成可验证的攻击路径

陈恒屹从攻击面扩张讲起：资产侧更复杂——多云多账号多团队、多种云资源与身份权限，还多了 Agent、MCP、skill 等新形态资产；风险侧漏洞披露加速、AI coding 让业务变更频繁，版本变更还可能把已修复的历史问题又带回来。他点出研判视角：漏洞总数虽多，真正可利用的占比、自家资产哪些受影响才是关键，刚披露漏洞的加速验证需求越来越强。Agentic ASM 的核心是"把已有资产转化为可被验证的攻击路径"：以资产、暴露配置、身份权限、业务标签等事实为基础，AI 做上下文研判识别候选路径。架构上接入多云配置、互联网扫描与告警，做资产融合与风险打标落到关系图谱，再由 AI 研判节点价值（承载业务、网络可达性、AKSK/身份权限是否过大），底层千问系列模型提供研判能力。典型链路：外网经负载均衡可达云主机，主机有漏洞与配置风险，同 VPC 可横向到其他主机，据此生成攻击链路候选。风险验证分广度（外网资产检查：服务、域名、IP、接口）与深度（关键路径交 Agentic BAS 验证能否真打通）两路。Agentic BAS 即 AI 自动化渗透，通过执行证据动态调整策略、配自建 PoC 库与专项工具，产出"可追溯的结论"——真实存在、可利用，而非"可能存在风险"的虚判；任务输入含目标资产（域名、IP、APK、小程序）、业务上下文、身份凭证与执行约束，底层千问模型按特性路由 Flash/Plus/Max。四 Agent 流水线：侦察（资产识别与深挖、接口发现、域名关联）→执行（规划并测试）→验证（复核防模型幻觉/业务下线/临时变更，保证真实可达）→报告（结论与修复建议）；Harness 底层是安全工具、skill、MCP 与沙箱权限隔离。五步实例：①资产识别+JS 分析——打包或混淆的 JS 人工难看，Agent 能持续分析出接口并构造参数；②权限控制与最小验证——删除接口等敏感操作底层已防护、有害请求做限制；③判别数据是否真敏感——不是 API 未授权就报风险，要结合业务上下文；④产出 BAS 报告。运营闭环：ASM 持续发现资产与变化、联动业务上下文排优先级，BAS 从广度（全部资产）与深度（ASM 候选关键路径）两面测试，复核后交安全运营团队修复与调策略；可做成定时巡检流水线，周期检测资产增减、接口参数变化；重保窗口用 BAS 针对性测试；并与代码安全联动——发布后自动构建沙箱、把测试环境交给 BAS 验证，不必等发布后才渗透。

### 环节四：张宇翔 — WAAP：行为链打分、投毒识别 Agent、天级规则迭代

张宇翔从场景变迁切入：去年主题还是"为 AI 应用做防护"（主流是 Chatbox），随着 Cursor 2.0、OpenClaw、Codex 朝 Agent 迭代，所有人包括攻击者都低门槛用上了 Agent。两个内部判断：今年攻击数字比去年明显增高；且以往多为尝试、真正造成破坏的占比不高，今年生效的破坏性攻击占比显著提高，"可以接近到一半"。三大痛点：变种快（人写脚本要睡觉，Agent 不用可以一直变）；误拦截增多（不断加策略对抗必然带来误拦，见过客户规则两三年不迭代，快消品牌高峰几百万访问量拦掉 20 万感觉不到）；攻击越来越像人（Agent 改 UA、伪造 IP、绕过验证码，甚至控制鼠标键盘模拟浏览器；而正常用户也在用豆包、千问、ChatGPT 提问，如何区分"人问问题"与"Agent 爬数据做信息收集"成了新难题）；再加速度差——开发有 AI 提效、安全团队没有，这个差就是攻击面暴露面。解法一句话："打不过就加入他"，把 WAF 也变成 Agent 的。最基础的是自研安全大模型：基于千问 3.8 后训练，优势是阿里自有模型、数据流不到第三方，且不收集业务数据只收集特征。通过流量自迭代漏洞规则——不再靠安全人员基于新披露 CVE、自挖零day手写规则——从周级别提升到天级，还为每个客户生成贴合业务的定制规则。误报治理靠"智能动态加白"：根据实际流量发现某规则拦的全是正常业务即自动加白；典型如 AI Chatbox 对话里的 SQL/JS 触发注入/XSS 误报，智能加白放行 AI 应用 body，同时配 50 多种 AI 组件特有规则（LiteLLM、Ollama、MLFlow、英伟达 Triton 等）保证加白后组件自身漏洞仍被防护，并可集成 AI 护栏拦提示词注入与敏感内容。Bot 防护从"单点判断"升级为跨天行为链打分，他的比喻极其形象：买水果、买水果刀、订去美国的机票、买奥特曼面具、再到银行对面小树边休息——"每一个动作都很正常，但他们串起来，显然我不是一个好人"；落到产品就是各类行为打异常分（水果刀 20 分、面具 5 分、机票 10 分，同一对象叠加再加分），按分处置，安全运营 Agent 动态调打分机制防规则漂移。识别 Agent 用"提示词投毒/中间人"手法：像特工截电报掺错误信息，在不改变原意下向 Agent 注入信息，Agent 以为是后端正常返回便传递自己的特征，从而暴露"你是 Agent 不是人"，再由安全运营 Agent 锁定类别与具体对象。API 安全靠一套系统跟上开发速度：自动理解敏感信息、接口画像（支付/查询/管理）与 API 结构，开发迭代什么就学什么——API 变了要更新注册、系统可自动动态注册，让安全第一时间知道业务变了。AI 嵌入的时延与成本两难点：时延用线上向量引擎先筛相似度、有症状才送大模型复核；成本靠分模块配专门模型（敏感数据/画像识别、Agent 识别/行为轨迹、漏洞规则、AI 组件规则各用不同模型），不大幅抬高用户成本。客户实证：与头部基模公司合作，标准架构为 Agent 调用→WAF→AI 网关→推理集群，WAF 集群防百万级 CC 与 HTTP DDoS（行业顶级），Bot 识别降低约 30% 止损。收尾：入选 Forrester 代表厂商、IDC 报告领导者第一。

### 环节五：刘星光 — 古茗实战：用魔法打败魔法，零增员扛住代码翻倍

刘星光以甲方视角展开双向挤压：研发侧 AI coding 产出翻倍、交付加快（业务乐见），但审核与上线检测失控——研发提交走 CI/CD 安全来不及审成瓶颈，AI 问题代码没第一时间发现还会被复制到更多场景；攻击侧同一批 AI 产品递到攻击者手上——门槛变低（想法直接给 AI 生成攻击思路）、侦查变易、社工钓鱼逻辑清晰到难判、攻击 7×24 而防守做不到。真实 CVE 数据：2022 年约 2.5 万个，今年 9 月已 6.6 万——官方年初预计约 5.9 万、9 月即破 6.6 万，他预计最终可能超 7 万。攻击也产品化：以前在 kali 执行 PoC 要先定位拿到 PoC，现在把想法加当天爆的 CVE/零day扔给 AI，工具很快出来、精准打到对应机器。更现实的是招人困境：安全团队人非常少，有 headcount 也招不到——经验与企业不匹配、护网经历不等于解决问题的能力、牛人薪资压力大。结论："用魔法打败魔法"——把增人的成本换成买 Agent 安全服务，以 Agent 之 7×24 对攻击之 7×24，安全同学的价值收敛为"最后对核心操作做判断"。古茗架构横轴覆盖开发、测试、上线前、运行时、持续运营，纵轴是小程序→高防→CDN→WAF→API 网关→微服务→数据层→订单会员支付的真实链路。四段布防：开发测试段把 AI 代码审计强行融入 CI，提交即源头查 SQL 注入、越权、依赖 CVE；上线前 AI 渗透测试以攻击者视角沿真实网络路径确认漏洞能否打进，并用完整链路数据支撑定级谈判（P0 不修复不上线、P1 三天内、P2 下次迭代——研发关心能否按时上线，安全要拿真实链路说服而非"我认为它是 P0"）；运行时 WAF+AI Bot 防脚本、恶意爬虫与黄牛；运营侧 Agent SOC 汇聚告警整体研判联动。他强调四个维度不是独立工具而是研发、验证、防护、运营的接力，缺一环整条路都有问题，从代码到上线设三道门：AI 审计净化代码、AI 渗透拦在上线前、WAF 持续治理。案例细节：一次对 57190 端口微服务的攻击只伪造一个请求头就绕过内部互通网关，代码审计关联上下文确认影响并评分——底层依旧依赖 SAST/SCA 提供稳定召回的确定性证据。他重点讲外部红队/众测的失效：请红队众测结果只反映当前版本，报告要半个月到一个月才拿到，"拿到报告的时候这个版本可能已经被迭代了"，更多变成应付等保三级、众测检查的投入；AI 渗透做到小时级输出、每次发布都自己打一遍，让低频验证变成持续能力，重点打小程序接口越权、支付流程漏洞、WAF 绕过、批量接口滥用。AI Bot 侧传统库固定靠关键词手动维护，而快消品牌需要部分爬虫带来品牌曝光、不能一刀切，故分四类处置。效果：误杀率 1.8%→0.2%、自动化识别率升至 42%、Bot 规则验证 3 天→半小时甚至 15 分钟、上线前修复占比 90%+、接口覆盖扩大 5 倍、单次渗透从周级降到小时级、流入生产的高危漏洞减约 70%（保守值，实际更高）。踩坑三条：误报毁信任；定级不能安全单方出，要和研发共建优先级与修复机制；报告必须可复现——以前工具输出只有安全自己懂，现在 AI 生成完整可复现报告让研发信服。第二实战是 SOAR 重构：告警多到重要信息被静音淹没、溯源看不清路径、手动处置慢；旧架构 K8s、ECS、线下 IDC 及交换机/路由器/VPN（SNMP 数据落本地或 Zabbix）日志各自为政，新架构统一采集到同一位置由 AI 联动上下文分析。攻击回放中以往工程师面对多条入侵路径是盲目的，AI Agent 2 分 30 秒定位并创建事件、反复验证确认为真实攻击后处置出报告，自动化处置率大于 90%。关于取代：现阶段不会——AI 产物仍有问题不能直接用其策略，人的价值反而更高（判断整条链路有没有问题）。未来方向：供应链安全、AI 情报反哺内部知识库、安全基建融入整体业务体系。

### 环节六：陶夏薇 — Agentic SOC：从 Copilot 到 Autopilot，156 秒还原 HF 攻击链

陶夏薇聚焦 SOC 运营负责人最关心的事：AI 能研判告警后，怎么实现自动化端到端闭环。以七月份 Hugging Face Agent 逃逸测评沙箱事件为引：Agent 经三方平台跳板进入 HF 数据链、扩展到集群、拿到身份权限甚至内网数据库与代码权限，官方披露借助中国大模型把通常数天的分析压缩到数小时。人工为什么难？她把调查拆成五个证据来源——测评与制品日志、K8s 操作审计日志、云操作审计日志、主机日志、代码/数据库层——单系统都可能拿到证据，难的是自动化串成链路图：时间对齐、身份到工作负载映射、进程活动归属哪个资源，全要人工串，卡点就是人。去年 Copilot 只做告警总结、命令说明、处置建议，跨域证据拼凑与任务推进仍靠人；目标形态 Autopilot 分工明确：安全运营负责人设定目标并保留授权（人在环内为业务影响把关）；Agent 组织理解目标、持续推进计划、协作调 skill 工具完成端到端运营；Harness 作为运行底座保证结论合理、不越证据边界、权限受控。多 Agent 协作：任务调度 Agent 接收命令、明确优先级与完成条件，拆解给云安全、终端安全、身份安全等领域专家 Agent；加速不只靠模型节奏，更靠减少串行等待与重复取证——先明确任务契约（目标、完成条件、何时转人工），再判断可否并行，收证后由 Harness 验证。能力生产侧同样工程化：真实事件发现检测缺口→冻结样本→自动定位问题、自动构建发布→样本重放+自动化安全验证→灰度→人工审核放行（最后一步必须人工，人控制生产目标与验收标准）。能力生产"不单是 prompt 优化"，是含任务契约、AI 资产件、可审核契约的完整发布包；只依赖大模型输出不稳定，必须保证每个证据可查询、结论不越界、动作在安全边界内，执行侧还要校验缺参数与否、对象是否唯一。每次迭代发布跑 SOCbench：片中 211 道、现已累积 230 多道，覆盖 16 类攻击场景，围绕调查五阶段（环境定位、入口确认、主链还原完整性、影响范围、结论准确性）逐段打分，再加能力维度画像综合评分，并平衡效率与稳定性；训练的是 Agent 能力生产工作站交付体系、不训练大模型，但底层千问每次升级也要重跑 SOCbench 保证交付稳定。靶场验证基于 HF 公开技术路径搭建：MLflow 应用入口定时任务→工作负载执行权限→K8s 集群入口→取 service token 与 secret 凭证→更高 K8s 权限→创建特权 Pod→越权拿主机 Node 权限→主机绑定的角色 STS→云账号权限→临时打通隔离网络→控制内网主机访问生产 MongoDB 与代码。效果：team leader 研判拆解并调起告警分析、云主机、网络、身份等专家 Agent 协同；一个细节体现严谨：云审计日志看到资源操作与网络打通、主机侧看到进程执行命令，但两者间没有网络日志直接关联，Agent 只做逻辑层面关联并明示。思维链透明设计：结论区分"正确事实/推理关联结论/缺数据"——如数据是否已出内网，没证据就不下结论只告知缺数据。总效果：关联 7 个告警、22 个关键实体、2 个受影响资产，全程 156 秒（与古茗侧同量级），此复杂度人工协同需数小时。处置环节 Agent 先校验恶意实体参数与对象唯一性，自动推荐一键处置，最后由人在业务影响范围内审批。半年多客户效果：典型客户从控制台 5 天降到一周 0.5 天（只介入高危严重事件）；有 APT 事件调查 20 多分钟出结果，整体保守 30 分钟以内。

### 环节七：岑黎光 — SecOps Agent 压轴：自然语言运维、PolicyGate 三层管控

压轴的岑黎光先向听到最后的听众致谢，随后抽象出安全团队三重压力：日常重复任务的自动化维护负担——静态规则/剧本过去隔段时间调一次，现在业务与安全产品迭代极快，调整频率是原来的 10 倍以上、几乎每周要调；关键信息通知同步——不是所有事都该全自动，什么信息值得同步、多快提取出来是压力；规模化处置——账号产品越来越多，处置能力须随业务规模自动扩展。对工具的四条要求：持续理解业务上下文；提供"站在所有云安全产品之上"的统一自然语言运维入口，打通所有产品 API、内置安全场景 skill 与 MCP 工具；有授权边界；产出可复核可观测结果、敏感动作进审计——"人的执行和 Agent 的执行还是要区别对待"。现场演示：自然语言输入"梳理有暴露面的资产的高危漏洞"，任务拆给子 Agent 形成报告（哪些资产暴露外部服务、哪些高危漏洞优先修复）；因修复可能涉及内核升级，一定由人工确认快照策略后下发、邮件通知。三案例对应三重压力。案例一：某企业主账号挂 50 多个子账号、近 2000 台主机，安全团队每天 9 点逐账号切各控制台看告警漏洞、整合成晨报——"一个上午就没有了"，真正运维下午才开始；用 SecOps Agent 后配好 9 点定时任务（汇总近 24 小时高危告警与未修复漏洞、授权范围内联合网络安全产品核查修复优先级、合并历史任务进展与今日新任务），9:20 报告已在邮箱，人工复核 15-20 分钟即可发出——相较原来近两小时是质的飞跃。他归纳五个高频场景：告警批量查询与处置、资产全景调查（跨账号跨产品信息原本散落各控制台）、周报总览、多账号漏洞与配置治理策略下发、通知分发（邮件/钉钉等 IM 集成）。案例二：某外企要求云产品一变更即触发扫描、算出增量 diff，并关联自家 CMDB 定位修复责任人——链路为感知变更→触发扫描→取最新报告→关联 CMDB→生成带责任人的报告，通知出去的消息已是"待认领的、确定的、需要谁去修复"的信息；通知机制相比传统预设模板的改进是触发式启动+内容提示词定义（页面下发什么任务、邮件就收到什么内容），并打通云账号联系人体系（邮箱、电话、短信），可覆盖风险摘要、处置结果、修复提醒、超期单点通知；与三方 CMDB 以 skill/MCP 连接，产品本身 API 串联天然打通阿里云全产品。案例三：某集团客户要多账号降漏洞量、梳理最高优先级漏洞并用 Agent 修复，三个担心——凭什么信 Agent 的优先级判断、敏感修复（内核升级可能致工作负载不兼容，支付系统影响被无限放大）如何安全执行、如何区分人的操作与 Agent 借用云账号身份发起的操作。解法：优先级判断联合云安全中心、云防火墙、WAF、攻击面管理等多源上下文综合评判可利用性与业务风险；高危修复先做预案（快照、保留时长、回滚方案）；专门角色在云控制台操作审计中把 Agent 指令与人工记录区分开，保证"知道它套在笼子里、边界在哪、做过哪些动作"。重头戏是 PolicyGate 模块：通用 AI 工作台有云账号权限后只要 API 参数填对就执行，做不到的是安全视角——知道漏洞修复、访问策略变更影响的背后资产与对外业务；以修复 12 台 ECS 系统漏洞需重启、内核兼容性无法提前预估为例，强制确认快照与回滚预案。三层控制：意图识别层判断动作是否有业务风险；行为校验层硬校验——哪怕提示词写明快照与回滚预案，触发修复或策略变更 API 依然弹出预案要求人工再确认；强制留痕——所有过 PolicyGate 的风险动作强制留痕，事后可追溯"哪句提示词触发了哪些动作、产生了什么业务影响"（有自动审批开关，但业务影响类变更仍建议走校验）。一方 Agent 自身安全交给 Agent 安全中心（身份权限、skill 供应链扫描、运行时检测、输入输出敏感操作复核），客户自建 Agent 同样可用，并预告次日专场详讲。效果数据：单任务人工时间减 60%、告警分诊时长缩短 2/3、有效处置时长缩短 70%——处置前考量已提示到位，拿 Checklist 评估后安心下发、审计兜底。收尾点题：让 AI 承接更繁杂的安全运维动作，人介入的流程专注提供更关键的判断。

## 这场的意义

对行业而言，这场给出了一份"安全产品 Agentic 化"的完整参考实现：五条产品线不约而同收敛到同一套工程范式——确定性体系（规则、小模型、向量引擎、SAST/SCA）解决高频已知问题，大模型只接难问题并按 Flash/Plus/Max 分层路由，再用 Harness 治大模型三大病（结论波动、上下文成本、幻觉），最后以"审核 Agent+沙箱 PoC 复现+最小证据集+思维链透明"保证可信。这印证了一个正在成型的共识：安全 Agent 的竞争力不在模型调用而在 Harness 与数据飞轮——阿里云敢讲"三年三体战略攒下的数据管线"，古茗敢讲"底层依旧依赖 SAST/SCA 提供稳定召回的确定性证据"，是同一件事的两面；甲方落地教训（误报毁信任、定级共建、报告可复现）则定义了安全 Agent 进入真实研发流程的社会学门槛。

对个人与从业者而言，两个信号值得立即行动。其一，攻防剪刀差已经数据化：CVE 从 2.5 万涨到 6.6 万、破坏性攻击占比接近一半、Agent 攻击 7×24 不间断——还在"人工+静态策略"上堆人力的团队，该把"单位安全任务的自动化率"当成第一指标重新盘点防线；古茗证明零增员承接研发产出翻倍可行，路径就是三道门（AI 审计进 CI、AI 渗透拦上线、运行时持续治理）加 Agent SOC。其二，人机边界的产品化设计已有现成模板：PolicyGate 三层管控（意图识别、行为硬校验、强制留痕）、Agent 操作与人工操作在审计中可区分、Agentic SOC 的"结论区分事实/推理/缺数据"，都是已上线能力，可直接抄进自己的权限与审计设计。至于"安全人会不会被取代"：现阶段不会，但价值重心已从"执行与尝试"移到"最终研判与链路判断"，越早转型为"带着 Agent 找威胁的人"，越能在下一轮洗牌中占据有利位置。
