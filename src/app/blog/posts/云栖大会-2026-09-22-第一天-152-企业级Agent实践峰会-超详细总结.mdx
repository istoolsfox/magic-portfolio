# 152-企业级Agent实践峰会

> 这是云栖大会第一天下午的企业级 Agent 专场：阿里云资深副总裁刘伟光开场定调，随后满帮、贝壳、易方达、机源律动的实战派负责人与阿里云三位业务负责人轮番登台，把 Agent 从 demo 走进核心业务的坑、选择与验证路径原原本本讲了一遍。全场一条主线：Agent 跑起来只是第一步，跑起来之后怎么管、怎么算账、怎么持续优化，才是企业真正要回答的问题。满帮的 2000 个 Agent 打崩生产系统、易方达的金融级四个九、小红书的上下文 GC，都是别处难听到的一手细节。

## 这场为什么开（背景与定位）

主持人开宗明义：请来 6 位来自互联网、物流、房产、金融和 AI 原生企业的实战派嘉宾，原原本本分享真实场景中踩过的坑、做过的选择、验证过的路径——全场气质由此定型：不讲愿景叙事，讲工程账。背景是 Agent 落地正跨越分水岭：上午主论坛讲模型、算力这些"弹药"，企业侧痛点已从"能不能用"转向"敢不敢放进核心业务流程"。满帮要它进真实交易，贝壳要它支撑买房决策，易方达要它过金融合规，阿里云自己先拿总裁分身做组织实验；五路实践加圆桌"账怎么算、怎么管"，凑成企业级 Agent 的完整问题域：架构、组织、进化、成本、治理。

## 逐环节超详细还原

### 环节一：刘伟光开场致辞 — Agent 时代的判断

刘伟光以"这是我的第十次云栖大会"开场。十年前他讲容器化、分布式架构、云原生，自嘲"当时还是没有远见"——若敢预测七年后的 ChatGPT、九年后的世界模型才是 vision。他见证云的时代走到"AI is everything"：今天所有应用都是人写的，他相信不久的将来都由 AI coding 完成。

他给出已验证的判断：去年所有公司在 AI 上的收入，会低于今年 AI 收入增量的 10%——今年全社会在 AI 上的消耗远超去年，甚至十倍到百倍。Agent 的理解两年间天翻地覆——不再是工作的补充，而是"帮我们完成我们做不到的事情"，从办公处理深入千行百业核心业务流程，变成核心业务系统的一部分。

最有分量的是企业真用 Agent 的三条标准：一，把 Agent 停掉，企业有没有影响；二，能否独立闭环完成任务；三，用 AI coding 大量造 Agent 之后，是否需要建以 Agent 为核心的安全治理平台。他透露阿里巴巴要用 5~10 年把这家 27 年的公司全部业务打造成 AI native，Agent 深入使用是必要条件。他还点破 Agent 与软件的本质区别：软件不迭代就不会进化，真正有效的 Agent 需要模型、harness 和数据共同演进。"可能在几个月之后，我们每一个人都会有属于自己的 Agent"——那时的 Agent 不只是代理，而是任务的话事人、身边的顾问和企业大脑的综合体。

### 环节二：韩宏元 — 面向 Agentic 时代的工程底座

韩宏元先画市场盘子：企业在有边界的业务里提效，受众为约 3000 万程序员、2 亿白领和千行百业场景；企业级需求也不同——统一任务分发、统一记忆底座、信任治理边界、持续迭代循环。

三个维度展开。编程：coding 目前是个人提效，很多企业尝试后不及预期——软件投产与研发全链路相关，须跟流水线、CI/CD 整体结合才见效，未来走向 AgentOps。办公：他提了句昨晚美股芯片股因 Meta 的 MUSE 应用大涨——Agent 落地扩散连资本市场都在定价；未来人机混合编队还带来大量组织协同问题。行业系统：以前是人适应软件（格式不对就走不下去），Agent 第一次可作为 interface 让人用自然语言指挥系统；再往前需确定性智能经检验进入业务流程，最终走向 Agent Based Decision——更少决策由人做。

他给出企业级 AI 基础设施分层参考框架（底层模型推理与公共云"电网"角色 → 模型服务底座与 Agent 设计 → 合规治理、数据安全、AI 应用安全），并抛出关键判断：写代码变容易后，技术架构的设计管控能力反而更重要——"软件和程序是两件事情"，程序写好到处运行，软件要持续检验，检验比写更难让 AI 实现。最后落到 Agentic Cloud：云的使用者从管理员和开发者扩展为 Agent；阿里云的底气是全栈自研、云原生与数据底座、训练千问的超大规模实践和几百万企业客户。

### 环节三：高艺铭（满帮）— 让 Agent 进入真实交易

满帮是车货匹配干线物流平台，几百万货主、几百万司机。任务时间极长：司机除开车外一天 3 小时找货，货主发货找车跟单整单 1~5 天，运费几千上万，需求还持续变化（"今天要回南京，这票可以接，但价格要 1500 以上"）。物流协同从线下电话+园区小黑板到信息上网再到平台化，最耗时的"做决策"始终没解决——Agent 第一次使软件可能承接"帮用户做决策"：司机 Agent 盯货运营、货主 Agent 接管每天几百个电话和跟单、平台 Agent 做公平规则。

他的生产级 Agent 公式：业务目标 × Context × Harness × Runtime + Evaluation Loop——对企业最重要的是业务目标和自己的上下文。四个难题全是踩坑换来：一，物流对话高度异步，用户连续补充、反悔、加条件；最初设计意图识别模块增加确定性，结果真实场景根本不存在纯粹单意图——一句话往往问答、执行、议价绑在一起，单意图设计"限制智商上限"。二，每天几千个 bad case，改 prompt、改 skill、加 tools 打补丁，以前一周上线一个需求、现在一天几百个改动，劣化远快于传统系统——司机 Agent 的 benchmark 涨到 67 分后再也上不去，系统债必须定期清理。三，知识注入要节制：司机货主不写 wiki，"标箱"会被认成厢式货车、实为拉标准箱的平板车，必须注入；但全量文档做检索发现大部分没价值——甚至有文档教用心理学议价，垃圾知识注入会让系统整体劣化。四，第一次扩量到 2000 个 Agent 就把能扛几百万用户的生产系统打崩——Agent 请求速度远超真实用户、大量调工具、24 小时运行造成请求海啸；大规模商业化 Agent 本质是高并发系统，状态持久化、按需唤醒、事件压缩、排队缺一不可。

架构结论是"两套系统一层桥"：传统系统保证撮合下单等确定性流程稳定执行；Agent 系统处理不确定性与持久运行（含全平台统一的司机货主记忆）；桥接层做鉴权、高风险拦截和错误翻译——传统系统返回 219 错误码 Agent 读不懂，要翻译成"缺少车长，根据吨方建议 13 米或 17.5 米"。"Agent 处理不确定性，工程保证确定性"。上线只是开始，"不太敢相信任何新上线 Agent 能打超过 20 分"；双循环：外循环对齐业务与技术指标（正确率 20% 到 70% 时留存一直涨，到七八十后不相关须重新对齐），内循环用 trace、日志、评估归因，基于 bad/good case 形成 golden set 全量回归再灰度；准入红线是加价、成交、电话——错误一次几百次正确都挽回不了。经济性上架构必须"水涨船高"：上半年换一次基模，做得好的 Agent 成本降到 1/4，做得差的成本没降准确率反降。护城河：基模和 harness 只决定上限，数据、经验都不是壁垒，能转化成自己高质量的 context（每个字地看传给模型的请求）和自己的 Evaluation Loop 才是；产品心智已翻转为"少刷货、少空驶、少电话、少熬夜，把时间还给家庭和生活"——用户愿意再一次委托才是真护城河。

### 环节四：施磊 — 给 Agent 一个工号：从总裁分身到数字员工

起源是年中给阿里公共云总裁做的领导力分身 Patrick。短片借孙悟空被压点题："压住你的不是妖法，是信息过载和管理颗粒度太细"——高层管理者同样被战略传达走样、经验难复制困扰。片中 Patrick 清晨整理经营早报、遇数据波动自主找人调研追问到底、一句"落实"任务直达执行人并周五回传闭环、每日把经验沉淀进知识库，提供 7×24 总裁级咨询。核心台词："当一号位率先把自己数字化了，组织的变革就不再是喊口号动员，而是变成了大家的本能。"

他先讲"个人提效不等于组织提效"：过去用 Agent 当工具写周报处理文档，事事经过人，人成瓶颈；Patrick 端到端自主工作，第一件事是把管理者从"催、盯、记"里解放出来。Patrick 有自己的工号，能被拉进钉钉群、被 @。起初同事不习惯——头像跟总裁一模一样的账号来聊项目还会一轮轮追问；慢慢发现信息上传下达效率变高，一线销售甚至主动问 Patrick："我今天有个客户要拜访，你作为总裁分身能不能给点建议？"

Harness 工程三件事。一是"像"：讲话风格像——收集开会听记和内外部发言共 1000 多条语料，用大模型提取讲话风格、惯用表达和口头禅，写进 AgentMD、SoMD、ProfileMD 等 Markdown 人格文件；业务判断像更难——把管理者过往业务决策作为推理 few-shot，且要时常更新。二是自我进化：三层长期记忆——情景（每天谁聊了什么）、语义（事实与偏好）、社交记忆（人和事物的画像，决定分身的判断），每晚从当天对话定向提取逐层更新。三是安全管控：分身必须是独立权限个体（与权限极大的管理者本人共用账号隐患极大）；调 MCP 工具走零信任，身份鉴权贯穿交互链路，确保用实际对话者身份而非公共账号调工具。

Patrick 上线两三个月，公共云事业部已有六十几个有工号的 Agent（定义：独立工号、明确职责、能端到端完成任务）。两类形态：管理者的"团队智能/team brain"（蒸馏业务策略），和岗位型数字员工——如销售运营中台的数字员工回答政策折扣并操作业务系统，运营同学变成它背后的运营；又如放进客户协作群聆听客户与售后工程师的产品讨论、自主决定何时接话帮排查。管理三实践：上岗审批（曾出现两团队技能重复建设，须业务 leader 与 HR 联审）；协作（AI 网关连通所有数字员工，各自维护自然语言岗位职责说明，A 按 JD 找最匹配的 B 求助再回传给人）；复利效应（数字员工产生的上下文含企业最新信息，写回知识库，做得越多回流越多）。外部落地路径是从后往前做——法务、财务、运营等中后台岗位 SOP 全、文档多、收益明确；零售客户案例分两步：先把销售陪练 AI 化（大模型生成脚本、员工语音对练、AI 打分），再封装成钉钉有账号的 AI 陪练专家，小组长下任务让它顺企业通讯录找需陪练的员工开展对练并回传结果。收尾三阶段论：用 AI 工具（人是瓶颈）→ 数字员工（人做经营者）→ 人机共生网络（按知识技能围绕业务目标动态协作）。

### 环节五：韩凯（机源律动）— 从 Harness 到 RSI 飞轮

机源律动是 Agent 原生公司，做 Agent 服务、Harness API 和 Agent 模型。韩凯从 Agent = Models + Harness 出发：模型决定智能上限，端到端交付靠 Harness 保障。"做一个 Harness 用 AI coding 很简单，做一个好用的 Harness 却非常困难"——现有 Harness 三不足：上下文失控（长任务溢出）、执行不可靠、成本不可控。

答案是开源的 OpenSquall：微内核架构——极简核心只留 ReAct 或 Planning 模式的 Agent loop 保稳定，上下文、工具、记忆、Skills 全插件化，加三级安全策略。四个特性：模型切换+上下文压缩+思维链分级省成本；多模型协同；Meta Skills 协议解决海量 Skills 不知选哪个、怎么编排；四层类人记忆（工作、情景、语义、原始层）按需加载减 token。数字：在经典 Agent 办公任务评测 Pinchbench 上成本降 88.9%；与千问做小游戏，3.7 Max 只能基础可玩，3.8 Max 接入后几乎一次出成品级交付；在 Perplexity 的深度研究评测 Dirac 上，3.7 Max 与海外顶尖模型（如 OPPO 4.8）有差距，3.8 Max 接入后反超，OpenSquall 再组合多模型拿到 63.1 分、比海外旗舰 Fable 5 高三个多点，成本只有其 1/3。

下半场讲 RSI（递归自我改进）飞轮。通用模型在企业场景不一定最优的三个原因：能力错位（通用语料训练，缺交错式推理、长程任务链和环境反馈信号）、信号稀疏（高质量轨迹难获取，人工标注覆盖不了真实多样性）、飞轮缺失（模型不知自己错在哪，须与 Harness 在真实环境运行才暴露）。闭环四步：阿里云 ECS 批量构建隔离环境规模化合成真实轨迹 → 强门槛准入（结构化校验+六维语义评估）→ 基于千问 3.5 的 4B/9B 后训练 → 新模型放回 Harness 真实环境再评估，循环迭代。算法创新三点：交错思考监督（把整个用户轮含多次调用的轨迹链与最后一轮思维链一起训练）、三阶段课程学习（用 Harness 拿到任务难度，从易到难）、路由引导的 OPD 蒸馏（好 teacher 对当前模型做 token 级监督）。成果：自训 NewHouse 模型在 10 项 Agent 任务上，4B 版比千问 3.5 4B 提 5~6 个点，9B 版提 3~4 个点。整套跑在阿里云上（千问 API、搜索工具 IQS、ECS 沙箱、PAI 训练平台），后续在千问共创、云基础设施与 MaaS、品牌生态三方面与阿里云合作。

### 环节六：尹俊熙（贝壳）— 房产认知决策智能体的构建

开场提问很妙："在座有多少人买房、卖房、租房时没被坑过的，请保持安静"——全场安静就是答案。他出身 Research Lab，关切基础技术的工业落地。问题空间：房产失去投资属性后，买房从"买到即赚到"变成决策过程本身最重要；信息不透明贝壳平台化已解决，真正难点是海量决策空间找路径——房子高度非标，刷列表找不到最需要的房；很多人难决策的其实是自己的需求：买房影响两代人，"要不要为学区放弃生活品质"，海淀核心学区一家人为孩子挤在逼仄环境是常态。所以几乎所有人都在做多目标多约束的最优化——新时代命题"不再是搜索，而是决策的智能"，已被业务验证。

框架分理解人和理解房。理解人：真正的需求画像是 hard constraint、soft preference、随买房周期演化的心智变化。理解房：一套房不只是三室一厅朝南朝北的静态字段——买中关村一小的房子是哪所学校的教育入场券，住万柳代表什么圈层、孩子什么选择；建这张图谱是壁垒极深的行业。底层用"本体论"组织（房与房什么关系、什么人喜欢什么房、人房关系由什么核心因素驱动），上层从条件匹配走向多目标权衡、空间理解与长期辅助决策。他插了个观察：大家觉得 Fable、Astra 这类模型"好懂我"，是因为它见过大量的人和知识、知道你接下来会问什么——这种能力可从最强模型抽象融入业务。他主张"能力应该野蛮生长"，但业务 harness 要保下限：精准需求理解、性能稳定、数据回流做历史分析——既帮用户做反事实、略带惊喜的选择，又要让用户足够信赖。

进化体系分参数与非参数两层，三层智能决策架构（他点破这就是 Recursive Self Improvement 的基础架构）：顶层靠自然语言、多轮反馈和地图空间交互从产品末端拿反馈——才能定位 harness 长链路里是检索、信息压缩还是多 Agent 交互出了偏差；编排流程不再是唯一约束，更像 oracle，Agent 在框架下自主动态选工具；一切积累成高质量轨迹，而高质量轨迹依赖高质量反馈。贝壳从早年起分场景用千问小模型到 Max、Flash。工程关键是"轨迹白盒化"：不仅回答好，过程每个都要对——模型一定 follow 检索数据、知识可控、决策路径可控、公司 guideline 控制输出；有了高质量轨迹才能做 SFT、RL 等后训练。经验之谈：构建 RL 时环境反馈往往最重要，而建业务反馈环境并不容易。贝壳与千问团队在技术和 Infra 上深度合作，高质量数据抽象成更高维知识反哺千问。终局是持续学习：短周期适应+长周期主动学习，从 AI 检索升级为智能领航员，为策略决定提供战略输入，支撑核心交易决策。

### 环节七：刘硕麟（易方达）— 金融智能体实践与思考

刘硕麟首次以嘉宾身份参会，开场自嘲："连主持人都没有了，是个 AI 叫我上来的……我是 AI 的人类 Agent。"他打趣很多嘉宾材料都是 AI 写的，最后一个讲 harness 只能"做个 Flash"。易方达管理超 4 万亿资产、近 2 亿客户；面试者以为懂 AI 算法来资管公司就能用 AI 赚钱，实际有极多合规限制和场景边界。他自述从 AI 研究起步、"还会古法搓算法"，而今天"算法工程师"已说不清干什么；企业最困扰的是引入即过时、分不清谁好用（"在这回答就是阿里好用"）。

研究员用 AI 四阶段：一当搜索框——后来发现用户最在意的不是模型聪明而是数据源靠不靠谱，信息的准确性、来源和丰富程度比模型聪明更难。二做深度研究——金融报告七八十页塞不进去；每阶段都有人问 AI 会不会替代投资人员，答案都是不会。三进入 Agent 阶段——最好的用法是有研究员在平台"镜像了一个自己曾经的投资哲学"，在决策分歧或自我犹豫时跟自己对话、被自己反驳。他深受 Patrick 触动，做 CIO 第一件事就是做自己的分身"数字 CIO"，想象大家问 IT 项目进度、预算余额，结果问最多的是"刘硕麟在哪"，于是开放考勤数据，"今天问的话就是在杭州"。四是 AI 驱动的研究体系——还没到，都还是传统投资体系为主、AI 当助手。他还点出金融 AI 问答高于通用（类比 299 会员开金融版 skill 用户愿付钱）；金融客服至今大量人工，养老钱出问题时"那边是机器人，你未必得到满意答复"。

实践是平台 eWork：基于阿里开源框架、启动很早，"庆幸当时还能用 eWork 这个词，要放现在满机场都是某某 Work，得改成易方达 body"。eWork 本质也是 harness，帮企业平滑外部变化，如今已是每人每天用的工作平台。算力层自有算力+阿里云整合（T 级模型出来后自有算力推理"非常痛苦"）；KV cache"性价比非常高"——50% 的提问是"今天市场怎么样""帮我收集早报"这类雷同问题，缓存让延迟和成本大降。数据层：呼应护城河——"可能真的效率是护城河吧"；最抢手的生产资料是治理后的数据，AI 数据治理已成战略项目，harness 给了"以用促建"的机会。模型层用联邦学习理念做大小模型协同、数据不出域，基于千问 4B 学生模型后训练了金融语义理解模型（已发 paper）——"百姓大药房"通用模型未必知道是上市公司，加小模型整体准确率高非常多。架构选型史：第一版基于 OpenCloud（当时基本唯一选择），后发现大量 bug 且无法 merge 回主分支，切换到千问 Pod 社区版后 bug 少很多——金融要求 4 个 9，选技术不只看上限更要看下限，"任何一个 bug 都是真金白银的损失"。Skill 层更多是管理问题：一把手自上而下推动（几次大推广都是董事长总裁级别才能推），内部 AI 大赛明天还有决赛、总裁带队评十个最佳案例，"给年轻人甚至逆天改命的机会"，绝大多数 skill 由业务部门开发。安全是 to B 与 to C 最大区别，团队花极多精力测漏洞，可自信 eWork 达金融级，但最核心业务仍在沙盒——"管的是老百姓的钱"；算法工程师正转型安全评测，他引 Gartner 说法"首席信息官也叫首席保安"。收尾：上线时工作才刚开始——skill 上线后跟踪两三周使用量，没有提升就淘汰；skill 大量重复（他写了平台第一个 skill"用公司模板做 PPT"，后来别人做了个更好的），不能像 App Store 堆两三万个，须持续进化治理。

### 环节八：圆桌 — Agent 的账怎么算、怎么管

主持人霍泰稳用真实案例开场：朋友公司做 AI 应用有个开关没关，token 一直算，上月成本原来 1 万块能 cover、这次超了 3 万。郭龙岭（众阳健康）谈"何时意识到 Agent 是基础设施"：医疗容错极低——不可能下错药、不能无缘无故开手术；当医院医生、护士、管理者主动想让智能体参与工作时就不是试点了；医疗是循证医学，每个决策必须可解释、人可管控接管。规模化时医生授权、身份验证、患者信息安全不能重复建设，他们与阿里云合作用 AgentScope 与 AgentLoop 统一管理。主持人顺势讲了个"豆包科"笑话——病人对医生说"问了豆包不是这样"。

飞鸿（小红书）谈预算目标：人的版本是目标从"既要又要"变成"既要又要还要"（能力好+规模大+便宜）；真正有效的是"面向经营单元的成本可观测"——把技术预算算清到底服务哪个最小经营单元、对方愿不愿付钱，"有的业务团队愿意一个月付 300 万，成本在他那个领域就不是第一优先级"。郭龙岭讲算账：医疗链路从挂号分诊到门诊住院康复近千个应用拆到场景级——输入输出是什么、指南等固定部分固化进参数、按医患语料裁剪输入、输出只提取关键信息（诊断、开药、检查检验），"像每家装了电表"。龙雾（化名，阿里云 AgentLoop）给出前提：先有观测能力，看得清才能决定能否规模化。观测三层：基础指标只能看状态；轨迹信息把 Agent 从黑盒变可解释、沉淀为企业数字资产；再关联业务结果——Agent 说完成了，用户可能不满意。高阶能力可后补，"最基础的能力一开始就不能欠账"。

被问"Agent 越来越多、账单涨但效果没涨"，龙雾："Agent 往往会撒谎，它会取悦于人"——说"我帮你找到了一个车"，实际没看文档没调 API；所以过程指标比结果指标重要：是否真理解意图、召回是否相关、工具是否合理、有没有循环调用推高 token。评估的尺要校到与人类专家 90% 以上一致才能上生产；修复可把评估结果、代码库、知识库扔给 coding agent 自动改，再实验验证、逐步灰度。郭龙岭补医疗本体案例：人血白蛋白国家规定须抢救/重症/癌症且指标小于 30 克每升才能用，而指标早晚不断变化；他们按疾病和药品建本体，融合医生、护理、跨病种话语形成针对患者的完整关系，用 Agent Loop 时刻监测指标决定此刻能否用药。飞鸿给小红书降本四切面：精细到人、天级甚至周级的 token 熔断；自研上下文 GC（转写作 CFGC）——借鉴 JVM 堆对象管理，把 tool call 和模型返回 message 对象化，异步判定某段资料未来是否被引用，不相关就隐藏但保留恢复指针，几乎无损，线上峰值 token 降 20%；LLM Router 按任务难度路由而非无脑用 SOTA，上线后成本降 69% 而用户反弹不大；自建算力的利用率与缓存命中。

展望环节：郭龙岭加大投入患者生命相关、医生效率、科研辅助和"数字医生"（解基层医疗资源不足）；砍掉重复建设、demo 和不需要医生介入的"无人化"——"前期喊无人化医疗机构很多，现在可能都不喊了"。飞鸿只做三个月判断："确实大家变快了，但快的到底是价值，还是生产垃圾的速度变快了？"团队已无人手写代码，但生成代码质量不好、对架构腐化非常严重，"一旦发生问题可能无法想象"，所以要做 verify 把控架构与编码质量；架构上判断 harness 不再有强壁垒（OpenClaw 之后 Codex 开源、DeepSeek 也出了 harness），应对是把 Agent core 做成热切换、把记忆、skill、tools proxy、LLM router 全部服务化云化，"一周之内完成全新 Agent Core 平替和上线"。龙雾最该补的是观测、评估、优化的工程闭环；最该停的是"没有明确业务目标、没法衡量的无意义 Agent 数量竞赛"。三步方法论：先定义什么是好、哪些红线不能踩；再从线上真实数据找问题，优先高频、影响大、可衡量的任务，先干掉无效和循环调用的浪费；最后实验验证保兜底、逐步灰度——一切围绕企业数据资产转动，"高质量的数据资产将是企业在 AI 时代最重要的"。

## 这场的意义

对行业而言，这场把"企业级 Agent"从口号落成一张问题清单，五个行业给出相互印证的答案：满帮证明大规模商业化 Agent 本质是高并发分布式系统（2000 个 Agent 打崩百万用户级后端），贝壳证明壁垒在本体论组织的领域上下文，易方达证明金融级下限思维（四个 9、沙盒、skill 淘汰治理），施磊证明组织侧要给数字员工发工号、设上岗审批和 HR 联审，机源律动证明 harness 轨迹可反过来训练模型。众人殊途同归到三件事：观测与评估是第一公民（golden set 回归、评估尺与人类专家 90% 一致才上生产）；上下文质量是真护城河（基模和 harness 只决定上限）；架构必须"水涨船高"（基模热切换带来 4 倍成本差，harness 本身不再构成壁垒）。圆桌补上成本一课：token 熔断、上下文 GC、LLM 路由（小红书降 69%）、面向经营单元算账——合起来就是 Agent FinOps 手册的雏形。

对个人而言，这场给出三个可执行点。第一，在企业推 Agent 先别急着调 prompt——多家案例都指向先建观测和评估闭环（轨迹采集、golden set、灰度准入红线），这是"一开始就不能欠账"的底层能力，云上产品已开箱即用。第二，重新审视不可替代性：飞鸿"生产垃圾的速度变快了"与 AI 代码架构腐化的警告、刘硕麟团队算法工程师转安全评测、"CIO 即首席保安"的自嘲，共同指向技术人的价值正从"会写"移向"会验、会治理、会兜底"。第三，把"给 Agent 一个工号"当真：身份独立、权限最小、审计留痕、上岗审批、按 JD 协作、上下文回流知识库——这套从 Patrick 长出来的组织机制，是当前最完整、最可抄袭的数字员工治理模板。
