# 171-存储专场

> 这是云栖大会第一天的存储专场：阿里云高级研发副总裁、存储产品线负责人蒋江伟开场定调，彭亚雄发布全栈自研新一代 CPFS（单文件系统 100PB、吞吐 5 倍），随后全球公共云首发 KV Cache Store（G3.5 层，Kimi 实测 TTFT 降 54%），罗明带来 OSS 全模态数据基座（Table Bucket 等），陶毅与吴君平压轴讲 EBS 的 AI 原生进化（一分钟创 60 万块盘）。小鹏、黑芝麻、千问、Kimi、小米、OPPO 六路客户与团队用真实数字背书。一句话价值：把"为 AI 算力提速、为 Agent 数据筑基"从口号变成产品清单和实测数据。

## 这场为什么开（背景与定位）

存储专场要回答的问题只有一个：当 AI 从文字走向物理世界、从万卡走向百万卡、从推理走向 Agent，数据基础设施该怎么重做。蒋江伟开场给出存储团队的判断——数据大爆发的真正推手不是基模训练（基模所需数据没那么大），而是自动驾驶的音视频，以及正在到来的物理世界感知数据，过去三年产生的数据已超过人类历史数据的总和。需求侧被客户三连问推着走：训练要"规模更大、性能更好、TCO 更优"；推理侧 HBM/DRAM 昂贵，需要廉价存储层替显存扛 KV cache；Agent 要海量、多租、安全隔离的文件系统。于是按"训练—推理—Agent"三条线各发一款重磅产品：全栈自研新一代 CPFS、全球云计算公司首家发布的 KV Cache Store、面向 Agent 的 AgentFS，全部构建在盘古底座上——正如开场视频里阿里云创始人（转写作"王金博士"）对盘古的阐述，这是高速推产品同时做到性能与成本世界领先的底气。全场结构：每个发布配一个技术 DeepDive，再配客户实证。

## 逐环节超详细还原

### 环节一：蒋江伟开场致辞——数据大爆发与三大发布

蒋江伟先拿会场难找开玩笑："来这里的肯定都是，要么是我们有同事带过来，要么就是真爱了。"随后纠正流行误判：数据大爆发的推手不是基模训练，而是自动驾驶的音视频——这些数据一直存在，只是过去不存、价值未被洞察，"今天我们发现这些数据是值得被存下来的"；往后还有更多物理世界感知数据（温度、方位、坐标、轻重），到目的地只是中间过程、到了要完成任务，数据量更大。他引用 CEO 吴永明主论坛的判断佐证，并称过去三年产生的数据已超过人类历史总和。接着预告三大发布：训练场景的全新一代 CPFS（全栈自研，"所有云计算公司里应该是各项指标最好的一款产品"）、推理场景的 KV Cache Store（云计算公司首家发布同类产品，"我相信他们现在这个阶段也应该在研发过程中"）、Agent 场景的 AgentFS，并剧透 KV 缓存实测：两个大客户命中率均提升 20%、GPU 卡接近节省 50%。收尾以盘古点题：基于盘古，才能高速推出产品同时把性能、稳定、可靠、成本做到世界领先。

### 环节二：彭亚雄——全栈自研 CPFS 商业化发布

彭亚雄开场铺陈大盘：吴泳铭讲未来机器智能的思考力可能是今天的一千倍；IDC 口径 AI 基础设施投资增 56%、Google 推理业务翻 7 倍；集群去年讲万卡、今年十万卡，"已经有百万卡的建设规划在路上了"。核心发布新一代 CPFS 四大升级。规模：单文件系统上限 100PB，比三年前提升 17 倍——过去的痛是文件系统到上限只能拆，权限、容量、访问路径全部重来，而"每一个算法工程师都会跟你讲我的数据很重要、是不能删的"。数据流动：preload 之外新增 lazyload 按需加载、边拉边训（"让 GPU 等待分钟到小时级别，简直是犯罪"）。性能：吞吐 20TB→百TB（5 倍）、元数据性能 10 倍；线上基模训练 checkpoint 写入缩短 90%、回退次数降 80%、启动时间提升 2 倍。挂载：一套文件系统同时支持 RDMA 与 VPC 双通道，同域自动走 RDMA、跨域 Auto Switch 自动选 VPC。另预告 KV Cache Store 实测（TTFT 降 30%-50%、命中率升 15%-20%、GPU 节点省 30%-50%）、Vector Bucket 数万客户几十亿行向量，以及 CPFS 数据洞察（atime 热力图、容量异动监控找"成本黑洞"）。收尾"为 AI 而生，与 AI 共成长"，宣布国庆节前在北京、乌兰察布（转写作"乌兰"）、新加坡 region 开放售卖。

### 环节三：小鹏乔秀安（Peter）——智驾训练的 CPFS 实践

小鹏基础平台部乔秀安以使用者兼建设者身份分享。小鹏 2014 年成立，覆盖 AI 汽车、飞行汽车、AI 机器人，共性是持续产生并大量消费物理世界数据——数据是模型持续迭代的燃料。痛点一是文件系统零碎化：小鹏 OSS 数据达数百甚至上千 PB，旧多租 CPFS 单实例约 20PB、100 亿文件数，到上限就拆（A 拆成 B、B 拆成 C），每实例分别管挂载/权限/容量，Kubernetes 每个集群还要把所有 CPFS 再挂一遍；同一训练集从训练角度完整、从存储角度却分散在多实例多目录，底层复杂度透传给业务。新架构的超大单命名空间（百亿级容量、万亿级文件扩展）把训练样本和模型统一到单文件平面。痛点二是全量 warm up 撑不住：新模型（转写作 VR 模型）数据集大、迭代频繁，大量时间耗在数据搬运；文件已打包成大文件（转写作 lark），常只需一个片段却要存全长、浪费容量。他们重设链路：训练先启动、数据按需读取、边训边预热，首个 epoch 较慢，但 lazyload 加 range cache 只缓存真正需要的片段，后续 epoch 复用——训练启动更快、减少无效 IO、磁盘利用率更高、性价比更高。

### 环节四：黑芝麻沈杰——芯片设计场景的 CPFS 实践

沈杰带着踩坑亲历者质感开讲：早年智驾数据处理全自建，成千上万图像要洗刷、打标、缩小，"我们当时有一个文件竟然达到了超过了 16TB，简直是很痛苦"。黑芝麻 2016 年成立、2024 年港股上市，今年上半年芯片出货 600 万片，从研发型走到规模量产；华山、武当系列形成全栈 IP，芯片公司的竞争已是全栈（算法+工具链+软件+模型）。对具身智能他给出时点判断："可能到明年或者后年，大家会看到具身的 GPT 时刻"——芯片做得久、市场与算法可能变，要等市场稍微收敛再进，"一旦市场稍微成熟了，你一颗芯片最后给系统带来的核心能力是无法估量的"。存储侧：算法、模型、供应链多团队数据来回倒，上千人公司里数据孤岛非常痛苦，"整个基础设施的统一架构非常非常重要"。用上新一代 CPFS 后：读吞吐提升约 2.5 倍（大量文件是几十 PB 级）、元数据性能提升、核心训练任务 overall 时间提升 80%。他还点评：并行文件系统全世界就那么几个（转写点名 Lustre、CPFS、BGFS），"这都是几十年前就有了"，以前给超算用，AI 时代对数据的强要求是新课题，阿里自研做好它"真的解决了业界一个痛点问题"。

### 环节五：徐丽——全栈自研 CPFS 技术 DeepDive

徐丽总结四年支撑超大规模训练的三大挑战：混合负载（训练读取+写 checkpoint 之上叠加宽目录遍历、小文件访问且都要高性能）；成本精细化（几周前的 checkpoint 沉降廉价介质、原始数据集留 OSS 按需加载、多团队严控容量）；稳定性（慢 IO 与训练 NCCL 超时关联、全链路 CRC、控制故障爆炸半径）。AI 存储三关键词：文件接口（POSIX 便捷+并行高吞吐）、对象的扩展性（数十 PB+数万卡并行）、快存储延时（万卡写 checkpoint 稳定低延时保 GPU 利用率）。底气：连续三年获存储顶会 FAST 最佳论文奖，盘古底座+EBS+自研分布式索引+高速访问通道与协议栈（转写作 VSC/Sora）。架构为三层：弹性客户端与高速通道/分布式元数据与数据服务/飞天盘古。三扩展：元数据目录树分布式打散+动态分裂到万亿文件；数据按块打散+多集群联邦到 100PB；客户端 DPU 卸载+RDMA 优化支撑 10 万卡。性能栈：IOUring+batchIO 单客户端 4K 随机读写 100 万 RPS；BF3/CIPU 直通零拷贝 40Gbps；元数据目录亲和+定制分布式事务；数据 LogStructured+全用户态+大小 IO 分离。案例：千问模型并发加载启动耗时降 50%、峰值算力利用率 +30%；黑芝麻训练 +80%、读带宽近 2.5 倍，全部实例已稳定运行其上。

### 环节六：袁满——千问超大规模训练稳定性实践

袁满贡献了全场最硬核的工程分享：千问训练大集群多任务并行、单任务最大数万卡，故障恢复建立在基于存储的 checkpoint 技术上。成果：训练 ETR 大于 97%（口径比标准 ETR 更严），且零温备机热备机——"即使是百分之几的温备机，也会带来巨大的机器空转和成本损失，稳定性是一个带成本约束的命题"。恢复耗时全景：故障检测 14%、资源调度 22.3%、训练回退 23%、拉起启动 40%。三个引擎：健康度感知节点恢复（AI Master）——检测前移为周期性主动健康检测，健康度成为可被调度消费的数据库；故障时健康节点原地恢复续训、只换真正故障的 rank，从 10 分钟量级降到分钟级。多级检查点——每 40 步写高频检查点到本地快速存储（内存/本地盘/CPFS 本地临时文件），每 200 步写全局检查点确定性落 CPFS；平均写入 150 秒降到 15 秒以下、故障回退从 150 步降到 15 步，一个数量级。训练启动优化——dist checkpoint 端到端优化在 512 卡省 24 秒；通信建连从 eager 改 lazy 并与计算掩盖；流水并行感知预热对所有 stage 并行初始化，很多场景省 7 分钟。前提是底层存储稳定可预期：CPFS 百 PB 容量让多版本多任务 checkpoint 共用一张盘，权限隔离、容量限制、数据洞察分别治多团队共享、单任务挤占、容量热点。展望 CPFS 演进为智能 AI 数据基础设施：短期记忆、策略自适应、治理智能化、检查点全生命周期管理。

### 环节七：李阳——KV Cache Store 发布

李阳发布专为 AI 推理设计、全球公共云首发的 KV Cache Store。他铺陈四个变化：模型参数增长到万亿级甚至奔向十万亿级；长上下文从数万 token 增到百万级；多轮对话的会话要跨算力节点灵活调度——算力无状态可自由调度，但 KV cache 需要跨节点共享；PD 分离架构普及，Prefill 与 Decode 节点间要传 KV cache；公共前缀在客户业务请求中重复千万次。所有变化指向同一挑战：没有弹性扩展的 KV cache 存储空间，昂贵 GPU 就浪费在重复计算——推理瓶颈正从算力供应转向 KV cache。分层定位：G1/G2/G3（显存/内存/本地盘）快但与算力耦合、单机访问、单位容量成本高到扩容无法承受；G4 远端共享存储离算力远、接口不为 KV cache 设计。KV Cache Store 卡位 G3.5：存算分离交付部署，缓存空间与算力完全解耦、独立购买扩缩容，单实例持续扩到千亿级 KV 数据；首推算力亲和部署（可选灵骏（转写作"凌骏"）GPU 节点的网络编号），单机 40GB/s 吞吐、batch 接口百万级 QPS；原生用户态 KV 接口（put/get/delete+batch）+主流语言 SDK，另为推理引擎提供 connector 快速上线；硬件专为该场景设计并大量瘦身、单位容量成本极致优化，临近裸金属客户还可纳管 G3 本地盘成资源池。实验室验证命中率、token 吞吐、首 token 速度均大幅提升。

### 环节八：张小路——KV Cache Store 技术解析

张小路拆架构：推理引擎→connector/SDK→跑在用户机器上的 cache agent（纳管本地盘、对接 G3.5、对上统一接口）→G3 与 G3.5。G3 即 GPU 本地盘，agent 提供网络通信能力（RDMA/TCP 等），KV cache 存在节点 A、节点 B 可远端读，实现池化。G3.5 是独立于 GPU 的分布式分片弹性存储：容量从 1P 提到 2P 底层扩展分片、业务无感，"写入的 key 可以更晚被淘汰，比如从一个小时保存到两个小时"，从而提升命中率。KV cache 流动路线：HBM→本地内存→本地 SSD（G3）→G3.5→失效；读取时判断 key 位置去对应层取，被淘汰就是 cache miss，代价是一次 GPU 重算。他特意解释共享缓存的必要性：推理引擎为卡的利用率做调度，多轮对话很难保证每轮都在同一 GPU——上轮在节点 A、下轮调度到节点 B，没有共享存储 B 就要重新 prefetch 重算；有了共享缓存，A 算过的数据直接让 B 读。读回速度是生命线：一个 block 可能几十兆上百兆，直接决定用户感知的 TTFT——"如果读取数据的速度还比不上 GPU 重算的速度，那这个 KV cache 帮助就比较小了"。读回链路：推理引擎→cache agent→DPU（CIPU/BF3 硬件卸载，复用 CPFS 技术）→后端专用硬件 eBOF（RDMA 访问，KV cache 语义下沉其中加速）。成本核心是 SSD 寿命：KV cache 持续大写入，TLC/QLC 的 PE cycle 有限——减少盘内对过期数据的搬移、降低写放大，"把所有盘的 PE cycle 全部用于用户的写入"。

### 环节九：Kimi 陈百胜——K2 到 K3 的 KV cache 架构演进

陈百胜证明 KV Cache Store 不是实验室产品。K3 发布后上下文从 256K 涨到 1M。K1/K2 阶段 Kimi 发布并开源 Mooncake（转写作 MoonKite），核心是"以存换算"+PD 分离：以 KV cache 为中心的调度（按位置与传输成本决策）、零拷贝 RDMA 的自研 Transfer Engine（显存内存搬运无 CPU 干预）、集群闲置内存形成缓存池；收益是线上请求吞吐提升 75%。新挑战：多业务线（Kimi Code/Chat/Work、API 平台）、上下文 4 倍多增长、会话缓存要求从小时级涨到天级。K3 在模型架构层面优化：3:1 混合注意力+残差注意力，同长度上下文的 KV cache 需求比 K2 降低 60%。考虑训推混部的潮汐流量（白天推理高峰、晚上训练高峰），磁盘缓存有五需求：优先本地写（避免带宽竞争）、支持远端读写、namespace 隔离（按模型版本隔离）、RDMA 保延时、混合注意力缓存分开存放。于是与阿里云共创 G3 层：位于 Mooncake 管理的内存层以下，把集群闲置磁盘统一成池；prefetch 请求经前缀匹配、按传输成本+机器负载打分选节点再到 G2/G3 取缓存；与推理引擎解耦，训推混部动态扩缩容后缓存仍有效命中。G3 仍有三瓶颈：容量墙（本地 SSD 固定、写满即溢出）、本地盘绑定、缓存可用性（机器不可用缓存跟着不可用）。故进一步定义 G3.5 四原则：与 G3 同接口、存放位置可动态调整、性能接近 G3、云上弹性。实测三数字：TTFT 降 54%、吞吐提高 20%、缓存时间窗口扩大 9 倍。

### 环节十：罗明——OSS 从对象到全模态

罗明用物理 AI 产业数据开场：Waymo 覆盖 10 个美国城市、每周订单 50 万次；特斯拉机器人今年量产、首期目标一年 100 万台；西门子数字孪生识别 90% 工厂设计风险。英伟达 Cosmos 训世界模型用 2000 万小时视频、1 亿片段、8 亿条描述、256/768 维向量——世界模型需要对象+表+向量的全模态数据。重磅是第三种桶 Table Bucket：支持 Iceberg 与 LANCE，并行写入达自建方案（转写作"自建 sbook 表"）10 倍以上；小文件合并、孤儿清理、快照管理这些 dirty work 下沉到存储端，省 EMR 计算与存算带宽；兼容开源 Iceberg/Delta Lake 标准，Spark/Flink 改配置即用。Vector Bucket Fusion Mode：检索延迟降 10 倍、QPS 升 10 倍、召回率最高 99%，热冷向量统一管理。数据处理：Web Studio 原生多媒体处理+千问模型（图片打标、视频描述、人脸检测）等 50 多种原子能力、AI credit 计量；WebFlow 模板编排、存量批量+增量自动触发，数据自动流转衍生新数据。访问：OSS 加速器（NVMe 同 AZ、个位数毫秒）新增缓存热点监控与可变大小数据块（AI 数据用 128K 小块省空间、降回源放大）；资源池 QoS 新支持 QPS 精确流控。成本三件：生命周期 dry run 预演防误配；归档直读自动转回标准；智能分层三层自动调度、零删除费取回费，"成本只会下降"。数据管理：OSS MetaData 首发两张表——变更日志表分钟级、实时清单表小时级，Iceberg 格式一条 SQL 分析百亿千亿对象；MetaQuery 新增一句话事件监测、高光时刻自定义、多语言翻译。工具链：SDK 条件写/删、A2A（Agent 直连 OSS Agent）、OSS Skills 自然语言读写、批量操作支持 copy。

### 环节十一：小米钟宇江——云原生湖仓实践

钟宇江讲表格式与存储底座的演进。传统数仓 Hadoop 存算耦合、运维重；离线 ETL 落 Hive、查询再导一份到 OLAP、实时又引 Kafka——数据来回倒、链路割裂。四诉求：存算分离一份数据多计算复用；多模态能存能算；更好支持 Python（算法侧主导语言）；更强的数据管理（Hive 表格管理弱，规范散在业务逻辑里）。选 Iceberg 三理由：云原生表格式原生支持 OSS（HDFS→OSS 平滑迁移基础）；开放格式对接批/流/OLAP 引擎；快照、Schema evolution、ACID 定义在表格式层。平台一键导入（消息队列/线上 MySQL/Excel/云表格），流批 OLAP 全基于一个表格式不用来回导，pyiceberg+ray connector 供 Python。湖仓自动优化服务：用户只定义维护策略，后台自动做快照过期清理、孤立文件清理、sort/zorder 提升 data skipping、存量数据列级加密。迁移：Iceberg 数据文件与 warehouse 解耦，自动转储任务把 HDFS 数据搬 OSS 全程无感，存储单价约降 80%；OSS 与计算间加缓存层，自动分析血缘找热点表，高峰期前预加载。多模态引入 LANCE：Iceberg 擅长批量扫描（SQL/DataFrame），AI/ML 要高效随机访问（按 row id 取样本）；Lance 三优势：按 id 直接定位+二级索引；无 Row Group 概念可直接加列改列（Parquet 要全量重写）；支持快照/ACID 按版本复现训练。图文交错数据集同表存：Blob 存视频外部引用+range、小图 in line、大图 URI；ray+Lance fragment 分布式处理，merge columns 原表加列零拷贝，shuffle 按 row id 随机读喂训练。OSS 提供 TBPS 级带宽与流控，支撑数十万张表、上百 PB。

### 环节十二：OPPO 付庆武——从传统数据湖到全模态数据湖

付庆武与小米互为印证：手机厂商的互联网服务、影像、AI 中心、IT 服务多模态需求爆发。传统湖仓四问题：数据孤岛、检索缺失、结构化与多模态联合分析缺失、数据治理缺失；落到 Iceberg：数据集不可搜（无向量化和语义检索）、底层 Parquet 点查弱、推搜场景特征与素材召回不能同步做。解法是 Lance 与 LanceDB。架构自上而下：数据平台→血缘权限→统一计算（Spark/Flink/LanceDB）→统一元数据（行业通用 Gravitino，转写作 GranTino）→Iceberg+Lance→OSS（全量数据在阿里云上）。落地真实问题：Iceberg 作为在线服务要解决海量元数据膨胀、业务延迟、高频写入、多表并发维护——自研管理平台针对性解决；Lance 是嵌入式 DB，先集群化 server 化，再解决索引反复读、热数据读的问题，引入自研分布式缓存"科问"（已开源贡献给 CNCF）：CacheMode 做云上对象存储高性能访问（类似阿里云加速器），FSMode 提供完整 POSIX 语义异步落 OSS；除模型训练场景外全部在线落地。底座：前年把大数据所有底座迁到 OSS——线性弹性无限容量、性能好、稳定性好，自建至少需两人运维、迁移后转向其他方向；现在每天运行百万级 Spark 任务、数据量数百 PB，两三年非常稳定。成果：Iceberg on OSS 已线上落地；Lance 集群化+读缓存优化后对比官方 benchmark 快 2-3 倍；全公司图片数据入湖，影像拼图、AI 图片搜索、个人多模态问答助理（作多模态知识库）已上线。

### 环节十三：陶毅——EBS 从云原生到 AI 原生

陶毅从成绩单讲起：去年 EBS 业内第一家商业化弹性临时盘，今年国内厂商全部跟随；一年 260% 规模增长、近百家头部客户、数百 PB、20 多个可用区，覆盖自动驾驶、具身智能、量化交易。新痛点：头部新能源智驾客户的视频预处理（OSS 拉到本地做解帧、鸟看图、去畸变）是线性递归流水线，大批量作业下"99% 的作业都已经完成了，总是被几个作业来拖住"，最终影响 OTA 推送。背后是评价体系之变：过去讲 IOPS/吞吐/时延（快存储三大公认指标），AI 更看重集群吞吐与任务并发度。于是推出弹性临时盘第四代 Pool：一块盘的参数指标变成池化服务一批任务，池中盘任意自定义容量、任意盘都能拿原先的 4GB 读/2GB 写；对比友商本地盘与算力绑死（16 核绑死 1.92TB、性能空闲不能用），"让客户的每一笔钱都获得最大的效率提升"。推理侧此前用快照技术（AutoPL 性能突发、快照预热把模型提前送到计算节点就近位置）解决模型加载：头部视频模型厂商声数科技频繁换模型，从 10 分钟量级变成 15 秒，接近两个数量级。今年推理从实验品变成大规模部署，暴露三问题：环境一致性、扩容冷启动、千卡集群共用同版本的成本浪费。对应发布：只读共享盘（一盘挂 16 节点省 93% 成本、AutoPL 4GB→6GB 提升 50%、只读防篡改）；多快照创盘（多快照共一块盘按分区访问不同模型、改软链接即换版本）；云盘克隆升级（跨可用区克隆+一对多）。稳定性：快照锁定（防病毒与误操作）、快照策略升级（实例维度、多策略）。另推出四个官方 Skill 回应"监控指标看不懂"。最后提到 Regional 容灾盘一年增长 43 倍、11 个可用区、超 10 家世界 500 强，并预告次日将发布面向 Agent 场景的新能力（转写作 EICD）。

### 环节十四：吴君平——AI 时代 EBS 背后的技术

吴君平讲两件事。第一件提升吞吐密度：关键指标是放大系数，以前二点几；新架构两块 DPU 卡互备、双端口盘、任意卡接 IO，网络放大系数做到一——全部物理带宽给用户，密度提升约一倍。再压极限：AI 数据多已压过、常规压缩效果差，但差异化压缩算法仍能压、只是吃算力——于是做"柔性压缩"：计算端先用 QAT（DPU 卡）压缩，算力不足按 IO 迁到后端（后端也有 QAT），极端时临时取消（概率极低），用户无感；线上看压过的数据还能再压 25%、没压的能压一半，等效吞吐再翻倍。吞吐高了延迟怎么保？他用高速公路作比，答案是端到端物理隔离：改虚拟机驱动与内核（已进新内核并写专利），严格区分延迟敏感型 IO（DirectIO 同步阻塞）与吞吐型 IO（page cache 下刷、pdflush 时机用户不感知——系统大部分 IO 走 page cache）；NVMe 下发做优先级区分；BlockServer 建双线程池（用户态 pull 模式处理延迟型、pipeline 模式吞吐友好）；网络层在 RDMA 上规划"大象流与老鼠流"两条完全隔离路径（网卡到交换机）；盘层再分两池。效果：90% 极限吞吐水位下 4K 写长尾延迟仍 3 毫秒以内，"很少有友商能达到"。第二件模型加载分发：只读共享后端可做到一百块云盘实际挂一块实体盘，三级突破——内存加速、内存跨线程无锁读（单核 2.5G 上限突破到单机）、64K 分片×64 条带宽度（一块盘用上整个集群存储）；快照预热：提前几分钟把模型从 OSS 拉成本地盘，每集群一份、盘创出即有性能、后端 lazy load 填平；盘到盘分发：验证好的云盘直接作母盘一对多克隆，不经快照不经 OSS，原盘可继续写（崩溃一致性副本）；组合拳还有快照批量创盘、副本自动扩展、读缓存加速、OSS 带宽自动扩容、前后端流量隔离、多快照联合创盘——单个 region 一分钟创建 60 万块盘。

## 这场的意义

对行业而言，这场会标志着存储层在 AI 技术栈里从"配套"升格为"杠杆"。最典型的信号是 KV Cache Store：当推理瓶颈从算力供应转向 KV cache 管理，存储公司第一次直接下场做推理加速引擎——用 G3.5 层的廉价 SSD 换显存，Kimi 实测 TTFT 降 54%、吞吐升 20%、缓存窗口扩 9 倍，改变的是 token 成本曲线本身。同样值得注意的是"dirty work 下沉"成为共识：OSS Table Bucket 把 compaction、快照管理、孤儿文件清理从计算端搬到存储端，小米、OPPO 两家大体量数据团队用几乎相同的路线（Iceberg 管结构化+Lance 管多模态+OSS 做底座）完成湖仓收敛，说明这套组合已通过规模化验证。而千问的"检测 14%/调度 22.3%/回退 23%/启动 40%"恢复耗时全景图，给全行业提供了一张万卡稳定性优化的作战地图——97% ETR 不靠热备机堆出来，靠分层工程治理。

对个人从业者而言，至少有三条可带走的启发。其一是缓存命中率正在成为推理与 Agent 系统的一等指标：Kimi 的演进（以存换算、多级缓存流动、namespace 隔离）展示了完整思考框架，做长会话 Agent 的人应把缓存策略纳入调度决策而不是事后补丁。其二是稳定性是系统工程而非单点技术：健康度感知恢复、多级检查点、流水并行感知预热分别对应调度、存储、框架三层，任何一层缺失都不成立——这套"分层拆解再协同"的方法论可迁移到任何大规模分布式系统。其三是看 AI 基础设施的眼光要更新：过去问 IOPS/吞吐/时延，现在要问集群吞吐、任务并发度、单 token 成本、缓存窗口时长；EBS 从"一块盘的参数"到"一个池的服务"再到用 Skill 帮用户分析，对做基础设施产品的人都有参照价值。正如袁满那句收尾：稳定性不是运气，是一层层工程治理、规划和协同优化产生的结果——这大概也是整场存储专场最想传递的价值观。
