# 172-国际AgenticAI峰会

> 国际 Agentic AI 峰会是云栖大会面向全球视角的 Agent 分论坛：阿里千问 3.8 系列领衔，钉钉 Qwen Work、BMW、Unity 中国、SAP、日本奥特曼 IP 方与硅谷开源推理三厂（Fireworks AI / vLLM 阵营 / Together AI）同台。整场一条主线——"前沿模型如何变成企业生产力"：模型层讲连续性（continuity）与稀疏效率，应用层讲数字员工与上下文，行业层讲灵活架构与 UX，基础设施层讲开源、成本与评测。看完等于同时听懂模型、应用、行业、开源四方对 Agentic AI 的回答。

## 这场为什么开（背景与定位）

这是第二天下午的国际场，主题词是 Agentic AI 的"企业级落地 + 全球化"。阿里云把自家模型（千问 3.8 Max/Flash/Omni/Audio/图像编辑）、自家办公产品（钉钉与 Qwen Work）与国际头部客户/伙伴放在同一个舞台：汽车（BMW）、游戏引擎（Unity 中国）、企业软件（SAP）、日本 IP 内容（奥特曼持有方），最后压轴一场硅谷开源圆桌，把讨论从"阿里的模型多强"拉高到"开源模型生态与推理经济学的全球走向"。前一场致辞由李飞飞（转写 Feifei）担纲，本场多位讲者（钉钉、BMW）明确引用其开场观点——"千问模型非常高效""千问不只是单个模型而是一个模型家族，阿里云还愿意托管 DeepSeek 等第三方模型"，可见全场的叙事骨架就是这句：**模型家族 + 开放托管 = 企业可以放心把 Agent 建在上面**。

注意：本场转写缺失开场约 70 分钟（录制启动偏晚），首段从第一位讲者演讲中途切入；日语演讲一段 ASR 失真严重，细节以现场为准。

## 逐环节超详细还原

### 环节一：YuSen —— Qwen Work：把 Agent 变成"数字员工"

转写切入时，他正在回应李飞飞致辞中"千问模型非常高效"的说法，并给出产品吃到的两层模型红利。第一层是 **Qwen 3.8 OmniFlash**：一个多模态理解模型，专门把企业的非结构化数据——培训材料、视频、图片、大量 PDF——"理解成结构化层级"。第二层是一个与模型团队共建的**专用 context（企业上下文）模型**：企业数据按天甚至按小时生成，模型必须能频繁更新，所以"尺寸刚好"是核心诉求——太大成本扛不住，太小不够聪明。这两个模型支撑起他对企业场景的基本判断：靠千问，能做出很好的企业上下文产品。

接着他抛出本场第一个概念：**AI workforce（AI 劳动力）**。他特意强调"AI workforce 不是一个产品本身"，而是由产品的三大能力拼出来的。第一是 **钉钉 Connect/钉钉本体**：钉钉是最常用的企业即时通讯产品，还覆盖会议、文档等大量功能；现在它开始支持"数字员工"。他给了一个非常企业视角的洞察：如果你只把 Agent 当一个 bot，权限和各种设定都没配对，它在企业里根本没法干活——必须把 Agent 放进 IM 产品里，配好正确的权限、给它邮箱地址、定义它能做什么，它才能像那些 SaaS 软件一样"进入你的公司"，像员工一样做事。第二是**企业上下文**：让 Agent 理解你的业务，它才能像人一样完成工作。

随后转入面向海外市场的录音产品 **DingTalk A1**：团队前一天刚发布了 A2，但 A2 不进国际市场，A1 已经在海外销售。A1 的核心思想很洞察人心——对每一段销售沟通，**只留文字、不留音频**：因为被人录音会不舒服，而"录完音、转成文字、立刻删掉音频"，员工感受就好得多。这样企业能拿到所有销售的真实话术文本，交给 Qwen Work 或任何 AI agent 分析：总结哪些是好的 pitch、哪些是坏想法，把 top sales 的经验提炼出来，辅导低绩效员工变好。这是"用隐私友好换数据资产"的典型设计。

接下来是 **Qwen Work APP 的发布**：企业可以在保留现有系统原有页面和数据的前提下叠加 Agent 能力，用户在 Qwen Work 里搜索、安装、即开即用。现场放了一段金融研究宣传片：不需要复杂 prompt，拖选一根 K 线，AI 就根据你的动作分析趋势与阻力位；同行业选多家公司，AI 并排对比业务、盈利与估值；从营收、毛利率到净利润增速，**18 项关键公司指标**任选加到股票卡片上；你做的每一次选择和调整 AI 都记得；研究报告几秒生成——查行情、找数据、跑分析、读研报，不再搬数据、不再切换应用，整个金融分析工作流在一个 Office 应用里跑完。他补充：这个特性让公司里**每个员工都可以有自己不同的 Qwen Work 界面**，把 AI 能力放到各自首屏最常用的位置。

最后讲 **Trustworthy（可信）**，他说没时间展开，只讲两件事：第一，限制 Agent 的每一个动作——不想让它碰的数据它碰不到，用沙箱把主要动作都关进去；而且有**文件删除恢复**能力，Agent 误删了不该删的文件可以找回来。第二是**数据血缘（data lineage）**：两端卡敏感数据——发现输入侧有敏感数据，AI 不许访问；发现输出侧结果含敏感数据，就不许发到公司外面。完整的安全中心在后端，可按需配置。收尾一句："Qwen Work 不是又一个 AI agent，它是企业级 AI Agent 平台——它懂你的业务，能像你的员工一样协作，而且可信。"

### 环节二：Yuanhe —— 千问 3.8 全家桶：从对话到生产力

阿里云模型服务线总监、Model Studio（百炼，他自称 "the token engine"）产品经理 Yuanhe 接棒。开场自嘲："如果这台引擎断电，我不知道自己还能不能干活。"他接续 YuSen 场次里"context 改变 Agent 工作方式"的话头，说要往下再挖一层——看体验底下的模型能力。客户的实际问题不是参数和跑分，而是"**怎么把这份智能用进实践**"。

他给出一个同事类比：给同事派活，他要先理解任务和任务周围的上下文（可能躺在文档、视频、图片或其他格式里），然后做计划、执行、失败就迭代，最后以各种格式产出结果给你审。映射到模型矩阵：**千问 Omni 与视觉模型负责理解上下文，Qwen Max/Qwen Flash 负责推理、规划、执行，创作类模型负责生成各种格式的产出**，全程 Qwen Audio Realtime 让人能自然地打断、澄清、改变方向。一句话概括他的方法论："**The key is continuity. Our goal stays connected across context, actions and results.**"（关键是连续性：目标跨上下文、行动与结果保持连接。）

然后是全场最硬的一个数字故事。测试很简单："模型能不能钉在一个任务上？"他们给 **Qwen 3.8 Max** 一个软件工程目标，让 Agent **自主跑 16 天、无人介入**——期间经历测试失败、意外结果、甚至工具本身的变更，模型仍要记得自己当初为什么出发。这一跑的产出：**开了 151 个 issue、提了 127 个 PR、做了 265 个 commit**。他强调更深的故事是连续性：Agent 守住了最初目标并持续返修。同样的节奏出现在研究、办公、芯片设计、量化研究等各行各业——工具会变，韵律不变：plan, try, inspect, reiterate。

支撑这种"耐力"的是什么？Qwen 3.8 Max 有 **2.4 万亿训练参数**，当前快照在 Arena 文本榜排名第 2、Coding Arena 全栈榜第 1（他提醒排名动态变化，但"我们在顶部"）。长 Agent 工作流需要的不只是跑分：Qwen 3.8 Max 能跑在 Qwen Code、Claude Code、OpenCode、Codex 等环境里，terminal bench 上任务可跨工具链延续——用户体验因此改变：不用每隔几步就重新交代任务，Agent 能记住目标并从错误中恢复。

接下来是成本侧：Agent 要调用模型成百上千次，每一步都贵就没法规模化。**Qwen 3.8 Flash** 应运而生：**总参数 125B，每个 token 只激活 6B**。他把全参模型比作大图书馆，Flash 只在需要时把相关的书搬给你。注意力设计遵循同样规则：**gated delta net 层维护一份运行记忆，稀疏注意力层可以回溯早期的具体细节**。叠加其他效率改进，Qwen 3.8 Flash 的训练算力压到了 **Qwen 3.7 Plus 的九分之一**——每一步省一点看似不多，但在长 Agent 工作流里会复利。

视觉与多模态部分现场放了一段餐厅视频 demo：AI 助手看到餐桌、听到一家人的对话、记住他们的需求——安排三人位、上茶和开胃小食、推荐清淡菜、给孩子配儿童餐；当一块鸡肉看起来没熟时，它主动叫服务员来检查。他的解读：**状态在视觉、语音、记忆与工具之间保持连接**。他们前一天刚发布 **Qwen Audio 3.1 Realtime**：为实时语音协作设计，支持全上下文对话；体验很"个人"——可调语气、语速、情绪，甚至声音克隆；最重要的是**对话能直接变成动作**——通过 function call、MCP 和其他 API，模型自己决定什么时候开口回答、什么时候在后台默默搜索，语音成了"工作推进时你保持掌控的自然方式"。

生成侧的关键词是**可编辑性（editability）**："第一张生成的图很少就是最终稿。"图像编辑模型（转写 Queen Image Edit 3.1）支持**最多 10 张参考图**、精确局部编辑，横跨时尚、学术图表、商业图。理念是让模型加入你的评审循环，而不是逼用户一遍遍重掷骰子。视频则把连续性变得可见：角色、物体、创意要跨场景、跨风格存活；他因时间限制跳过了一版视频模型 demo，但要点不变——连续性贯穿真人实拍、产品可视化和动画，"创意始终认得出来"。最后展示了 **Happy Oyster 世界模型**：不同于生成一张固定图像，它探索的是一个**可响应的世界**——用户用键盘操控画面里的角色，世界实时回应你。

收尾回到"周一早晨给同事派活"的类比：我们派的是任务，不是写得完美的 prompt；每个结果成为下一次观察，每次纠正成为新的上下文。"智能只有在**缩短意图与有用结果之间距离**时才成立。Frontier models create value when it can stay on the goal while keep you in control."（前沿模型的价值在于：既能钉住目标，又让你始终掌控。）

### 环节三：大島悠介（Oshima Yusuke）—— 奥特曼 IP 与 AI（日语演讲）

第三位讲者是大島悠介（转写 We Oshima Yusuke），Subura Fields Holdings（即円谷 Fields Holdings，奥特曼 IP 持有方）执行高管（managing corporate officer）。他全程用日语演讲，火山 ASR 对日语几乎失效，大段内容被转写成无意义的英文拟音，**本环节细节可信度有限**，以下只复述转写中可辨认的线索。

可辨认的开场是日语寒暄与致谢（"doumo arigatou gozaimasu"）。通篇反复出现的实词集中在三类：一是**奥特曼 IP 本体**——Ultraman、kaiju（怪兽）、"英雄与怪兽的宿敌"关系的表述，以及 Ultraman Taro 等角色名与一系列英雄/怪兽名字的罗列，可判断他系统介绍了圆谷的奥特曼系列内容资产；二是**内容发行矩阵**——转写里出现动画、游戏、漫画，以及 Hulu 剧集、电视剧集、韩剧等发行渠道词汇，还有"英雄特摄""新世代"一类表述，可推断他在讲奥特曼 IP 覆盖特摄、动画、游戏、海外流媒体的多元内容布局；三是**制作技术与 AI 的结合点**——转写中出现 motion capture（转写为 emotion capture）、动画制作、以及"游戏以全新环境/引擎重制"一类的表述，可推断他讲了 AI/新技术在 IP 内容生产中的应用。转写中还零星出现"Margot Robbie""co-star"等好莱坞相关字样与某海外剧集的讨论，指向与海外影视的合作话题，但无法确认具体内容。

演讲中段有约两分钟的转写完全循环失真（反复输出 "in the Skidoo in the Miami in the Sony"式碎片），按经验判断是现场播放了一段配乐视频（大概率是 IP 内容混剪/新企划 PV），ASR 在音乐下彻底失效。综合判断，这一环节的定位是：**用世界级 IP 方的身份证明 AI 内容生产技术（视觉、语音、视频生成）在成熟娱乐工业里的真实需求**——与前后的企业客户案例互为呼应。细节待现场视频佐证，此处不妄加还原。

### 环节四：Pascal Thyssen —— BMW：AI 定义汽车，不如说 AI 定义体验

BMW 研发中国用户交互与业务线 VP Pascal Thyssen 博士开场感谢阿里邀请，落地杭州——"全球最重要的云计算与人工智能舞台之一"。他先纠正命题：今天不是讲 AI defined vehicle（AI 定义汽车），而是 **AI defined experience（AI 定义体验）**——"今天你会听我反复说 experience 这个词"。对 BMW，下一步不是更强的语音助手、也不是又一个数字化功能：**AI 正在成为车辆的核心技术，但技术从来不是目的地，目的地是直觉而愉悦的客户体验，而且是"一眼即 BMW"的体验。**

载体是新世代（Neue Klasse，转写 Neue Klasse/moi classer）。它汇聚电动化、数字化、智能化，同时守住品牌核心承诺——纯粹驾驶乐趣（sheer driving pleasure）。在中国，这个愿景落在三款车上：**BMW iX3** 是第一个证明点，一款专为中国打造的电动智能 SAV；**BMW i3** 把驾驶者之车带入智能时代——运动、精准、有情感；**BMW 7 系**把新世代带进豪华细分市场。他强调中国是 BMW 重要的创新引擎，本地研发团队与中国技术伙伴紧密协作——今天的体验就是这么造出来的。

体验的中心是 **BMW 全景 iDrive**。设计原则一句话："**Eyes on the road, hands on the wheel**（眼盯路面，手握方向）"。底层方法叫**视觉锥（visual cone）**：驾驶关键信息放在驾驶员自然视线的正前方，附加信息按相关性和交互需要排布。听起来简单，但要求整个座舱作为一个系统来设计——屏幕位置、信息层级、方向盘控制与语音助手必须严丝合缝。他称之为"数字豪华"：不是为技术而技术，而是自然融入驾驶的技术。全景 iDrive 带来四大交互界面：①**3D HUD**——独家的车道级导航直接投在驾驶员视线里，还叠加驾驶辅助信息，复杂路况一眼看懂；②**全景视域显示**——左边是全部驾驶要务，右边是你的个人空间，自定义你想在车里看到什么；③**多功能方向盘**——Shy Tech（转写 Chytec）技术，按键只在真正相关时才亮起可用；④**中央显示**——其余控制与信息，触控完成。关键创新不在单个组件，而在协同：信息永远出现在对的地点、对的颗粒度、对的时机。

然后是 **BMW 智能个人助理**。他与"阿里巴巴（Bama）和阿里"一起为中国专属体验打造了**专属 AI 底座**：可灵活调用领先模型——包括千问与 DeepSeek 能力——而 BMW 负责整体集成、客户体验与车辆语境。他特意呼应李飞飞开场：千问不是一个模型而是一个**模型家族**，阿里还开放托管 DeepSeek 等模型——在本案例中 DeepSeek 驱动一个**通用知识 agent**；系统不再对每个请求一视同仁，而是聚合多个专职 agent，比如"car genius 旅行伴侣"（购车/出行精灵，转写 car genius travel companion）和刚才说的 DeepSeek 通用知识 agent。生成式 AI 也用于个性化：**BMW AI particles（转写音）**让客户用自然语音请求为界面生成动画内容。真正的创新不是单个 agent，而是把它们**呈现为一致且透明的体验**：无论何时交互，助理的形象始终可见（屏幕中央），给即时反馈、全程透明；中央显示承接更复杂的对话，展示上下文细节与选项；结果是语音、视觉引导、触控自然互补的多模态交互。

最新的玩法是 **AI 生成个人小组件（personal widgets）**：给客户全新的座舱个性化方式——给孩子生日做一个生日蛋糕 widget，或者把你家猫狗的 widget 摆在你眼前。座舱成了"对你最重要的人与记忆的映照"。BMW 的独特之处是每个 widget 都以 BMW 独有设计语言生成，再叠加细腻的微动画——"这是 AI 超越功能性、贡献更个人、更情感、更难忘体验的完美例子"。

拉到 UI 背后，技术演进清晰：规则 → 基础模型 → Agentic AI → 推理 → 世界模型。但真正的挑战不是下一个模型，而是**把这些技术变成无缝的车内体验**：必须整合所有车辆域、平衡车载与云下（offboard）、接入车外的数字客户生态。所以**灵活性**是他未来 AI 架构的中心设计原则：①伙伴灵活——从伙伴拿最好的能力；②模型灵活——换新模型不必改产品设计；③Agent 灵活——给个人助理加新 agent（比如前面看到的 Qwen Work）不用重做整个产品；④部署灵活——车载/云下混合架构，隐私原因有些必须车端跑，但客户感知必须是同一个一致体验。

他正面回答了一个行业之问："AI 语音交互最终会取代图形界面吗？我们的答案是**不，不会**。"语音会变得强大、自然、主动，但图形界面会一直在——因为 GUI 创造信任、透明、即时定位，同时提升安全与情感联结；而生成式 AI 反过来会**动态生成界面元素**来抬升 GUI/UX。所以未来不是"语音 vs GUI"，而是**多模态交互**，问题是怎么聪明地融合、各用其强。三条收束：①新世代标志 BMW 新纪元——全球工程 + 中国创新 + 战略伙伴（阿里等）；②灵活 AI 架构是持续创新的地基——随时纳入新模型、新伙伴、新 agent、新生态；③"**AI is the enabler. But the unique UX is the differentiator.**"——AI 是使能器，独特体验才是差异化，最终必须守住"纯粹驾驶乐趣"。

### 环节五：张俊波 —— Unity 中国：Codey，为游戏开发而生的 Agent

Unity 中国 CEO 张俊波（转写 Jumbo Zhang）的开场极简："今天我只讲一件事：**用 AI 快速做出高质量游戏**。"AI 在重塑所有行业，游戏业站在最前线：把一个想法变成可玩的游戏需要几十种技能、复杂管线、长周期、高成本，而 AI 正在重写这条管线——概念设计、美术资产、动画、代码、台词，AI 已经能参与越来越多原本完全依赖人手的环节。"游戏制作的焦点正在从 **how to make the game** 转向 **what to build**。"

但他马上泼冷水：游戏开发仍是复杂的工程挑战——代码、资产、场景、性能深度耦合，**用通用 Agent 解这些瓶颈往往效率不达标**。所以 Unity 中国基于多年游戏开发经验，做了一个专用 Agent：面向 Unity 引擎和中国自研的团结引擎（Tuanjie），名字叫 **Codey**（转写不稳定，Cloudy/Codeley/Coldly 均有出现，下文统一写 Codey）。Codey 不是通用代码 Agent，也不是聊天机器人——它是**只为游戏开发而生的 AI Agent**：接入引擎、模型、资产商店与插件，横跨工程、美术、QA、运营与发行，覆盖从想法到上线的整条工作流。

他先感谢阿里：Codey 的能力构建在阿里的产品生态上。千问 VL 多模态模型提供视觉理解底座，Unity 在其上用游戏开发数据训练了**专用小模型——基于千问 27B 底座、叠加游戏开发 LoRA**，在窄任务上打败通用模型；千问 27B 是该尺寸最强的开源基座、与旗舰模型同源；开源权重让他们能自由微调，且强中文理解贴合中国开发者工作流；模型推理跑在阿里云上——弹性 GPU 扩缩、与服务栈协同优化、国内节点低延迟。"这就是为什么阿里是我们选择的生态伙伴。"

产品形态上，Codey 是**五端同核**：桌面端、引擎内插件、移动端、团结 Web、IDE 插件——五个入口由同一个 Agent 驱动；并接通了从代码生成到 3D 资产生成再到视频生成的完整基础模型链。桌面端，Codey 取代了 Unity Hub 成为项目管家：管账号、管项目、管编辑器每个版本，同时是桌面 Agent 能力的完整载体；浏览器里也能用 Codey 全部能力，还支持 Unity 编辑器云串流；手机上也能开工——随时随地做游戏。还刚发布了 **Codey Canvas**（转写 cozy canvas）：依托社区海量的资产模板与低代码基础工作流，搭出**完全可控的 AIGC 管线**——生成的每一步都可预测、可复用。他的金句："**Turning AI art generation from a gacha pool into a mature production process.**"（把 AI 美术从抽卡池变成成熟生产流程。）

然后是一连串真实场景 demo：①**一键跨端**——单击把 Android 构建转成鸿蒙（HarmonyOS）构建，新平台几乎零额外成本触达；②**天气系统**——描述你想要什么，Codey 在引擎内配好复杂的天空盒、云层与动态光照，高度自动化且完全个性化；③**游戏云服务**——Unity Online Services（排行榜、匹配、云存档、分析）很好用但配置是门槛，Codey 把这套配置自动化："你说，它就做好"；④**单机转多人**——这对开发者几乎等于重写（网络同步、数据管理、匹配），Codey 能把单机游戏快速变成多人游戏，这套在线服务同样跑在阿里云；⑤**性能优化**——自动生成完整性能报告、定位瓶颈、优化构建，看内存 dump、崩溃 dump、分析帧缓冲；⑥**自动测试**——从现有项目自动生成游戏内测试工具，AI 替你写脚本、跑起来、分析数据；⑦**车载 HMI**——开发者输入"创建地形、房屋、UI、车门控制与相机控制，别给我写代码，直接做"，Codey 一次无缝完成地形配置、贴图更新、车辆模型与动画；⑧**室内展厅**——选中车型加一句指令，车辆配置、室内场景、相机控制、灯光调节、材质替换一条命令全部完成。他强调：用 AI 做游戏不意味着只能做简单网页游戏——现场展示了高画质水准，并透露内部也在密集用 Codey 做大项目：团结引擎高性能实时渲染 demo **Tower Valley**。收尾："让每个开发者的好想法被高效构建、被全世界看到。AI 时代，团结与全球百万开发者一起重塑游戏开发格局——**develop with AI, create without limit**（转写 develop with less）。"

### 环节六：Fan Kong —— SAP：自主企业与 Business AI 平台

SAP Data & Analytics 总裁兼首席产品官 Fan Kong 上场先调侃大家坐了快两小时能量还剩多少。他定位 SAP 的双重身份：**既是阿里云的客户，也是阿里云的伙伴**，在华经营超过三十年。SAP 的起点是套装应用的先驱，如今全球几十万客户把整个业务跑在 SAP 应用套件上。

他先给一个冷静的全场视角：今天所有讲者描述的其实是同一个问题——过去一到三年大语言模型价值与创新加速毋庸置疑（他也点名千问 3.8 与各家前沿实验室在视频、语音、文本上的进展），但 LLM 本质是**预训练模型**：一万亿、五万亿、十万亿参数也好，本质是海量预训练数据；训练一次要 2 万到 50 万张 GPU，成本最高可到一两千万甚至两千五百万（美元量级），在特定硬件上跑一个月左右。问题在水面之下：**海量企业数据不在预训练模型里**——一张采购订单、一个销售事件、一个采购事件，这些根本性的业务语境 LLM 完全没有。SAP 的叙事就是：**把你的业务上下文与 LLM 的一切创新连接起来**——"本质上我们是在把两堵墙接起来"。

连接的具体形态是 **Autonomous Enterprise（自主企业）**，SAP 在自家活动中正式提出：让业务事件可以在 **human in the loop 或 human on the loop 之外**被驱动，并且横跨企业每一个域——财务、采购、供应链一直到客户体验。全球几十万客户的运营后端跑在 SAP 上，意味着**几十年的运营数据与语境**；把它们喂给 AI 和 Agent 自主运行，不是简单自动化，而是"由几十年业务语境驱动的内在价值"。

承载它的是 **Business AI 平台**，一套端到端能力：构建 Agent（从零构建，SAP 与非 SAP 均可，代码型或内容型皆可，底下有集成套件打通全域数据）、运行 Agent、扩展 Agent；数据语境化；用 SAP 与非 SAP 模型推理；一路到治理。治理为何关键？因为 LLM 本身理解不了你的身份要求、用户验收要求，更理解不了企业数据该有什么治理与安全。

**语境化**是成功 Agent 最重要的特征，其中第一个要素是 **SAP 知识图谱**。他做了一个精彩区分：满大街厂商都在讲知识图谱，但**只装元数据的空图谱，与被全部业务语境完全"水合"（hydrated）的图谱是两回事**。SAP 用新产品 **Business Data Cloud** 实现后者：从所有主 SAP/非 SAP 系统摄取数据，沉淀为**数据产品（data products）**——经过策划、语义富化的数据集，比如一张销售订单、一个成本中心；所有数据产品都做了**主数据对齐**——一个成本中心可能同时活在 Salesforce、Snowflake 和 SAP 环境里，在语境层与知识图谱里你能确认其质量、治理与安全。推理层因此受益：无论带什么模型来，都能享受同一层语境化——"我们不但给你数据，还给你数据附带的语境，并保留模型的自由选择权。"

**治理**部分他讲得很重：大多数 AI 项目翻车，是因为一开始没把治理做对，客户和监管会非常苛刻。SAP 的答案是 **AI Agent Hub**：所有 Agent 可审计、集中管理，并有清晰护栏规定 Agent 能做什么、不能做什么。他讲了一个刚经历的面试式段子：如果把 Agent 当员工写年终评语，大概会写——"Agent X 很棒，但可惜有时会编造不该编的东西，还会闯进不该进的领域，不过始终很努力。"这话当人类员工的年度评估没问题，因为人可以培训；但**一个行为不端的 Agent 带来的声誉风险极其巨大**——所以治理必须是 AI 落地的核心地基，不是补丁。

工具侧是 **Joule Studio 与 Joule Runtime**（转写 Jule）：单一 IDE，前端随便带——Lovable 也好、Claude 也好——但 Agent 运行时遵循同样原则：必须在语境化与推理层之内运行，连得到所有数据、又不允许绕过护栏直接摸数据。治理上还引入**双记忆**概念：**agent memory + company memory（公司记忆）**。他举例：每到季末，采购团队都知道给最好的供应商更好的折扣能换来更大价值——这种和供应商多年甚至几十年互动攒下的知识，必须通过公司记忆装备给每一个 Agent 和每一个人，让公司记忆持久存续，让组织凭直觉世代积累的行为方式得以延续。两者结合放进 Agent 治理，你就不必再忙于兜底各种低级错误，而是能稳定输出高价值与高韧性。

最后是与阿里云的伙伴关系：SAP 看遍全球超大规模云伙伴（北美那几家），而阿里云正迅速成为**最重要的伙伴之一**。过去 18~24 个月合作持续加码：从 SAP Cloud ERP 起步，如今加入平台服务与 IBP（集成业务计划）方案；接下来 **Cloud ERP 私有云版**将直接在阿里云上提供托管环境（Q3 落地），**SAP Business Data Cloud** 也将于次年初登陆阿里云。结语致谢中国客户几十年的信任，未来与自主企业战略一起继续深耕。

### 环节七：开源圆桌 —— Powering the Open Source Era：从原始模型到企业应用

压轴圆桌由阿里云国际业务 VP 兼北美总经理 **Alex Chen** 主持，嘉宾四位：**Yun**（Fireworks AI 工程副总裁）、**Kaitao**（vLLM 核心维护者、InfraAI 联合创始人兼首席科学家）、**Ted**（Together AI 工程 VP，主管推理平台）、**Huiping Ding**（阿里云模型业务线资深工程师，千问 AI 平台团队，负责 AI Infra，在阿里约 9 年）。主持人定位：这三位硅谷客人加上自家人，就是一份"硅谷 AI 心态快照"；议题是 AI 的现状——把 token 变成智能、把智能变成行动——外加前瞻判断。

**第一问：过去 12 个月最意外的发展是什么？** Huiping：年初开源 Agent（转写 open claude）兴起——AI 从"能回答问题"变成"能为你规划、执行工作流、完成任务的系统"，今年是 agentic 元年的起点。Ted 补充：那波浪潮意味着两件事——第一次有 Agent 能通用地干日常任务、打开了所有人的想象力；而且它能接不同模型、尤其开源模型，他们平台上开源模型用量激增，**关键是 Agent 用量的增长是"粘"住的、持续增长**，不像以往一些现象昙花一现，它撑起了今年的整体用量增长。Kaitao 的答案赢得全场会心一笑："**Qwen 3.8 Max 的发布**"（主持人：这答案不错，我们可没串通）。他说做开源模型支持的软件栈，最想看到强开源模型；此前业界怀疑开源能否追上最强闭源，而 Qwen 3.8 Max 给了他们信心：**开源模型可以钉在解决复杂任务的前沿**。Yun 的观察最结构化：今年最震撼的是**成本×质量前沿的移动速度**——社区发明了 "kill zone" 概念：每个新模型在"横轴成本、纵轴智能"的图上落一个点，前沿线代表每个价位的最优质量；**仅仅最近两个月这条线就被开源模型多次刷新**——GLM、Kimi、DeepSeek、最近的千问，每次发布大家都喊"左下角的模型全死了"。"从没见过技术演进这么快。"主持人补充自己的视角：年初 agentic 负载爆发，阿里云在几周内扩出千万级 vCPU 应对；下半年前沿模型扎堆发布。

**第二问：客户对开源权重的态度变了吗？** Yun：一两年前前沿被认为在闭源阵营，开源只是"便宜但低质的替代品"；**过去六到八个月这条线被跨过去了**——开源在各维度已可与闭源相当，所有客户都在认真考虑开源；而且超越成本/质量权衡，开源有**透明度、控制力、可定制**，这是闭源给不了的。Ted 两点补充：采用人群扩圈了——最早是 AI 原生公司（懂微调、懂模型能力边界），今年开源模型跨过可靠性阈值后，**传统企业也敢用了**；同时开源竞争太激烈、迭代太快，客户反而形成新心智——"**我要保留切换模型的自由**"，模型可切换本身成了他们产品里的标配功能诉求。主持人追问 Huiping：千问既开源了最大的 2.4 万亿参数模型也有闭源版本，开源战略图什么？Huiping 给了完整论证：①AI 已成为企业基础设施的一部分（工作流、产品、甚至决策），模型必须好用、**成本足够低才能铺得开**、还要安全可控；②开源让企业能用自己的数据做微调或后训练，**定制模型通常胜过通用模型**，保障企业竞争力；③可自托管（云上或自有机器）带来数据位置、管理、可用性的自主权；④可持续性：全世界的工程师、研究者都在评测开源模型、找弱点、做改进，与 vLLM、SGLang 这类推理框架和各类 Agent 框架一起构成开源 AI 的完整版图。主持人总结并补刀：开源还防"停服黑天鹅"——**今年确实发生过某闭源模型突然对非美国用户停服数周的事**，欧洲客户吓得不轻，这也是开源可持续性价值的现实注脚。

**第三问（给 Kaitao）：模型越来越聪明，推理越来越贵，怎么平衡？** Kaitao 给出全场信息密度最高的一段"推理经济学"：过去两年清晰的趋势是**智能随总参数规模增长**（前一天主论坛刚说千问下一代可能到 5 万亿甚至 10 万亿参数），而**推理成本随激活参数增长**——万亿参数模型每次只激活一小部分。推论很反直觉：模型很大但流量很小的公司自持部署**成本效率极差**（养一个 10 万亿参数模型要买一堆机器就为"放"着它）；而海量用户共享一个超大集群时，成本被全员摊薄，**实际成本接近同激活参数量的稠密模型**。稀疏化还在加码：MoE 是一种稀疏；Qwen 3.8 Flash 的稀疏注意力、线性注意力、逐层嵌入是另一条稀疏轴。他开了一个脑洞：假如有 100 万亿参数的模型，可能要一个超节点甚至一个集群专门"供"着它——只有几个用户时贵到离谱，用户够多、请求可批量并行时，**成本能摊薄到和小模型一样划算**。结论一句话："**云 + 大模型，可能就是通向超级智能的终极方案。**"

**第四问（给 Ted 和 Yun）：模型发版这么快，企业何时该自建衍生模型？** Ted 的框架：企业最终交付的是**价值（每个任务的成功成本）**，所以先分清什么变什么不变——业务目标、客户数据变得慢，**模型及其能力变得快**；所以要把力气花在"评对的东西"上：客服就看任务解决率，编码就**在你真实代码库环境里评测**，并且必须有可复现的评测框架。再看成本账：便宜的小模型因为错误和重试**未必真便宜**，更强的模型可能更少步数完成任务。经验观察：越稳定的任务，所微调模型的生命周期越长；快速演变的领域换得越勤。根本答案是：**建立自己的数据集、评测与迭代框架**——从当年 SFT 到现在的 RL，不变的是你的数据和环境。Yun 聚焦"如何穿过 benchmark 迷雾"：公开评测只能帮你**缩候选名单**，因为它不能代表你的工作负载——①公开数据集大概率已进训练集，模型早已过拟合；②它只刻画平均用例，刻画不了你的具体场景。所以每家公司必须**自建评测**，他还点了三件最容易被忽略的事：**其一，今天先进能力多来自 agentic，harness 是评测的一部分——同一个模型换一个 harness 跑同一个评测，可以差 10 分**，评测必须匹配你生产环境的那个 harness；**其二，要看轨迹（trajectory）**——多数 benchmark 只给通过率，但 Agent 好不好用藏在轨迹里：工具调用失败能不能恢复、知不知道何时停、上下文被压缩后还跑不跑题；**其三，成本必须是评测的一部分**——按 token 报价极具误导性，真实总成本取决于完成任务生成了多少 token 和缓存命中率，要评的是**端到端每任务成本**。主持人顺势升华：行业现在度量"dollar per million token"，黄仁勋在 GTC 讲"dollar per token"，也许终局是 **"dollar per business outcome"（每业务成果的成本）**——怎么标准化它，是下一个有趣的问题。

**最后一问：未来 12 个月的预测？** Huiping：还是成本——闭源模型 token 价格太贵，开源 AI 要在降本上继续突破，让 AI 应用人人可用。Ted：开源系统会变成**公用事业（utility）**——"付钱、灯就亮"，选择的复杂度、测试的复杂度都该由系统消化掉，"就像水和电"；而且凡是能定目标的都可优化、终将自动化。Kaitao：坚信开源模型会越来越好、在接下来的时代拿走更多市场份额，"我们正是在为那个时代造推理软件"。Yun 的格局最大：一年后再谈开源 AI，话题将不再是模型本身——而是**能源问题、硬件设计问题、数据够不够喂 AI、集成系统、AI 之外的缺失件（沙箱、记忆管理）、以及它如何改写整个计算生态**。主持人 Alex Chen 收尾抛出自己的"忐忑"：最近总听到 **RSI（递归自我改进）**——也许 12 个月后模型都在改进自己，届时发版不再这么多、"发布一次自己变强"，甚至我们会发明"度量自我改进能力"的新基准来替代现有 benchmark。"12 个月后见分晓，谁知道 AI 世界会变成什么样。"圆桌在笑声中收场。

## 这场的意义

**对行业：企业级 Agent 的共识底座浮出水面。** 这场峰会最有信息量的不是某一个模型发布，而是四类角色不约而同指向同一组关键词。钉钉讲**权限沙箱 + 文件可恢复 + 数据血缘**，SAP 讲 **Agent Hub + 护栏 + 双记忆**，BMW 讲**透明可见的助理形象 + 车端云下一致体验**——治理不再是合规附件，而是产品能力本身。同时"连续性"成为模型层的新叙事：16 天自主软件工程（151 issues/127 PRs/265 commits）证明前沿竞争已从"单步智商"转向"长任务耐力 + 激活参数经济学"，开源圆桌把它点透——智能随总参涨、成本随激活参涨，所以云 + 大模型是终局。开源侧的判断更直接：六到八个月前开源跨过临界点，kill zone 前沿两个月刷几次，传统企业已经进场，"可随时换模型"本身成了采购刚需。

**对个人：评测工程是当下最被低估、也最值钱的能力。** 这场把"Eval"抬到了方法论高度：公开 benchmark 只配缩候选名单；评测必须用你生产环境的 harness（换 harness 差 10 分）；必须看轨迹而不只是通过率（失败恢复、知止、上下文压缩后不跑题）；必须算端到端每任务成本而非 token 单价。无论做模型、做应用还是做基建，能搭起"自己的数据集 + 可复现评测框架 + harness 与生产一致 + 轨迹与成本分析"这套闭环的人，就是企业从"试 AI"走向"用 AI 交付业务结果"路上最稀缺的角色——度量衡从 dollar per million token 迁向 dollar per business outcome 的那一刻，价值锚点就从 token 变成了业务结果。

**对做产品的人：AI 是 enabler，体验才是 differentiator。** BMW 的"语音不会取代 GUI，未来是多模态"、Unity 的"AIGC 从抽卡池变成熟生产流程"、钉钉的"数字员工要有权限、邮箱和边界"、SAP 的"公司记忆让组织行为延续"——四句话合成同一条产品律：把模型的不确定性装进可预期、可审计、可个性化的体验容器里，Agentic AI 才算真正进入生产。而对内容产业，円谷 Fields 的登台说明连最保守的百年 IP 工业都已把 AI 写进制作管线——这一轮没有旁观席。
