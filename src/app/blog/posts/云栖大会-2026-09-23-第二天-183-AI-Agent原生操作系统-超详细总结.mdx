# 183-AI-Agent原生操作系统

> 云栖大会第二天下午的 AI Agent 原生操作系统分论坛，由阿里云与龙蜥（OpenAnolis）社区主办，联合浙江省经信厅、中兴通讯、鼎道智联、AMD、Arm、英特尔等产学研各方。全场围绕一个命题：AI Agent 是 OS 史上第一个"非人类用户"，操作系统必须从"给人用"重构为 Agent First——向下优化内核释放算力，向上提供 Harness 级治理让大家"敢用"。一场听下来，能建立 Agentic OS 三层架构、System Harness、意图总线、Skill Hub、Monorepo 数据面的完整词汇表。

## 这场为什么开（背景与定位）

开场致辞定调：AI 正从"会对话、能生成"迈向"能思考、会行动"，国家"十五"规划提出培育智能原生新模式、新业态，强化模、芯、云、用协同。AI Agent 原生操作系统不是给传统系统加一个"智能功能"，而是面向智能体时代重构的基础软件体系——向下连接芯片、计算、存储、网络，向上衔接模型、数据与应用，承载身份、权限、安全等治理能力。浙江提供产业底座：高端软件产业营收同比增长 14%，规上软件企业近 3000 家，人工智能服务商 67 家，首版次软件 447 项，备案生成式 AI 服务超百项，经信厅还联合 7 部门印发开源体系建设实施意见。另一关键节点：龙蜥社区刚完成向开放原子开源基金会的捐赠——本场正是"捐赠后新起点"上的一次产业总动员。

## 逐环节超详细还原

### 环节一：开场致辞——董钊（浙江省经信厅）与马涛（阿里云/龙蜥社区）

董钊代表浙江省经信厅致欢迎辞。他把云栖大会定义为观察数字前沿、汇聚产业力量的开放平台，指出智能体已进入研发、生产、服务场景，本场主题恰逢其时，并给出全场纲领："如果大模型拓展了智能的边界，那么操作系统所要解决的就是如何让这个智能能够稳定、高效、安全地服务千行百业。"他同时摆出浙江家底（详见背景），期待以论坛为契机共同探索智能体基础软件的新架构、新标准、新生态，欢迎创新成果率先在浙江找场景。

马涛代表阿里云和龙蜥致辞，最重要的一条：龙蜥已正式完成向开放原子开源基金会的捐赠，是社区深化开放治理、迈向中立透明的一步，也是六年开源实践的新起点——阿里云与龙蜥长期深耕服务器操作系统自主创新，未来将加速建设 AI 原生的操作系统社区。六年积累：从内核调度到云原生协同、经生产系统检验的全栈技术积累，装机规模千万级，汇聚超 1000 家产业链合作伙伴。面向智能体时代他提出两个动作：持续推动 **System for AI 与 AI for System 双向创新**（系统为 AI 优化、AI 反过来重构系统）；**通过 Skill Hub 沉淀可复用、可组合的系统能力**——下半场专门举行了发布仪式。

### 环节二：张鹏程——操作系统在智能体时代的演进与新生（Agentic OS 主报告）

张鹏程从第一性原理切入：文件、进程等概念都建立在"OS 由人操作、运行人编写的程序"的假设上，而假设被打破了——出现一类新型用户，"不需要睡觉，由目标驱动，自己规划任务、自己编写程序、自己调用工具、自己决定开关环境"，这就是 AI Agent。由此提出 OS 三件事：**加速、扩展、新生**。

**加速**：以 Alibaba Cloud Linux 为载体、依托龙蜥可信供应链：通用 CPU 与 ECS 最新实例协同优化；RISC-V 云上规模化应用；与平头哥真武芯片做算子级适配并广泛适配国产芯片；OS 与编译器、工具链协同全栈加速，叠加可信计算与合规资质。量化收益：**不换硬件、只升级最新一代 Alibaba Cloud Linux，通用负载即有 40% 以上性能提升**；加解密等负载经 AVX 指令集使能有 50%~3 倍以上提升；Agent 高密度沙箱环境经 MTHP 等内核特性，**时间提升 10%+、内存节省 20%+**，同等资源跑出更高部署密度。

**扩展**：面向智能驾驶、具身智能等"物理 AI"——LLM 已收敛到"Transformer+PyTorch+高端算力"，优化可被框架吸收；而这里技术路线并行演进、训练栈分散、高中低端算力并存，优化边界被推到 OS 层。为此推出 OS 级加速扩展组件（转写音"LongKey"），**现场宣布进入 1.0**：零代码侵入、统一交付、自动适配硬件，以插件与 PyTorch 版本自适配，内做图优化、算子融合、数据处理优化，在智驾/具身智能模型（含 PPO 类强化学习训练）场景带来 50%~3 倍以上提升。

**新生**：本场主角。Agent 负载四特征：自主规划多轮任务；异构协同（云端/本地 GPU 推理+本地 CPU 编排与工具执行）；按需隔离、弹性存续的沙箱；长任务连续性。判断"真 Agentic OS"三标准：①系统级 Agent 交互与支撑能力；②系统可被 Agent 原生自交互与互操作；③面向 Agent 负载的规模化稳定安全治理——"不能靠仅仅预装几个 Agent 应用、桌面加几个辅助窗口就说是原生体验"。落地三层架构：**接入层**对各类 Agent Harness 框架原生适配、零成本接入；**治理层**（OS Harness）覆盖身份、权限、安全、可观测与 Workspace；**内核层**以沙箱为主、快速启停、高密度调度。云上各类 Agent 负载（训练、Agent 服务平台、数字员工）跑在 ECS、轻量服务器、Agent 沙箱上，与阿里云 IaaS/PaaS 原生集成。客户收益四条：开箱即用、零成本互操作；token 流更经济（系统调用与工具层面"瘦身"）；针对 Agent 高频改工作区提供**毫秒级快照与恢复**，误操作秒回；内核级全流程观测与安全防控。生态：项目开源 GitHub，依托龙蜥建 Skill 生态，与联想、鼎道共建边缘方案。最后预告 **Cici Agent**：两年前的辅助驾驶 copilot 升级为主动驾驶角色与数字分身，现场开启公测。

### 环节三：李晋渊——DingOS：端边云协同的智能体操作系统实践（鼎道智联）

李晋渊介绍鼎道智联：约六年前成立、联想投资孵化的新一代 OS 创业公司，第一版系统已搭载联想 Yoga AI mini（2C）与 Think AI tiny（2B）全网发售。OS 管三件事：交互、软件、硬件和资源。他将其放进"物理-数字"映射：人、家庭、企业对应个人/家庭/企业 AI 孪生，设备是入口和孪生载体，算力来自端边云，关键话题是**数据主权**。一个预判：现在 95% 以上 token 由云端供给，随端边算力增强，**几年后端边承接的 token 生产比例可能达 80% 以上**，背后是隐私与安全驱动。行业机会三个：自然交互（从菜单点选的"功能集成"转向生成式交互、服务直达）；系统级 AI 内核（传统 Kernel 面向资源，Agent 时代需要新 Kernel）；端边云协同计算（端侧面向人的体验、边侧 AI 主机面向机器衔接、云端解复杂问题，设计即隐私）。他点破三道坎：**不会用**——"什么是 API、什么是 token"对普通员工是坎，单纯命令行安装 80% 的人搞不定；**不敢用**——国内 80% 以上企业真实生产环境要求私有化部署，否则不敢把商业秘密发给云端模型；**用不起**——AI coding 推进狠的工程师月用量轻易过万，月底财务质疑投入产出。鼎道 OS 向下万物智联、向上自然交互、原生支持智能体分布式协同，人智共生。

本场最重要落点是**与阿里云 Agent OS 团队的联合成果**：面向算力受限、离线弱网、长程任务（误挂快速拉起）场景，把 Agentic OS 的 token 治理、可观测、Agent 安全、工作区恢复与鼎道 OS 原生融合，在联想 ThinkCenter X Tower 上测试验证，现场发布可体验版本（二期智能馆龙蜥展台附近）。解决四个字：**看得清**（任务轨迹、Token、资源系统级统一观测）、**管得住**（行为可审计、可干预、可追溯）、**用得省**（系统级 token 治理，**减省 30% 以上**）、**跑得稳**（工作区恢复让长任务更长更稳）。

### 环节四：冯付秋——Cici Agent：从排障副驾到系统主驾（阿里云云系统服务）

冯付秋负责阿里云全体系值班与稳定性保障，开场点题："今天写 Cici Agent 这个代码，九成以上基本上都是 AI 写的。"但代码写得快，系统能上线吗？他抛出运维三大痛点：一是软件垂直栈越来越厚（应用→中间件→基础设施→计算存储网络，体感变薄实际更厚），"CPU 高了"和"程序卡住"的关联没人说得清；二是告警泛滥，"该看还是不该看"；三是 CVE 越来越多，"修还是不修"——不修怕黑客，修了怕变更引发故障。通用 AI 给运维方案也不行：对环境完全没了解，凭截图列 100 种原因可能一种都做不下去——运维 AI 凭什么搞定它看都没看过的几万行 AI 写的代码？

所以 Cici Agent 定位不是工具，而是**数字员工**——像真助手："你告诉他一句话，你是相信他能干好这个事情的；干不好就炒掉重新请一个"。覆盖发行版、系统应用、稳定性保障、技能运维（特指 AI 推理/训练流量运维）、安全；入口覆盖自然语言、Agent、IM（飞书/钉钉）——"电脑都不用打开，就问它一句：我系统现在健不健康？"结论源码级、可执行。**安全**：平常靠漏洞扫描、基线、供应链对比，但多数工具只看版本号评分，无法判断 kconfig 开没开、组件是否在信任边界内；战时热门漏洞从爆出到攻击路径 **7 小时内 POC 就有**、修复窗口按小时计，企业实际修复按天算；解法是植入"虚拟的十号、二十号安全员工"。**发行版专家**：选一个软件包要考虑漏洞、与已有架构兼容（傻装最新版可能整个代码垮掉）、生命周期与稳定性等级（P1/P2/P3）、内核强关联、社区意见；服务终端用户、下游发行版厂商、运维同行与研究人员。**稳定性**：感知应用异常（客户最反感"我应用抖动了，你说网络没问题"）、全栈指标关联分析、偶发问题的任意时间点推演与源码级栈级分析、告警有体感（"再不搞，一小时后系统就有问题"）、从告警→诊断→修复→点下一步执行一体化，覆盖宕机、巡检、函数级栈 Profiling。**防幻觉**：安全判定必须有攻击链证据；诊断带推理过程（GC 日志逐时间点剖析、宕机 CPU 各核状态与核间冲突因果链）；"Agent 产生的结果，要有证据支撑这个结论而产生，而不是泛化地给你一个原因让你去尝试"。接入：阿里云超级框、可观测 ARMS、ACK 控制台、OpenAPI 按 skill 集成、IM、多云。压轴案例：GPU 集群诊断剖析到 **PyTorch 某个 worker 训练负载高导致集群下降**；多卡训练精确识别某张单卡负载高导致任务卡住；火焰图下钻到算子级、行号级。

### 环节五：Ragu Nambiar——智启 Agent AI 新时代：龙蜥 OS 与 AMD 共筑开放智能算力生态（AMD）

AMD 全球副总裁 Ragu Nambiar（负责全球软件与解决方案，近期还向 TPC 提议开发 agentic AI benchmark）核心论点是替 CPU 正名：大家以为 AGI 需要"很多 GPU"，**不对——大量 Agentic AI 工作流将跑在 CPU 上**。三层理由：ERP、CRM 等通用计算继续跑 CPU；多 GPU 系统需要高性能 host processor 做大块内存拷贝与前后处理（AMD 两年前推出 64 核高频型号被广泛采用）；5B~30B 小模型推理 CPU 已"足够好"。数据：CPU 市场 2025 年约 260 亿美元，2030 年预计 2200 亿美元，通用计算年增约 5%，**增量主要来自 Agentic AI**。他强调 **Agentic AI 不是单一 workload，而是一条 workload 流水线**：gateway（高并发、可扩展 TLS）→组装上下文（内存带宽密集）→规划路由→推理（按规模选 CPU/GPU）→工具执行（ERP/CRM 要跑的传统数据库类；编译器类"拉起即退"的 ephemeral 工具，软件路径优化极关键）→验证→流式响应。最佳 CPU 六要素：高核密度（塞更多沙箱）、核强度、内存容量、内存带宽、I/O、生态。

产品落到下一代 **Venice**（EPYC 第六代）：256 核、双路 512 核 1024 线程，不超分支撑 **500+ 沙箱**、2 倍超分支撑 **1000+ 沙箱/服务器**；代际核强度 +20%；DDR5 8000 MT/s 可上 12800 MT/s；PCIe Gen6。生态侧与龙蜥持续 backport 内核、虚拟化、安全、可观测补丁，杭州常驻团队支持阿里。中国三年路线：2024 软硬件优化合作、2025 聚焦虚拟化/安全/数据库深度差异化、当前主题 **day zero optimization**——Venice 云实例发布即全量优化、开箱即得性能；对龙蜥的 backport 投入同比增长 85%，连续获最佳伙伴奖。结尾：团队当天已**基于 AMD 技术提交超过一打 skills**。

### 环节六：侯柯欣 & 贺军——Arm 服务器平台、AGI CPU 与 Agent Skill

侯柯欣先给大盘：2019 年推出 Neoverse 平台至今，全球部署**超 15 亿颗 Neoverse CPU 核**——0 到 10 亿颗用 6 年，10 亿到 15 亿颗只用 **6 个月**。云厂商：阿里云前一天刚发布倚天 710 系列 CPU，AWS Graviton 迭代到第五代，Google 部署 Axion，微软 Azure 有 Cobalt。Agentic AI 正重塑数据中心：**代理 7×24 不间断工作，产生 token 数是人类的 15 倍以上**；传统数据中心为人工驱动、可预测负载设计，而 Agentic 负载带来推理不间断、目标导向工作流、代理间调用扩展、资源动态调整。她的金句式判断：**数据中心自身已经变成了一个智能体**。产品侧发布 **Arm AGI CPU**（"世界上最高效的代理 CPU"，已送测），与中国 OEM 打造 19 英寸参考设计：**36 千瓦风冷机架放 30 个双节点服务器，单机架 8160 核、180TB 低延迟内存，算力密度是 x86 的 2 倍**；200 千瓦宽体机架放 42 个双节点服务器，单机架 45696 核、内存超 1PB，密度同样 2 倍。全球超 2200 万开发者在云上工作于 Arm 平台。

贺军讲"让 Agent 自己做性能调优"：**Agent 不具备 Arm 平台调优知识**——不知抓什么数据、得不出结论、给不出建议。解法两层：**Arm Performance** 是预配置开箱即用的分析套件，内置工程实践总结的 recipe（配方）——代码热点、指令组成分析（计算/访存/SIMD 比例）、CPU 微架构分析，接入覆盖 GUI、命令行、MCP，目标平台覆盖 Neoverse Linux 与 Windows on ARM；但 Agent 拿到工具也不知道选哪个 recipe、哪些指标关键。再加 **Arm Performance Agent Skill**：不只是文档，而是"能力赋予"——把微架构经验与调优实践喂给 Agent 的知识库。五步工作流：自然语言定义输入（"性能不及预期"+边界条件）→选 recipe、做规划→采集数据自动出报告→解读分析（热点函数、关键指标、瓶颈根源）→输出有数据支撑、evidence-proved 的优化实现。实测：对一个"运行不够好"的函数，Agent 自动执行 memory access、微架构等 recipe 并给优化，最终**接近 5 倍性能提升**。Skill 已可到龙蜥 Skill Hub 下载。

### 环节七：龙蜥 Skill Hub 推荐系统发布仪式与首批技能颁奖

全场唯一仪式环节，标志龙蜥从"操作系统社区"走向"Agent 技能分发平台"。发布流程是嘉宾共同将手放在启动球上倒计时点亮，先发布推荐系统、随后颁奖。发布嘉宾：马涛、刘东（龙蜥副理事长、中兴通讯副总裁）、Ragu Nambiar、侯柯欣、张金楠（沐鑫股份开源生态总监、龙蜥智算联盟副主席）、吴建渊（英特尔数据中心事业部系统和集群软件资深研发总监）。评选有百余位贡献者参与，推荐系统按**功能可信度、运行增益、静态质量、动态安全**四维度评估出首批技能榜单。从发布嘉宾构成看，芯片（AMD/Arm/英特尔）、整机与 OS（阿里云/中兴/浪潮/曙光）三方共同按亮启动球——Skill Hub 从出生就被设计成跨厂商的公共技能设施，而非某一家自己的应用市场。个人奖（最佳贡献个人奖、最佳实践奖）：张磊、李海伦、李勇、王子言、周正中，由马涛与 Ragu Nambiar 颁发；最佳生态企业奖：阿里云计算、浪潮电子信息、英特尔中国、超威半导体（AMD）中国、曙光信息、Arm、中兴通讯、信雅达科技，由马涛与刘东颁发——芯片原厂、整机厂、OS 厂商同台领奖，与 Ragu 演讲中"AMD 当天已提交超过一打 skills"相呼应。评审维度值得琢磨：技能商店不只看功能，还要评"运行增益"与"动态安全"——这是技能生态被企业信任的命门。

### 环节八：王江波——迈向 AI Native：下一代 Anolis OS 的研发范式跃迁

王江波把镜头转向 OS 研发本身。发行版现实：成千上万个软件包，每个包都像独立个体（引入、特性更新、漏洞修复、合规变化）；组合爆炸——x86/ARM 之外有 RISC-V、龙芯等国产架构，制品覆盖运营、云原生、桌面，**一百多种交付组合相乘**；社区维护 3+2 共 5 年（友商多为 2+2 四年），商业版本 5+5+3 达 13 年。传统"古法"下团队极辛苦——但庞大数据采样恰好与"AI 本身就是概率和采样的过程"对上，这是范式跃迁的机会。他坦诚复盘弯路：全交给 AI——稳定性不够，"今天在这个同学桌面可以搞定，到下一个同学桌面就跑不稳了"；OpenClaw 火了后做插件想流程化——插件维护成本极高（OpenClaw 不到一天一个正式版本、平均每天 200~300 个 commit），成本大过收益。最终收敛出四个范式：**范式一：确定的事让流程做，不确定、模糊、最后一公里的事让 AI 做**——解决单点工作"不发飘"，磨了三个月；**范式二：把 AI 当员工培养，outer loop 把同事打断、bugzilla 问题抽象成 event 喂给 subagent，inner loop 单点深钻保证准确率**——两层循环让 AI 7×24 跑下去，人只在必要决策时介入；**范式三：想清楚功能边界**——每个展台都自称 Number One，说明编排、存储、运行时技术未收敛；通用能力拿来主义（技术平权了，别造轮子），精力留给垂直领域，"真正有价值的东西还是你的业务"；**范式四：Monorepo 数据面**——千问 3.8 约 2.4T 参数、下一代近 4T、上下文越来越长，下一代 OS 把内核、glibc、工具链等整个数据面放进一个 AI 可解读的统一数据面，用一代数据面代表一代发行版：启动问题牵扯 initramfs、grub 与存储软件，包间关系让 AI 发现"人之前发现不了的问题"；选型、构建修复、CVE 验证封装成 AI 原子能力——"之前一步一步人在击鼓传花的东西，现在一句话全部搞定"。

四个场景战果：**选型**——把工程师维护在 Excel/JSON 的静态快照变成可解释、可追溯、自主可控的选型规则，沉淀公开数据+深度合作才有的 counter case（反例）；**构建**——约两三千个软件包 AI 流程调试，此前约 8000~12000 小时（70~80 人月），**AI 后提效 10 倍**；**CVE 修复**——对社区约 **18 万条**数据采样归纳，"用 Agent 魔法打败魔法"：生成代码 Agent + Review Agent 互审，人只兜底；**RISC-V 跨 OS 适配**——AI 对软件包做分层、依赖图谱、差异取证、报告生成，再分析业务构建态与运行态，"业务方是震惊的，没想到之前这么繁琐的工作，AI 梳理得头头是道"。龙蜥支持的 CPU 架构从 2 款变 5 款、人没增加 5 倍，AI 正持续缩短工作量与人力的 gap；"某大厂已没有前端工程师职位"是技术平权的注脚。结语：**中国操作系统一直在跟随，但 Agent 和 AI Native 阶段给了中国操作系统一个弯道超车的机会——红帽、SuSE 的"人"不再是最大优势，把 AI 用得更好才是真正的竞争点。**

### 环节九：蒋学新——中兴通讯下一代操作系统 AIOS 的研究和实践

蒋学新的开场判断是全场最"狠"的一句："决定成败的往往不是模型本身，而是模型之外，把这种概率的输出变成可靠执行的那一部分的系统能力。"三要素重构：**入口**——从 APP 走向场景，交互终极形态是感知而非触控，用户意图始终是中心；"每一次交互的革命，都是把翻译的成本从人转移到系统"；交互的尽头不是重做界面，而是演化出系统级智能体的新形态内核。**生态**——互通对象上移：设备互通→工具→A2A→智能体互通，业界正定义智能体与系统级之间的新契约（调度、全局状态、可信约束、能力进化的系统承接），不可能一家定义。**可信**——从"连得上"到"可靠达成、可控可信"：每跳成功率 90% 多，长程任务几十跳后准确率显著下降。

核心理论贡献是回答"OS 在 AI 时代的第一性使命"：**不是让智能体跑得更快、效率更高，而是踩刹车——最低的使命就是让大家敢用**，把不确定的东西经系统性工程和工程控制学变成确定的系统。理由：智能体可以自主，但控制权必须交还 OS，因为复杂度不在主循环、在循环之外；电信场景（自智网络网优智能体）实践证明最终裁决很难交给 LLM-as-Judge。于是控制权从 **Agent Harness→OS/节点 Harness→System Harness 逐级外推**：Agent Harness 管循环、记忆、工具、技能、护栏、沙箱；节点 Harness 管整机状态；System Harness 是端边云集群控制平面——身份与能力、意图与编排、全局调度、全局策略与端到端可信、分布式状态与系统进化。

落地按"可运行→敢托付→在约束中进化"三步走，工具是**意图总线**：类比 TCP/IP 协议栈抽象，让意图结构化、可寻址、可靠送达，分四层——传输和连接、消息与会话（长任务可靠跑完）、任务语义（意图转标准化任务描述）、能力寻址（智能体把能力注册到总线）；To B 意图来自工厂、电信的标准操作，最易下沉。**自主权四级**：只建议不执行（重大权益、低置信度）；先确认审批后执行（资金、隐私、物理动作——他举豆包手机：上京东买奶茶都能做到，但最后付款必须人点一下，这是法规要求）；低风险先执行；自动执行。**被约束者不能自己当裁判**——模型当裁判三宗罪：目标冲突（以完成任务为目标，天然放宽自我约束）、裁判逻辑不靠谱、规则容易被自己绕过。可信靠三要素：判定点、执行点、观测点——内核 eBPF 可在智能体全生命链做判定与钩子；对闭源智能体框架，OS 层 eBPF 的 agent insight 能从底层还原调用链，不依赖 Agent 自身可观测机制。**进化**借遗传学立论：进化=变异、选择、遗传，变异发生在个体，所以自进化进化的不只是单个智能体、而是整个系统；进化四级：L0 权重、L1 智能体个体与记忆技能、L2 跨实例系统、L3 对进化机制本身的优化。System Harness 与 Agent Harness 的区别一句话：后者关注"怎么更好地完成和学会一件事情"，**前者是让整个种群、集群、系统不必学习第二遍**。中兴实践：做 OS 20 多年（2005 年起做嵌入式），覆盖服务器、虚拟化、终端桌面、车载、机载；服务器 OS 基于龙蜥发行版，连续两年通过国家安可测评；AIOS 不另起炉灶，在成熟的新支点操作系统上融合扩展，架构分硬件层、基础设施层、技术服务层（智能体控制器/运行时/资源管理）、业务服务层，支撑电信设备、自智网络、终端与中兴云；龙蜥近两年综合排名前三。落地场景**家庭 VDC**：一台低成本算力主机连接全屋家电，隐私数据端侧处理、端云协同分级，未来可能演化为家庭机器人。展望：重新定义下一代**系统级 ABI**——调度、授权、状态、进化四类契约。

### 环节十：王卓——PyTorch 生态兼容：PPU 软件栈 Sail 的开源共建实践

最后一场回到"AI for System"最硬核的一层：给国产算力做软件栈。王卓来自阿里云 AI 编译器团队，背景两条：PyTorch 是 AI 训练推理事实标准，**今年 5 月阿里云正式加入 PyTorch 基金会成为白金会员**；平头哥正把自维护软件栈逐步开源为 **Sail 软件栈**（底层算子库、编译器及 PyTorch、SGLang、vLLM、Triton 等框架适配），阿里云和龙蜥社区将共建此生态。三块：

**No-GIL**：GIL（全局解释器锁）导致 Python 没有原生多线程加速——拿不到锁的线程全被 block，想并行只能多进程，这也是 AI 系统一跑几百个进程的原因。No-GIL 去掉全局锁后线程原生并行，实测：序列化/反序列化约 4~5 倍提升、训练 loss 计算约 2 倍、Web Server 约 1.5 倍。团队解决两个典型问题：一是**多线程多卡同步**——allreduce 时不同线程无法保证匹配顺序，解法是在 PyTorch 里固化集合通信应答顺序；二是**内存暴涨**——No-GIL 引入线程私有引用计数，对象必须在申请它的线程回收、生命周期变长（带 GIL 约 10 兆出头，No-GIL 变 20 多兆，修复后回到 10 兆左右）。解决后 **No-GIL 在平头哥 PPU 上已生产就绪**。**torch.compile**：eager 模式绑定预写 kernel，compile 把操作拉进计算图做编译、靠算子融合动态生成新 kernel；矛盾是各家硬件"独门绝技"以预写算子库提供、在 compile 路径用不到——用预写算子吃到硬件指令但没有融合，开融合又用不上硬件指令。团队在 PPU 上启用 **AIU 特性**（平头哥读取显存的独特能力）实测：支持 AIU 的算子库为 100% 基线，强开 torch.compile（只有融合）只剩 75%，**compile+AIU（融合+硬件特性）约 110%**；真武 890 上卷积等关键操作都有类似空间。**PPU 原生**：让 PPU 摆脱兼容层独立运行——上游主树设备（NVIDIA、AMD、英特尔）是一等公民享 day 0 支持，其他卡走 PrivateUse1 接入；团队先用 PrivateUse1 把 PPU 作为完全独立设备运行，长期目标是推进上游主树；架构为搜索推荐业务—PyTorch—PPU native 插件（直接调用 Sail 计算架构）。收益：典型算子最高 **11 倍以上**提升；端到端案例为阿里云某客户具身智能模型，摆脱兼容层后约 **7.48 倍**提升——来源是少一层分发开销+不受 CUDA API 限制、性能上限更高。

## 这场的意义

**对行业**，这场论坛完成了"Agent 时代操作系统"的一次完整立范：阿里云 Agentic OS 给出接入层/治理层/内核层三层架构，中兴 AIOS 把治理推到 System Harness 层并给出意图总线、四级自主权、"被约束者不当裁判"的方法论，鼎道把同一套能力落到端边云真实整机，AMD 和 Arm 证明 Agent 负载正在重写"什么是一台好服务器"（沙箱密度、机架密度、token 是人类 15 倍），龙蜥用 Skill Hub 把系统能力变成可评估、可分发、可治理的技能生态。主线异常清晰：**模型决定智能的上限，操作系统决定智能能不能被放心地用**——控制权从 Agent Harness 到 OS Harness 再到 System Harness 的逐级外推，已成为 Agent 基础设施设计的标准词汇。

**对个人**，场内有大量可直接迁移的工程范式："确定的事走流程、模糊的事交给 AI"加 outer/inner loop 两层循环，是让系统既稳又 7×24 的最小框架；"被约束者不能自己当裁判"提醒所有用 LLM-as-Judge 做验收的团队，裁决权要外推到系统层（判定点/执行点/观测点 + eBPF 级观测）；王江波的四个场景证明传统基础软件领域恰是 AI 提效最大的洼地；Arm 用 Performance+Skill 让 Agent 自己做性能调优拿到近 5 倍提升，示范了"领域知识 Skill 化"的做法。

**对中国基础软件**，还藏着一层叙事：龙蜥捐赠开放原子完成中立化治理、发行版研发范式在 AI Native 上率先重写、RISC-V 与国产架构进入交付矩阵、平头哥 PPU 经 PPU native 路线摆脱 CUDA 兼容层拿到 7 倍以上收益——AI Native 阶段所有厂商第一次站上同一条起跑线，这正是中国操作系统"弯道超车"的窗口期。
