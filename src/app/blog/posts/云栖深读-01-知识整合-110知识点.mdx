# LLM 推理与 Agentic 知识图谱（云栖演讲线整合）

> 2026-09-22 整理。来源：本轮对话（魔搭/vLLM/KV Cache/DiffSynth-Studio/LoRA/Agentic/TokenSpeed/PD 分离/Decode 等）+ 150% 扩展。
> 结构：第一部分 44 个原始知识点；第二部分 66 个扩展知识点；合计 110 个。

## 第一部分：对话中出现过的知识点（44 个）

### A. 模型社区与引擎底座
1. **ModelScope 魔搭社区**：阿里 2022 年开源模型社区，中国版 Hugging Face，模型/数据集/创空间/免费算力
2. **vLLM**：UC Berkeley 系开源 LLM 推理引擎，OpenAI 兼容 API，吞吐比原生 transformers 高数倍
3. **PagedAttention**：KV Cache 按页管理消灭显存碎片（是管理方式，不是另一种缓存）
4. **Continuous Batching**：迭代级调度，请求完成即插入新请求，GPU 不空转
5. **SGLang**：另一主流引擎，RadixAttention（前缀树缓存）、HiCache 分层卸载
6. **TokenSpeed**：LightSeek 基金会 2026-05 发布的 agentic 推理引擎；首创 C++ 控制面（有限状态机，编译期类型系统保证 KV 资源安全）+ Python 执行面分离；Qwen3.5-397B 上 580 TPS 纪录
7. **tokenspeed-mla**：LightSeek 用 CuTe DSL 写的 MLA prefill 内核，以独立 pip 包回赠 vLLM，仅支持 Blackwell
8. **TensorRT-LLM**：NVIDIA 闭源高性能引擎，TokenSpeed 的对标物
9. **ComfyUI / DiffSynth-ComfyUI**：节点式工作流 UI；DiffSynth 打包成节点库进 ComfyUI

### B. KV Cache 与注意力家族
10. **KV Cache**：缓存历史 K/V 免重算；Qwen2.5-7B 约 56KB/token，是推理显存瓶颈本体
11. **Prefix Cache / APC**：跨请求复用共享前缀（system prompt + few-shot）；"最值钱的缓存"
12. **KV Cache 量化**：FP8/INT8/INT4（KIVI）；量化粒度分 per-tensor 与 per-head（NM Testing 测试模型名即粒度差异）
13. **GQA**：多个查询头共享少量 KV 头，介于 MHA 与 MQA 之间的省显存方案
14. **MLA**：DeepSeek 发明，K/V 压成共享 latent 向量，KV 缩约 10 倍（67K→650K token 容量），代价是 prefill 内核复杂难写快
15. **KDA / 线性注意力**：Kimi Delta Attention，固定状态矩阵 O(N) 复杂度、无增长 KV；Delta Rule + 逐维衰减，状态更新是仿射变换 S'=M·S+B
16. **DCP**：Decode Context Parallelism，KV Cache 沿序列维度切片到多卡，解决 MLA 等效单 KV 头的全量复制问题，Kimi K2.6 上 3.3×吞吐
17. **全局 KV 池**：跨实例共享 + 分层卸载（CPU/SSD）——Mooncake（Kimi 生产平台）、Tair KVCache（阿里云 Manager+HiSim 仿真器）、FlexKV（腾讯）
18. **Head-of-line blocking**：长 prefill 阻塞同批 decode；用 token 阈值、调度策略、PD 分离破解

### C. 推理过程、指标与架构
19. **Prefill**：并行吞完整输入生成 KV + 首 token；算力瓶颈；决定 TTFT
20. **Decode**：自回归逐 token 生成；串行 + 显存带宽瓶颈；决定 TPOT
21. **TTFT / TPOT / 吞吐**：首 token 延迟 / 每 token 耗时 / tok/s/GPU 三大指标
22. **Speculative decoding 投机解码**：小模型草稿 + 大模型并行验证；K3 上 DSpark 118→370 tok/s（3.14×）
23. **PD 分离**：Prefill/Decode 机群分工 + KV Transfer + Router 路由（LightLLM Router + Mooncake Transfer Engine + mooncake-store 共享池）
24. **Token**：模型处理最小单位（≠字≠词），由 tokenizer 切分

### D. Agentic 生态
25. **Agentic 工作方式**：感知→规划→工具→观察→修正循环；与 n8n 固定流程图的本质区别是运行时自主决策
26. **Agentic 负载特征**：中位 14.2 万 token 输入、短输出、>96% prefix 命中、subagent 密集
27. **AgentX**：SemiAnalysis 用真实 agent 编程轨迹构建的服务基准
28. **Agentic 服务基准家族**：Agentic Bench（分钟级可控）/ AA-AgentPerf / XPerf（学术）/ MLPerf Agentic Inference（行业标准）

### E. 训练与微调
29. **LoRA**：冻结底模 + 低秩补丁 B×A（秩 8-64，约 0.8% 参数）；文件几十 MB；一底多补丁可叠加可合并；游戏 MOD 类比
30. **QLoRA**：4-bit 底模 + LoRA，16GB 卡微调 30B 级模型
31. **Gradient checkpointing**：只存少数检查点层、反传时重算，约 30% 算力换激活显存
32. **DeepSpeed ZeRO**：梯度和优化器状态（Adam 状态为参数量 2 倍）分卡切分
33. **CPU offload 训练**：参数在显存↔内存动态搬运（--enable_model_cpu_offload 一键开启）
34. **Split Training**：DiffSynth 独创，用计算图引擎把梯度无关计算（文本/VAE 编码）前置成独立阶段
35. **动态量化训练**：冻结底模压低精度 + LoRA 高精度，两者叠加

### F. 扩散生成（DiffSynth-Studio 线）
36. **DiffSynth-Studio**：魔搭官方扩散模型引擎（13.2k stars），推理+训练统一，显存管理（磁盘↔内存↔显存三级调度）
37. **模型矩阵 11 个**：图像 FLUX.2 / Qwen-Image-2.1 / Z-Image；视频 Qwen-Video-Edit / Wan-Animate-2 / LingBot-Video / LTX-2 / MiniMax-H3；音乐 ACE-Step / MiniMax-Music3 / YuE2
38. **Image-to-LoRA**：一张风格图一步推理直接产出 LoRA，把小时级训练压成一次前向（已有 V2 + 技术报告）
39. **Diffusion Templates**：可控生成的插件化训练框架
40. **DiffSynth-WebUI / 魔搭 AIGC 区**：一键 LoRA 训练工具 / 以 DiffSynth 为核心引擎的产品化入口

### G. 模型谱系与行业事件
41. **Kimi K3**：2.8T MoE、1M 上下文、KDA+AttnRes+LatentMoE（896 专家激活 16）、python render 程序替代 Jinja 模板
42. **DeepSeek 系**：MLA 发源（V2 起）；V4.1-Flash 用 CED 从 encoder 末态投出全局 KV 进一步压缩
43. **Day-0 支持生态**：Kimi K3 / Qwen3.8（2.4T）/ Qwen3.8 Flash Next / GLM 5.3 Flash / Inkling 均有 TokenSpeed Day-0
44. **行业事件**：云栖 vLLM 演讲线与 AICon；TokenSpeed 入 PyTorch 生态；KVCache.AI（清华 MADSys + 月之暗面，Mooncake/KTransformers）

## 第二部分：扩展知识点（66 个，原有量的 150%）

### 扩展一：注意力与长上下文深化（10）
45. **MHA→MQA→GQA→MLA 演化谱**：多头全存→单 KV 头→分组共享→latent 压缩，每一步都在削 KV 体积，是对话里 GQA/MLA 两站的完整地图
46. **Sliding Window Attention**：每 token 只看最近 W 个 token（Mistral/Gemma 用），KV 占用有上界
47. **RoPE + YaRN/NTK 外推**：旋转位置编码是长上下文的基础；插值缩放让短上下文训出的模型外推到长上下文
48. **Lost in the middle / context rot**：长上下文中段信息注意力变弱的通病，长窗≠会用
49. **长上下文评测**：needle-in-a-haystack 抽针测试、RULER 综合基准
50. **Mamba / SSM**：选择性状态空间模型，线性复杂度，常与注意力混合组网（Jamba、MiniMax-01）
51. **线性注意力家族**：RWKV / RetNet / GDN / KDA 一脉相承——用固定大小状态替代增长的 KV
52. **NSA 稀疏注意力**（DeepSeek V3.2）：训练原生稀疏化，推理时直接跳过不重要的 KV 块
53. **上下文压缩**：滚动摘要、ICAE（把长段压成少量 token）、CED（encoder 隐状态投影出全局 KV）
54. **KV 驱逐策略**：LRU、前缀树驱逐（SGLang radix eviction）、水位线管理（tair-kvcache Reclaimer 同题）

### 扩展二：推理引擎内核与调度（10）
55. **FlashAttention 1/2/3**：分块计算注意力中间结果不落显存，IO-aware 设计；FA3 是 Hopper 架构专用
56. **内核语言生态**：CUDA C++ / Triton（Python 写内核）/ CuTe DSL（CUTLASS 的 Python 内嵌 DSL）——tokenspeed-mla 用的就是 CuTe DSL
57. **FlashInfer**：LLM serving 专用 attention/kernel 库，多个引擎共用
58. **CUDA Graphs**：把一步内所有 kernel launch 录成图重放，削 CPU 调度开销，decode 小 batch 的命门
59. **torch.compile / 图编译**：动态图编译成优化静态图，训练推理都用
60. **Chunked prefill**：长输入切片分步计算，避免一次 prefill 霸占整个 GPU（vLLM/SGLang 默认策略）
61. **Goodput 调度**：vLLM 的调度新指标——有效吞吐（成功生成的 token/时间），区分"GPU 忙"和"干活有用"
62. **抢占与换出**：显存吃紧时把低优先级请求计算状态换出到 CPU 内存（preemption & swapping）
63. **结构化输出 / 约束解码**：grammar、JSON schema 约束采样，agent 稳定产出可解析 JSON 的保障
64. **采样参数族**：temperature / top-p / top-k / min-p / repetition penalty；低熵任务（代码）投机解码接受率更高（K3 实测 4.73 vs 2.61）与之直接相关

### 扩展三：量化与本地推理（6）
65. **PTQ vs QAT**：训后量化（快、零训练）与量化感知训练（精度更高）两条路线
66. **权重量化格式谱**：GPTQ / AWQ / GGUF（Q4_K_M 等）/ FP8 / NVFP4 / MXFP4——K3 原生 MXFP4、DCP 测试用 NVFP4
67. **weight-only 与 KV 量化是两个独立旋钮**：分别压权重和缓存，可叠加使用
68. **llama.cpp / Ollama**：本地推理全家桶，GGUF 格式，Apple Silicon 统一内存尤其友好
69. **消费级硬件账**：24GB 卡可推理 7B-14B 全精度 / 70B 4-bit 量化，LoRA 微调 7B-12B
70. **KV offload 分层**：HiCache（SGLang）/ LMCache / vLLM CPU offload——GPU→CPU→SSD→远端四级阶梯

### 扩展四：分布式与硬件（12）
71. **四种并行全景**：TP 张量并行 / PP 流水线并行 / EP 专家并行 / DP 数据并行；DCP 是在序列维上新开的第五维
72. **集合通信原语**：AllGather / ReduceScatter / AllReduce（NCCL 实现）；DCP 的 Q AllGather 就是典型用法
73. **NVLink / NVSwitch / NVL72**：单机高速互联域；GB300 NVL72 = 一台机 72 卡 B300
74. **InfiniBand / RoCE / RDMA**：跨机高速网络；Mooncake Transfer Engine 靠 RDMA 搬 KV
75. **GPU 世代线**：A100→H100/H200→B200/B300（Blackwell）→ Rubin；HBM3e 显存带宽是 decode 的生命线
76. **显存带宽算术（speed-of-light 估计）**：decode 每 token 要读全部权重+KV，显存带宽 GB/s ÷ 每步需读数据 GB ≈ tok/s 理论上限
77. **AMD 生态**：MI300X / MI355X，ROCm 栈；K3 发布即有 AMD 版，TokenSpeed 有专门 AMD 内核基准仓库
78. **国产芯片线**：昇腾等 NPU；kvcache-ai/sglang-npu 就是 SGLang 的 NPU 移植线
79. **DeepEP**：DeepSeek 开源的 MoE 专家并行通信库（kvcache-ai 有容错增强 fork）
80. **MIG / GPU 切分 / 多租户**：一张物理卡切多个隔离实例，推理云的成本利器
81. **K8s 推理栈**：llm-d（阿里云）/ KServe / vLLM production stack——prefix-aware routing 在这一层做
82. **AI 存储层**：DeepSeek 3FS、mooncake-store 的后端（HF3FS / NFS）——KV 池化的底座

### 扩展五：训练后技术（9）
83. **Post-training 全景**：SFT 监督微调 → RLHF → DPO（直接偏好优化，免奖励模型）→ GRPO（DeepSeek 发扬，R1 用它做推理强化）
84. **奖励模型与偏好数据**：RLHF 的两个地基；数据质量常比算法更决定成败
85. **知识蒸馏**：大模型教小模型；CFG 蒸馏、DSpark 草稿模型都是广义蒸馏
86. **LoRA 变体**：DoRA（幅度/方向分解）、rsLoRA（缩放秩）、PiSSA（主成分初始化）
87. **Adapter 家族**：ControlNet（空间条件控制）、IP-Adapter（图像参考注入）——扩散侧的"外挂"
88. **FSDP vs DeepSpeed**：PyTorch 原生全分片数据并行 vs 微软三件套，分布式训练两大路线
89. **FP8 / bf16 训练精度**：DiffSynth 2.0 的 FP8 训练把非训练模块 FP8 化省显存
90. **合成数据与自我提升**：模型自生成数据再训练（MiniMax-H3 自生成数据集训 adapter 是实例）
91. **微调选型决策树**：学风格→LoRA；注入知识→RAG；改行为→SFT/RL；动架构→全参。绝大多数场景不需要全参微调

### 扩展六：扩散模型原理（11）
92. **扩散原理**：训练时逐步加噪学去噪（DDPM），生成时从纯噪声逐步还原；等价的 score-based 视角
93. **Flow Matching**：学速度场而非噪声预测的新范式，FLUX / Qwen-Image 系采用
94. **LDM 潜空间扩散**：像素→VAE 压到潜空间→在潜空间扩散→解码，计算量降百倍，Stable Diffusion 的立身之本
95. **DiT vs U-Net**：扩散骨干从卷积 U-Net 换成 Transformer（SD3 / FLUX 全面 DiT 化）
96. **CFG 及其蒸馏**：分类器无关引导提升指令忠实度但计算翻倍；CFG-distilled 模型（MiniMax-H3）直接免掉这步
97. **采样器**：Euler / DPM++ / DDIM 与步数权衡；好采样器 = 少步数高质量
98. **步数蒸馏**：LCM / Turbo 把几十步压到 1-4 步生成
99. **文本编码器演化**：CLIP/T5 → 直接用 LLM 当编码器（Qwen-Image 用 Qwen LLM，长 prompt 理解力跟着涨）
100. **视频生成要件**：3D/causal VAE、时间注意力层、首帧条件、帧间一致性——比图像难一个维度
101. **音乐生成架构**：符号域 vs 音频域生成；ACE-Step（文生音乐）、YuE（词到整首歌）；DiffSynth-Music 提供节拍/人声/伴奏/韵律/参考五种控制
102. **生成质量评测**：FID（分布距离）/ CLIP score（图文对齐）/ Aesthetic / ImageReward——DiffSynth 已内置这排指标

### 扩展七：Agent 工程（8）
103. **MCP（Model Context Protocol）**：工具/资源接入的标准协议，Agent 连外部能力的通用插座
104. **Function calling 格式演化**：JSON mode → tools API → 推理与行动交织；结构化输出是其地基
105. **Agent 沙箱**：E2B、firecracker microVM——安全执行不可信代码；kvcache-ai 组织里就有 firecracker fork（agent 执行层）
106. **多智能体框架**：LangGraph / CrewAI / AutoGen / 子代理模式——AgentX 测的 subagent 密集负载就是这类用法
107. **Agent 评测**：SWE-bench（改真实代码）/ τ-bench（工具对话）/ WebArena（网页操作）——与 WebRetriever 比赛同域
108. **Context engineering**：上下文预算管理、压缩、compaction（长任务滚动摘要）——agentic 时代对 prompt engineering 的升级
109. **Agent 记忆系统**：向量库检索记忆 / 分层记忆 / 文件式记忆——OpenHarness 的 memory 模块就是这个问题的个人实现
110. **RAG vs 长上下文**：检索注入 vs 直接塞百万 token 窗口；成本、延迟、精度的三角权衡，prefix cache 正在改写这笔账
