# 深度扩展版：每块内容量 ×2.5

> 2026-09-22。承接 01-知识整合（110 个知识点），本篇对 14 个板块逐一深挖：原理机制、关键算术、工程权衡、实例。每块内容量约为上一版的 2.5 倍（原 1 + 扩 1.5）。

## A. 模型社区与引擎底座（深）

**vLLM 内部解剖**。一个 vLLM 服务分两层：前端 AsyncLLM（接收 OpenAI 格式请求、流式吐 token）+ 引擎核心（调度器、块管理器、GPU 执行器）。每个调度 step 干三件事：从等待队列按优先级选请求、给它们分配 KV 块、把这一步要算的 token 打包发给 worker。V1 引擎重写后用统一的异步架构，Python 调度开销靠编译优化压低。

**PagedAttention 的账**。旧式实现按"最大可能长度"给每个请求预留连续显存——一个最多 2048 token 的请求哪怕实际只用 100 token 也占着整块，外加显存碎片，论文实测浪费可到 60-80%。分页方案把 KV 切成 16 token 的块、按需分配、用"块表"记录逻辑顺序（像操作系统的页表），浪费只剩最后一个块的平均半个块（\<8 token）。Prefix cache 天然建立在这套块结构上：相同前缀的请求直接指向同一批物理块，引用计数 + 写时复制（copy-on-write）保证一方要写时不破坏另一方。

**Continuous Batching 的账**。静态批处理要等一整批里最长的生成完才能换下一批——长度差 10 倍时 GPU 大量时间在陪跑。迭代级调度把"批"的粒度从"请求"降到"step"：每生成一个 token 就重新决策，完成的立刻让位、排队的立刻补进。这一项就能把吞吐提高 2-4 倍，与 PagedAttention 组合构成 vLLM 的立身之本。

**SGLang 的差异点**：RadixAttention 用一棵前缀树管理所有历史请求的 KV——新请求来时沿树匹配最长前缀直接复用，树节点按 LRU 驱逐；配套"零开销调度器"（论文宣称消除调度间隙）。工程上 vLLM 胜在生态与模型覆盖，SGLang 胜在复杂 agent 场景的前缀命中设计与前端 DSL。

**TokenSpeed 的架构为什么激进**：传统引擎调度器和执行都在 Python 里，资源共享正确性靠运行时纪律（容易出 KV 被错误复用的 bug）。TokenSpeed 把控制面做成 C++ 有限状态机，请求状态（WAITING→PREFILL→RUNNING→FINISHED…）和 KV 块所有权在**类型里编码**，编译期就禁止"没登记就复用"这类操作；执行面留 Python 换研究迭代速度。580 TPS 纪录（Qwen3.5-397B-A17B）证明这套分离没有牺牲性能。

**TensorRT-LLM**：NVIDIA 闭源引擎，靠算子融合+内核特化榨硬件，历来是性能标杆；代价是黑盒、只跟 NVIDIA 硬件、迭代慢。TokenSpeed/TRT 对比的意义就在"开源易用能不能摸到闭源极限"。

**ComfyUI**：把生成流程画成节点图（模型加载→编码→采样→解码），每个节点缓存自己的输出，改一个参数不重算整条链。它成为图像/视频圈事实标准的原因是"工作流即文件"——可复现、可分享，DiffSynth-ComfyUI 就是把自己的引擎能力封装成这类节点。

## B. KV Cache 与注意力家族（深）

**从公式看 KV Cache 的必然性**。注意力 softmax(QKᵀ/√d)V 里，第 t 个 token 的输出要用**所有历史 token 的 K 和 V**。生成第 N 个 token 时若不缓存，前 N-1 个的 K/V 要全部重算——O(N²) 计算量。缓存后每步只算新 token 的一份 q/k/v，K/V 历史直接查表。通用显存公式：

```
KV 显存 = 2(K,V) × 层数 × KV头数 × 头维 × 字节宽 × 序列长 × 并发数
```

Qwen2.5-7B（28 层/4 KV 头/128 维/bf16）≈ 56KB/token；DeepSeek 类 MLA 模型每层只存 512+64 维 latent，缩约一个数量级——这就是 Red Hat 实测"最大上下文 67K→650K"的来源。

**GQA 的位置**：MHA（32 头各存各的）→ MQA（所有头共享 1 组 KV，质量受损）→ GQA（如 Llama-3-70B 的 64 查询头共享 8 组 KV，省 8 倍、质量几乎不掉）→ MLA（压到 latent，再省一个数量级）。GQA 是"性价比甜点"，MLA 是"极限方案但内核难写"——因为注意力要先用 W^UK 矩阵把 latent 解压，矩阵形状不规则，FlashAttention 通用内核吃不下，必须专门写（tokenspeed-mla 存在的理由）。

**KDA 的数学骨架**：线性注意力维护固定状态矩阵 S（每头 d_k×d_v），新 token 来时 S ← S(I − βkkᵀ) + βvkᵀ——先按误差修正（Delta Rule），再写入新信息；β 是逐维衰减率（该忘的忘）。分块训练时一个 chunk 的状态更新可写成仿射映射 S′ = M·S + B，仿射可结合，所以能 AllGather + 前缀扫描做多卡并行（Zhiyuan Li 那篇博客的主定理）。代价：完全放弃 softmax 注意力的精确检索能力，所以 K3/Kimi Linear 用"线性层为主 + 周期性全注意力层"混合。

**DCP 的机制**：张量并行按头切 KV，GQA 切到 KV 头数就到顶，MLA 等效 1 头 → 每卡必须存全量 latent，长上下文直接爆显存。DCP 改按**序列位置**切：每卡只存序列一段的 KV。每步解码时把各卡的 Q（很小）AllGather 过来，各自算本地注意力的部分 softmax（用 LSE——log-sum-exp——保存归一化因子），再合并。Q 小所以通信便宜。实测 Kimi K2.6（NVFP4）8×B200：并发 64 时 TP 版 KV 打满 100% 吞吐 1863 tok/s/GPU 到顶；DCP 撑到并发 512、KV 82%、6091 tok/s/GPU——3.3 倍来自"能装更多并发"。

**Mooncake/全局池的工程要点**：跨实例共享 KV 的三个难点——元数据一致性（谁的前缀在哪台机）、传输（prefill 机器算完的 KV 要在 decode 机器开始前送到，走 RDMA 的 Transfer Engine）、容量（GPU→CPU 内存→SSD 分层，各层有水位线，超了按配额驱逐）。tair-kvcache Manager 的设计：集中式元数据 + 两阶段写（先拿地址、写完确认）保可靠 + 兼容多存储后端（HF3FS/Mooncake/NFS）+ HiSim 用 CPU 回放轨迹仿真容量规划（不用真 GPU）。

## C. 推理过程与指标（深）

**TTFT 的分解**：排队时间 + prefill 计算。排队在最忙时占大头（好的调度器按"还需多少 token"排序而不是先来后到）；prefill 计算与输入长度线性相关，但 prefix cache 命中能把"14 万 token 的输入"变成"只算新增的几千"。chunked prefill 再把长 prefill 切成每步几千 token 的片，穿插 decode，防止一个 20 万 token 的大请求把所有人卡住几十秒。

**TPOT 的物理上限（speed-of-light 算术）**：decode 每 token 要把**全部权重 + 全部 KV** 从显存读一遍，所以单流上限 ≈ 显存带宽 ÷ 每步读数据量。例：70B bf16 权重 140GB，H100 带宽 3.35TB/s → 单流上限约 24 tok/s，实际打七折 ~17。这就是为什么 decode 提速三途只有三条路：压权重（量化）、少读 KV（MLA/稀疏）、多路摊薄（batch——batch=32 时 32 个请求共享一次权重读取，人均带宽成本降 32 倍，这就是"吞吐随并发上升"的本质）。TokenSpeed 名字里的"speed of light"指的就是拿这个理论上限当工程目标。

**投机解码的收益公式**：草稿模型连猜 k 个、大模型一次验证，接受率 p 决定期望加速 ≈ (1−p^(k+1))/(1−p)。关键洞察：验证是并行的一次前向（prefill 式），不增加串行步数；代码类低熵任务 p 高（K3 实测每步接受 4.73 个 token），创意写作 p 低（2.61）。变体：n-gram/lookahead（不用草稿模型，直接猜重复模式）、Medusa/EAGLE（在主模型头上加解码头）。

**PD 分离的三个配套**：① Router 要做前缀亲和——同会话的请求路由到缓存热的机器，否则分离反而增加 miss；② KV Transfer 要做速率匹配——P 机器产 KV 的速度和 D 机器消费的速度要对齐（AgentX 用两阶段法测配比）；③ 共享池做兜底——P/D 之间直传不及格就落池子，agent 会话历史长久保温。这套的成本模型：PD 分离多花机器，但 TTFT 和 TPOT 各自按最优硬件配——混合部署时两者互相拖累的损失往往更大。

**Tokenizer 细节**：BPE 从高频字节对迭代合并出词表（15 万级）；中文常见字≈1 token、生僻词 2-3 个；同一段文字不同模型 token 数差 20-30%。工程含义：上下文预算是按 token 算的，工具 schema + system prompt 常驻 5k-15k，"可用上下文"永远比标称少一截。

## D. Agentic 生态（深）

**Agent 一步的成本解剖**。一轮 = system prompt + 工具定义 + 全部历史轨迹（旧工具输出是大头）+ 新观察 → 模型 → 短输出（通常是"调用哪个工具+参数"）。三个推论：① 输入输出比悬殊（AgentX 131:1 量级、Mooncake 文 94.2% 命中/2242 token/轮增长）；② 每一步都在为"上一步的上下文"付钱，所以 prefix cache 命中率直接等于 agent 的成本折扣率；③ 输出短意味着 decode 时间占比小，**TTFT 主导每步延迟**——agent 速度优化的主战场在 prefill。

**子代理（subagent）模式为什么火**：主 agent 上下文被"污染"后注意力退化（context rot），且 KV 越长每步越贵。解法：主 agent 只留结论，脏活（读十个文件、搜一百个网页）开独立子代理——子代理用全新短上下文，干完只回传摘要。双收益：主上下文干净（质量）+ 子上下文短（KV 便宜）。代价：子代理不能命中主代理的前缀缓存，所以子代理内部也要复用模式（同样的工具定义前缀）。

**基准设计学**：真实回放（AgentX 用真实编码 agent 轨迹）胜在真实、败在慢（小时级）且数据集固定会被"调参过拟合"；可控合成（Agentic Bench 按指定长度/轮数生成文本负载）胜在快（分钟级）、变量可控（能单测"长输入"或"多轮"各自的影响）、败在可能失真。这就是那页对比表的本质：**真实基准定价能力，合成基准做回归测试**。指标看什么：TTFT/TPOT 的 P50+P99（agent 对尾延迟敏感——一轮几百步，P99 每步慢一点全程就慢）、每任务成本、以及 cache 命中率本身。

**MCP 机制**：JSON-RPC 2.0 协议，三类原语——tools（可调用的函数）、resources（可读的数据）、prompts（可复用的提示模板）；传输走 stdio（本地进程）或 Streamable HTTP（远程）。价值：工具生态从"每应用各自定义"变成"一次封装、所有 agent 可用"（你 ZCode 里挂的飞书/Notion MCP 就是活例）。

**Context engineering 三区法**：上下文分三段管理——**静态头**（system prompt+工具定义，永不变化，必须放最前以命中 prefix cache；乱序重排会摧毁缓存）、**增长的中段**（历史轨迹，定期 compaction：LLM 把旧轮次摘要成几百 token 替换原文，最近几轮保真）、**工作尾**（当前任务的活跃数据）。你的 omniscient-agent 每 4 条消息做滚动摘要，就是这个学科的个人实践。

## E. 训练与微调（深）

**全参微调的显存三件套**（7B 模型，混合精度）：参数 14GB（bf16）+ 梯度 14GB + Adam 状态（fp32 主权重+m+v）84GB ≈ **112GB**， activations 还没算——消费级卡连边都摸不到，这就是 LoRA 存在的理由。

**LoRA 的完整数学**：冻结 W，学 ΔW≈BA（B∈R^(d×r), A∈R^(r×k)，r=8-64）。缩放系数 α/r 控制补丁强度（α 常=2r）。挂的位置按性价比排：注意力 q/v 最常见，MoE 时代挂 gate/up/down 的收益也在验证。效果上 r=16 已覆盖绝大多数风格/角色场景；知识密度大的任务才需要 r=64+ 或多项叠加。推理时 W′=W+(α/r)BA 一次矩阵加法合并，零延迟；多 LoRA 不合并则可热切换（vLLM 的 LoRA adapter 路由）。

**QLoRA 三板斧**：NF4（4-bit 信息最优格式——权重近似正态分布，NF4 的量化格点按正态分位点摆，同样 4 bit 精度更高）+ 双重量化（把量化常数也量化）+ 分页优化器（显存峰值时溢出到内存）。16GB 卡跑 30B 的秘密全在这。

**梯度检查点的策略**：不是每层都存，按 √N 间隔存检查点，反传时分段重算——计算开销固定 ~33%，激活显存从 O(N) 降到 O(√N)。

**ZeRO 三档**：Stage1 切优化器状态（8 卡省 8 倍这项）→ Stage2 加切梯度 → Stage3 加切参数，通信换显存。与张量并行的区别：ZeRO 是"数据并行+切状态"（每卡算完整层），TP 是"把每层切开"（卡间高频通信，必须 NVLink 域内）。两者可叠：TP×PP×DP×ZeRO 是大厂配方。

**Split Training 的原理**（DiffSynth 独创）：计算图引擎追踪 pipeline 里每个变量，发现"文本编码/VAE 编码不需要梯度"就把它们整体挪到阶段一离线批量做完存盘，阶段二只跑带梯度的部分。对 ControlNet 类训练（控制图编码极贵）收益最大——快且显存骤降。

**微调选型决策树**（成本从低到高）：改风格/语气 → LoRA（小时级、单卡）；注入私有知识 → RAG（不训模型，检索注入）；改行为对齐 → SFT/DPO（需要千条级数据）；动核心能力 → 全参（基本只属于大厂）。90% 的个人场景停在第一层。

## F. 扩散生成（深）

**DDPM 双循环**：训练循环——对干净图 x₀ 随机加 t 步噪声得 x_t，让网络学"预测加入的噪声 ε"；生成循环——从纯噪声出发，反复"预测噪声-减去一小步"几百次还原。核心洞察是"去噪 = 生成"：能去掉噪声的函数必然"知道"干净数据长什么样。

**Flow Matching 为什么取代它**：DDPM 的采样路径弯弯绕绕（几百步），Flow Matching 直接学速度场 v=dx/dt，把噪声到图像拉成近直线路径——路径直，步数就少（几十步甚至十步内）。FLUX/Qwen-Image 系全部是 FM。

**LDM 的算术**：512×512×3 图直接扩散 = 78 万维空间；VAE 压到 64×64×4 潜空间 = 1.6 万维，**省 48 倍**。代价：VAE 决定了细节上限（生图"手糊"一半怪 VAE）。

**DiT 与条件注入**：骨干从 U-Net 换 Transformer（SD3/FLUX），图像切块成 token 序列；条件（ timestep、文本）通过 adaLN（自适应归一化）注入每个块。DiT 论文证明扩散也吃 scaling law——加大骨干稳步变好，这才有后来的视频大模型。

**CFG 的数学与代价**：每步同时算有条件 ε(c) 和无条件 ε(u) 两个预测，组合 ε̃=ε(u)+w·(ε(c)−ε(u))，w≈5-8。指令忠实度靠它，但计算量 ×2。CFG-distilled（MiniMax-H3 路线）训练时用成对数据把 w 的效果蒸进单次前向——推理省一半。

**视频比图难在哪**：① 时间维也要压（causal 3D VAE，时间约 4×/空间 8× 量级）；② 帧间一致性——每帧独立生成会闪，时间注意力层强行绑住相邻帧；③ 首帧条件（图生视频 = 把图像 latent 拼在噪声前面当"锚"）；④ 数据荒——带字幕的优质视频远少于图文对。

**音乐生成两条路**：符号域（先产 MIDI/歌词对齐再合成，可控但失真）vs 音频域（直接产波形/频谱，端到端但难控）。ACE-Step 走音频域+Flow Matching；DiffSynth-Music 在此之上加五种控制输入（节拍/人声/伴奏/韵律/参考曲）——本质是把"可控性"从文本提示扩展到多模态条件，和 ControlNet 之于图像是同一思想。

**DiffSynth 引擎内幕**：pipeline 抽象（每个模型=组件注册表+执行图）、三级显存调度（层粒度在磁盘/内存/显存间换页，2.0 支持同时释放内存和显存）、统一 QuantizeConfig（bitsandbytes/torchao 后端、支持量化后保存与量化+LoRA）。

## G. 模型谱系与事件（深）

**Kimi K3 的三件新架构**：KDA（上面已拆）；AttnRes（注意力残差——把浅层注意力输出跨层混入深层，缓解深层表示退化）；LatentMoE（896 专家激活 16，量化平衡路由——按分位数而不是 softmax 概率分配专家负载，防"几个专家被挤爆"；权重原生 MXFP4，即 32 元素一块共享指数的 4-bit 微缩放格式，OCP 标准，比朴素 4-bit 精度高）。工程冷知识：chat 模板不用 Jinja 而用 Python render 程序——多模态+复杂工具协议下模板语言已不够用。

**DeepSeek 的发明链**（几乎一年一项行业标配）：V2→MLA；V3→MTP（多 token 预测，投机解码的训练侧基础）+DeepEP；R1→GRPO 验证了"纯 RL 造推理能力"；V3.2→NSA（训练原生稀疏注意力）；V4.1→CED（encoder 末态投出全局 KV）。开源界"DeepSeek 发明、全行业跟进"的节奏是这套知识图谱膨胀的第一推力。

**Day-0 支持的工程含量**：新模型发布当天能上线推理 = 提前拿到权重做内核适配（新注意力结构要新内核）+ 量化配方（FP4/NVFP4 转换）+ chat 模板 + recipes 文档。TokenSpeed 连发 K3/Qwen3.8/GLM 5.3 Flash 的 Day-0，说明其内核插件化架构真在起作用。

## 扩展一：注意力与长上下文（深）

**RoPE 直觉**：给每对维度一个旋转频率（低维转快、高维转慢），token 按位置旋转 q/k，内积自然带出相对位置。外推问题：训练没见过的位置频率外推失真；YaRN/NTK 的思路是"拉伸"频率分布——高频（局部分辨率）少动、低频（远程）多插，让 4K 训练的模型在 128K 上保持表现。

**Lost in the middle 机理**：注意力对位置有 U 形偏置（开头结尾强、中间弱），长上下文中段召回率塌腰。缓解：关键信息放两端、RAG 检索少量精准注入优于全文堆窗、评测用 RULER（多跳检索/计数/聚合等任务族）而非只测抽针。

**Mamba/SSM 核心**：状态空间模型 S′=AS+Bu 本是线性时不变系统，Mamba 的突破是让 Δ、B、C 依赖输入（选择性——该记的记该忘的忘），配合硬件感知的并行扫描（segment scan）兼顾训练并行与推理递归。推理显存 O(1) 状态 + O(N) 计算，与 KDA 同属"固定状态家族"。

**稀疏注意力路线**：NSA 分"压缩 token / 选中 token / 滑窗"三路注意力分支，**训练时就让模型学会只用稀疏子集**（对比推理期稀疏化——训练推理不一致伤质量）。与 KV 量化是正交的两刀：一个减"读多少"，一个减"存多大"。

## 扩展二：引擎内核与调度（深）

**FlashAttention 本质是 IO 重排**：朴素实现把 N×N 注意力矩阵写回显存再读；FA 分块（tile）计算，每块在 SRAM 里算完 softmax 部分和（running max/sum 的在线 softmax），中间结果不落 HBM——计算量不变，显存读写从平方级降到近线性，attention 从"显存带宽瓶颈"变回"算力瓶颈"。

**三种内核语言的取舍**：CUDA C++（极致性能、开发慢）、Triton（Python 写、开发快 10 倍、性能通常到八成）、CuTe DSL（CUTLASS 的新前端：tile/布局代数抽象，写高性能 GEMM 族内核比裸 CUDA 快而比 Triton 更接近极限——tokenspeed-mla 选它就是这个甜点位）。

**CUDA Graphs 为什么是 decode 命门**：decode 一步有几百个小 kernel，每个 launch 有微秒级 CPU 开销——GPU 算 5μs、CPU 花 8μs 派活，GPU 在等 CPU。录图重放把几百次 launch 变一次。限制：形状必须静态，所以 decode（形状固定）受益最大、prefill（长度不定）要 padding 技巧。

**Goodput 的定义智慧**：吞吐指标会被"抢占-重算"污染（请求被换出又重算的 token 也计入吞吐）。Goodput 只计**最终成功交付**的 token/秒——引擎调度器对着它优化，行为立刻健康（少接多成，而非多接多废）。

**约束解码**：把 JSON schema/Grammar 编译成状态机，每步只允许合法 token（对非法位置 logits 置 -inf）。难点是性能（逐 token 查 FSM），xgrammar 用预编译+批处理把开销压到 \<5%。

## 扩展三：量化与本地推理（深）

**GPTQ/AWQ 的分歧**：都在做"训后 4-bit 且少掉精度"。GPTQ 用二阶信息（Hessian）逐列量化、误差即时补偿到剩余列（数学派）；AWQ 观察到 ~1% 的"关键通道"（激活异常大的通道）决定质量，对这些通道做激活感知的缩放保护（数据派）。实践上 AWQ 对 LLM 更稳，GPTQ 在小模型快。

**GGUF k-quants**：社区格式，Q4_K 之类用"超块-子块"两级缩放（32 元素子块 + 更大的超块），比朴素 4-bit 平均精度高；配套 llama.cpp 全家桶让 Mac 统一内存也成为推理平台（M 系芯片内存带宽接近数据中心卡）。

**FP4 家族（NVFP4/MXFP4）**：不是朴素 4-bit——每 32 个元素一组共享指数+缩放（OCP MX 标准），动态范围问题被块级缩放解决，这是 Blackwell 原生支持、K3 原生训练的格式。趋势：**从"训后压"走向"训练时就用低精度"**，量化损失从源头消灭。

**KV 量化的特殊坑**：KV 是逐 token 累积的，量化误差会随序列累积放大——长上下文任务对 KV 量化最敏感（TurboQuant 那篇评测测的就是 3-4 bit KV 在 30B-200B 模型上的精度-性能曲线）。缓解：FP8（有硬件支持、误差小）先行，INT4 配 per-head 缩放+关键层跳过。

**24GB 卡实战预算**（以 4090 为例）：推理 7B-14B bf16 舒适、32B 4-bit 可跑、70B 4-bit 勉强（长上下文受限）；LoRA 微调 7B-12B（QLoRA 可上 20B+）；显存大头排序：权重 > KV > 激活，所以"长上下文 + 大 batch"先爆的是 KV。

## 扩展四：分布式与硬件（深）

**四种并行的通信画像**：TP——每层前后都要 AllReduce（通信最重，必须 NVLink 域内，一般 ≤8 卡）；PP——只在地界传激活（通信轻但有空泡：p 级流水 m 个微批时空泡率 (p−1)/(m+p−1)，微批越多越省）；EP——MoE 专属，all-to-all 分发/回收 token 给专家（DeepEP 专门优化，正常模式大吞吐/低延迟模式小 batch）；DP——梯度同步一次（最便宜）。DCP 是序列维的新轴，和 TP 正交可叠。

**带宽阶梯要背下来**：NVLink5 单卡 ~1.8TB/s（NVL72 机内 72 卡全互联）> HBM3e ~8TB/s（B200，显存本身）> PCIe5 ~128GB/s > 400G RDMA ~50GB/s（跨机）。设计原则：数据搬运次数 × 每次体积要匹配所在阶梯——这就是为什么 TP 不出机柜、KV 跨机传输要批量聚合。

**为什么 decode 吃带宽、prefill 吃算力**（算术版）：prefill 一次算 1000 个 token，权重读一次被 1000 个 token 摊薄——FLOPs 主导；decode 一次算 1 个 token，权重还是要全读——带宽主导。同一个模型在两种负载下是两种硬件的情人。

**llm-d/K8s 层**：推理上云的完整栈=网关（prefix 感知路由）+ 调度器（KV 亲和放置、弹性扩缩）+ 引擎（vLLM 等）。难点从"单机性能"变成"集群缓存协同"——一台机器的 prefix cache 命中是局部最优，全局命中率才省钱。

## 扩展五：训练后技术（深）

**SFT 细节**：数据格式是消息序列，**loss 只算 assistant 回复部分**（prompt 部分掩掉——否则模型学着复述问题）；chat 模板（Jinja 或 K3 的 Python 程序）负责把消息渲染成模型输入，模板错=白训。

**RLHF→DPO→GRPO 的演化逻辑**：RLHF 三步（训奖励模型→PPO 优化策略+KL 锁定不跑偏）效果最好但最难调（PPO 超参地狱、训练不稳）。DPO 的洞察：RLHF 目标有闭式解，可以推出一个直接在偏好对上训的损失——免奖励模型免 PPO，两步变一步。GRPO 解决的是"奖励信号从哪来"：把一组采样的奖励做组内归一化当优势（不需要价值网络），DeepSeek 用它+可验证奖励（代码跑测试、数学对答案）把推理能力 RL 出来——R1 的配方。

**蒸馏两层**：输出层蒸馏（学生拟合教师的 logits 分布——比硬标签信息多）和行为蒸馏（教师产生数据给学生 SFT）。CFG-distill、投机解码草稿模型、大模型造合成数据微调小模型，本质都是蒸馏。

**决策树的经济学**：LoRA 训练 7B 风格 = 单卡几小时几十块电费；RAG = 零训练+检索基建；全参 70B = 数十卡数周。先问"改的是什么"再掏钱——把"训练"当唯一手段是 AI 应用最贵的错误。

## 扩展六：扩散原理（深）

**v-prediction 与噪声调度的关系**：ε-预测在低噪声端不稳定，v-pred（预测速度组合量）在整个噪声谱上更均衡，FM 系全面采用；噪声调度（sigmoid/cosine）决定"先学整体还是先学细节"。

**采样器谱系**：DDIM（确定化去噪，跳步可行）→ Euler（FM 的天然搭档：沿速度场走欧拉步）→ DPM++（高阶求解器，同质量步数再减半）。本质都是解 ODE，越好的数值方法步数越少；步数蒸馏（LCM/Turbo）则把"多步 ODE"本身蒸成 1-4 步网络。

**文生图的三级放大**：文本编码器（语义理解上限）→ 扩散主干（布局与风格）→ VAE（细节上限）。Qwen-Image 换 LLM 系编码器后，"图里精准写中文字"这类指令跟随能力暴涨——瓶颈其实在最上游。

**视频数据工程**：高压缩 3D VAE（时间 4×/空间 8× 量级）把视频压进潜空间；训练数据靠"字幕-视频"对和切镜头检测清洗；评测用 VBench 等多维基准（动作幅度、主体一致性、美学……）。视频模型的进步一半靠架构、一半靠数据管线。

## 扩展七：Agent 工程（深）

**沙箱的威胁模型**：agent 执行模型产出的代码/命令 = 执行不可信输入。爆炸半径控制：文件系统只读挂载+临时层、网络白名单、资源限额（CPU/内存/时长）。firecracker microVM（启动 ~125ms）让"每任务一个全新虚拟机"成本可接受——kvcache-ai 组织 fork firecracker 加迁移支持，就是给 agent 执行层用的。

**多智能体框架的本质分歧**：LangGraph=显式状态机（节点+边+共享状态，可控可回放）；CrewAI=角色协作抽象（船长/船员）；AutoGen=对话协议（agent 间消息驱动）。选型看任务结构是否可预先图化——可图化用 LangGraph，探索性任务用对话式。

**评测的坑**：SWE-bench（真实 issue+测试通过率）最硬但数据会被污染（模型训练时见过仓库）；τ-bench 引入模拟用户（考多轮工具对话中的政策遵守）；WebArena 自建可复现网站防污染——你打的 WebRetriever 比赛就是这一族（DOM 操作、每题步数限制、result.json 规范全是同款工程约束）。

**记忆三层与实现**：情景记忆（发生了什么——按时间/会话存）、语义记忆（提炼出的事实——去重沉淀）、程序记忆（怎么做——技能文件）。实现从向量库（embedding+HNSW 近邻检索）到纯文件（可 grep、可 diff、LLM 直读）正在回摆——你的 OpenHarness memory 模块走的就是文件派。

**RAG vs 长上下文的账**：1M 窗口每次调用全量重放 = prefill 成本随知识库线性涨（prefix cache 能救第二次但救不了首次）；RAG 每次只注入 top-k 相关块（检索准的前提下便宜两个数量级）。2026 的共识是混合：RAG 管事实召回，长上下文管当轮推理——而 prefix cache 让"反复用同一大知识库"的成本快速趋近零，这笔账还在被重算。
