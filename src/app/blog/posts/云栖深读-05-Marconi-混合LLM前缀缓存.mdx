# Marconi：混合 LLM 时代的前缀缓存（MLSys 2025 杰出论文提名）

> 来源：https://mlsys.org/Virtual/2025/poster/3260
> 论文 "Marconi: Prefix Caching for the Era of Hybrid LLMs"；作者 Rui Pan, Zhuang Wang, Zhen Jia, Can Karakus, Luca Zancato, Tri Dao, Yida Wang, Ravi Netravali（CMU + Meta）；代码 github.com/ruipeterpan/marconi。

## 问题：混合架构废掉了 prefix cache 的半壁江山

传统 prefix cache 靠"部分前缀匹配"复用：新请求和缓存条目共享到第 k 个 token 就能复用前 k 个 token 的 KV。但**混合 LLM（注意力层 + 循环层/SSM）里，循环层的状态是"原地更新"的**——一个缓存条目的 SSM 状态已经吸收了它整个序列的信息，无法回滚到"只看前 k 个 token"的状态。后果：部分匹配复用不可行，只剩精确匹配可用；缓存里堆满巨大而几乎不会重用的条目。

## 解法：面向复用概率与节省率的准入/驱逐

Marconi 的准入（admission）与驱逐（eviction）不只看新旧（recency），还看两个新维度：
1. **预测复用可能性**——在各种命中场景（精确/部分/跨请求）下这个条目被再用的概率
2. **单位内存的计算节省**——命中它能省下多少 prefill 计算 ÷ 占多少显存（"性价比"而非"大小"）

## 结果

跨负载与混合模型：token 命中率最高 **34.4×** 于 SOTA prefix cache 系统；TTFT 降低 71.1%（或 617ms）。

## 我的扩展

1. **和 01 文件是互补的两半**：Zhiyuan Li 两篇讲"混合架构的数学怎么并行训练"；Marconi 讲"混合架构上服务怎么缓存"——同一个架构选择在训练侧和服务侧各出一个研究热点，2025-2026 推理系统的主线之一。
2. **缓存经济学的一般式**：Marconi 的价值函数 = P(复用) × 省下的计算 ÷ 显存成本。这个式子对所有缓存层通用——prefix cache 块、KV 池条目（tair 的水位线驱逐）、甚至 agent 会话历史的 compaction 决策（旧轨迹摘要 vs 保真）都可以套。
3. **对 Kimi K3 的直接意义**：K3 = KDA 线性层 + 周期全注意力层的混合 → 恰好是 Marconi 针对的形态。K3 的 96% 命中率故事只覆盖注意力层那部分；线性层状态如何缓存复用，正是这条研究线的用武之地。
4. **延伸阅读**：SGLang HiCache（分层 KV 的工程实现）、Mooncake 论文（KVCache-centric 存算分离）、tair-kvcache Manager 的滑动窗口/KV 匹配策略（生产侧的多匹配探索）。
