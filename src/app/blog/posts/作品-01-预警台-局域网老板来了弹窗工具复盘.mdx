# 弹一句「老板来了」，凭什么迭代十八个版本？局域网预警台开发复盘

> 老板起身了，正朝你这排工位走过来。你还有三十秒收拾表情，而同事的屏幕上已经弹出一条置顶小横幅。这类「预警按钮」是办公室刚需，但把它做成「每台电脑装一个、谁都能发、人人都收得到、还能自动升级」的正经软件，会接连撞上一串桌面开发的经典暗坑。这个工具我叫它预警台：从 10 月 30 日立项到 11 月 9 日，从 v0.1 迭代到 v1.8，共十八个版本号。这篇就按时间线讲，每个版本到底在修什么。

## 一、结论先行

先给三句话结论。第一，这个工具没有任何黑魔法：UDP 广播加一个云端长轮询，全部代码只依赖 Python 标准库，连 GUI 用的都是自带的 Tk。第二，真正的工程量全在「让它在别人的电脑上活下来」这个环节——防火墙、窗口层级、进程交接，每一处都藏着不亲历就不知道的坑。第三，最值钱的一条经验：自动更新的版本号必须有单一真源，两个数据源对不上，下场是「每开一次软件就重装一遍」的死循环。

后面挑五个最有故事性的坑讲透，扫脸版单独一节，最后一张表收尾。

## 二、它是怎么工作的

架构一句话：一个进程干三件事。**发**，点大红按钮，消息按 UDP 全网广播；**收**，后台监听，收到就弹一条 380 像素宽的深色小横幅，macOS 落在右上角，Windows 落在右下角并自动避开任务栏；**常驻**，点关闭只是藏面板，程序留在托盘里继续值班。

发消息走两条通道。局域网通道用 UDP 2425 的飞鸽传书协议——装了飞鸽的机器会额外弹一个消息窗——再配一条自己的 2426 JSON 通道。云端通道是出站 HTTPS 长轮询：客户端主动连服务器，服务器实时推给同组所有人。局域网广播、定向单播、云端推送可能同时到达，接收端靠消息 id 去重，只弹一条。

```json
{"type":"boss-alert","id":"…","message":"老板来了！","sender":"预警台","ts":…}
```

id 这个字段是三路送达不重复弹窗的基石。同一个预警从三条路过来，内容一样但路径不同，没有 id 就要弹三次。

## 三、坑一：消息发出去了，同事的屏幕没反应

上线第二天，真实网络就把问题送上门了：有人点预警，别人收不到，自己反而收到两条。局域网广播用的是 UDP。UDP 像往小区里撒传单，撒完你就走了，没人告诉你传单被物业扔了。这里扮演物业的，就是 Windows 防火墙——它默认拦截入站连接，广播包到了门口就被扔掉。

先修诊断（v0.6）。每台预警台每 20 秒广播一次「我在线」，收到探测的机器回应一声。于是面板上能看见两种名单：回应了我的，列出「在线 N 台」；只发来探测、却收不到我回应的，单独列一行「收不到我的」。实测里这一行名单上的机器，几乎都是防火墙拦了入站。发送端同时改成三路齐发：按真实子网掩码给每张网卡算一个定向广播地址，再加全局广播地址，最后单播给所有在线机器；接收端按包 id 去重，「自己收到两条」也一并修掉。

再修自愈（v0.7）。程序每次启动自己检查防火墙规则，发现没有放行规则，就弹一次系统授权提权，用命令把规则补上，9 秒后复查。加上安装器的管理员模式自动放行和托盘里的一键放行，一共三条路；三条路都被拒绝的，面板常驻一行红字提示。

这一课的教训：局域网工具的送达率不是广播协议决定的，是接收端的防火墙策略决定的。工具能做的，是让「谁收不到」可见，然后自己把路修通。

## 四、坑二：自动更新变成死循环

自动更新（v0.8）的设想很顺：启动 60 秒后查一次服务器上的版本清单，之后每 12 小时查一次，发现新版本就静默下载、替换自己、重启新版。听起来半小时的活。但几天之后用户（就是我自己）发现不对劲：每次打开软件它都在下载更新，装完重启，下次打开又下，明明装的就是最新版。

现场证据很整齐：临时目录里躺着 10 个更新解包残留。对账之后根因浮出水面：**云端清单和包内程序的版本号是两个独立维护的数据源**。发版的那几轮只改了清单里的数字，没动源码里的常量，于是云端清单写着 12，装到机器上的程序自报 10。程序一对比，判定「有新版本」，下载安装，重启完一自检还是 10，于是再下载。只要版本对不上，这个循环就永不收敛。

修法分三层。第一层治根：版本号只认源码里的一个常量，发版脚本自动用它生成云端清单和安装器版本，清单和包同源，物理上错不了位。第二层治症：客户端记账，同一个版本号出现「装失败」或「装完没升级」，24 小时内不再重试。第三层留证据：Mac 包内写入构建标记，标记不大于本机版本就拒装；解包临时目录用完即清，启动时再扫一遍历史残留。

```bash
# 版本号单一真源：清单是发版脚本从源码常量生成的
# src/boss_alert.pyw     APP_BUILD = 18
# 服务器 boss-alert.json  {"version": 18, …}
```

这一课的教训：任何「两边必须对上」的数字，都只能有一个源头。各自维护的两份版本号，迟早对不上。

## 五、坑三：主程序从来没被检查过

v1.4 是一轮整体体检，第一道工序就炸出一个藏了三个版本的雷：主程序文件里有一个变量从未定义，在 Windows 上的三条路径（防火墙自检、一键放行、静默更新）一跑就会抛出「变量未定义」错误——而这些异常全被兜底的空捕获吞掉了，所以从来没暴露过。

这个雷为什么能藏住？因为主程序的扩展名是 `.pyw`（Windows 上双击运行不弹黑窗的 Python 文件），而静态检查工具 ruff 默认根本不扫 `.pyw`。换句话说，这个八百多行的主文件，从立项起就没被任何工具读过一遍。它一直「能跑」，只是 Windows 上有几条路一走就悄悄折返，而症状又被表象掩盖——Windows 侧「更新过了还反复更新」的另一半根因，就是这里。

修完这个错误，顺藤摸瓜清出一串：跨线程共享名单的读写加了锁，每 20 秒探测网卡导致频繁启动子进程的问题加了缓存，连构建配置文件被忽略规则误杀、导致新克隆无法构建这种反向坑也一并抓了出来。

这一课的教训：工具链的覆盖范围要主动核对。配置里加上「扫描 .pyw」这一行，等价于给一个从未体检过的文件做了第一次体检。异常可以吞，但前提是你明确知道吞掉的会是什么。

## 六、坑四：Tk 横幅的两个怪脾气

Tk 是 Python 自带的 GUI 库，它在 macOS 上有两个怪脾气，各咬过这个项目一口。打个比方，Tk 像一位老派前台：你叮嘱「这封信直接送到总经理桌上」，它点头答应；但只要这位总经理还没在系统里完成登记，它就把信默默扔了。

第一个脾气在 v0.4 修。用户点红叉关掉面板，之后预警横幅再也不弹。根因是横幅挂在那个已被隐藏的主窗口下面，macOS 拒绝让「父亲不在场」的子窗口上屏。最终架构变成一个隐形宿主：一个 1×1 像素、完全透明的主窗口永远保持登记，面板和横幅都是它的独立子窗口。这就是「关掉面板、横幅照弹」的前提。

第二个脾气在扫脸版 v1.6 修，此缺陷普通版同源、自 v0.3 起一直存在。横幅「在弹」，但点开任何前台应用就把它盖住。写了个小探针直接问操作系统，实测横幅的窗口层级是 0——和普通窗口平级。而代码里明明设置了置顶属性。真相是：置顶属性必须在窗口完成系统登记之后再设，登记前设的会被 Tk 悄悄丢弃。修法只是把设置时机挪后一行，设完复测，层级从 0 升到 19，横幅压住了所有前台应用。

这一课的教训：GUI 库「看起来生效」和「系统层面生效」是两回事。怀疑窗口层级问题时别盯代码，用系统接口直接问操作系统要答案。

## 七、坑五：更新交接那一刻，两个进程一起消失

这是最有戏剧性的一个坑。自动更新的最后一步是旧进程让位给新进程。扫脸版从 1.5 升到 1.6 之后，系统日志里出现一条怪记录：新进程启动后 0.2 秒就退出了，之后机器上没有任何预警台在跑，横幅从此静音。

还原现场：旧进程替换完程序文件，还握着本地端口睡 1 秒；新进程已经启动，去绑同一个端口，绑不上；按单实例逻辑，它判断「已经有一个我在跑」，于是发唤醒命令、拿到回应、按双开规则退出；旧进程睡醒，也正常退出。两个人都以为对方在值班，结果全班没人。

修法是把交接变成显式动作：新实例唤醒旧实例、拿到回应之后不立刻退出，而是轮询新端口，每 0.5 秒试一次、最多 16 次，确认接班成功才退。用户故意开第二个的真双开场景不受影响，只是多等几秒才退。

v1.8 顺手修了同一族问题的另一张脸：那几秒的等待期里，第二个实例会先把面板窗口建出来干等着，用户就看到一个多余的空壳窗口；静默启动的窗口隐藏也藏得太晚，构造时会闪一下。修法是把隐藏动作提前到构造函数里，窗口还没机会出现在屏幕上就已经隐藏，端口被占时也立刻藏。

这一课的教训：两个进程的交接必须设计成「新人确认到岗，老人才走」。交接流程里任何一步靠时序假设，都会在某个时间点变成「全班没人」。

## 八、扫脸版：一份源码，两个互不打扰的包

第二轮需求来了：办公室装了人脸识别门禁，希望在指定同事刷脸进门时，给装了预警台的机器弹一条专属横幅。要求很苛刻：特殊版必须保留普通版的全部功能，而普通版已经在线上稳定运行，一行行为都不能变。

分叉方式上有个三角取舍。复制一份代码，以后每个 bug 要修两处，迟早分叉走样；加编译开关，源码改了忘了重新打包，两个包行为不一致且看不出来。最终方案走第三条路：源码只有一份，包里放不放一个叫 `EDITION_FACE` 的标记文件决定身份。标记文件物理可见，漏打包就是「刷脸功能静默消失」，但一眼能查。CI 里有一道断言专门验证它，发版前包内二进制还会自报身份，对不上直接拒绝出包。

```text
包内有 assets/EDITION_FACE → 扫脸版
包内没有                    → 普通版（行为与历史版本逐字一致）
```

两版彻底隔离靠五件套：各自的 UDP 端口（普通 2426、扫脸 2427，扫脸版不发飞鸽）、各自的云端分组、报文里的版本标记、各自的更新清单、各自的自启键和防火墙规则。这样两版可以装在同一台机器上同时跑，互不覆盖、互不更新对方。这里藏着一个反直觉的硬约束：扫脸版必须查自己的清单——查错清单，下一次自动更新会把它「更新回普通版」，刷脸功能当场消失。

```json
// 普通版查 boss-alert.json，扫脸版查 boss-alert-scan.json
{"version": 18, "windows": "…Setup.exe", "macos": "…macOS.zip"}
```

门禁侧的接入是另一串实测坑。官方接口必须用 GET 加查询参数，换 POST 会报一个极误导的「尚未颁发秘钥」错误，看着像密钥没生成，其实是请求方式错了。签名参数的实际名字和文档写的不一致，按文档读永远是空。签名值里的加号经过 URL 传输会被解成空格，自己算的签名自己验不过，必须做百分号编码。中继入口的纪律只有三条：任何异常都返回 200，因为返回服务器错误会触发门禁云最多 11 次重试、放大轰炸；同一报文 120 秒去重；密钥只放在权限 600 的服务器配置文件里。

刷脸链路全程走通的样子是这样：有人刷脸，门禁云回调服务器，服务器验签、去重、按关注名单过滤，推给扫脸版专属分组，蓝条横幅弹出——抬头一行是门禁设备和时间，正文是固定文案。整个改造动了 10 个文件，加 473 行删 39 行，普通版的公开链接和版本号一个没动。

## 九、设计哲学：不做什么和做什么一样重要

这个项目有一页哲学文档，开头就把边界钉死了。这些「不做」不是偷懒，每一个都对应一种被滥用的可能。

**不做远控**。预警通道不携带任何可执行动作，哪怕只是「收到预警顺便打开某个网址」这种便利功能，也默认关闭且只在本机配置生效——防止有人借「预警」在别人电脑上启动程序。

**不做重服务器**。云端只是一个纯标准库的长轮询中继脚本，没有数据库、没有账号、重启就丢历史。它是可选增强，配置里把中继地址置空，就回退成纯局域网模式。

**不落日志**。预警是瞬时提醒，发送不留痕，接收不留档。谁在什么时候提醒过谁，工具不记。

**不追求全屏压制**。横幅盖得住普通窗口就够了，独占全屏的游戏和放映本就不该被打扰。

还有一个反向的自觉：代码里确实有几处故意吞异常，每一处都带注释说明理由——托盘变成僵尸、启动直接失败这类崩溃的代价，远大于吞掉异常。技术选型上全程零第三方运行时依赖，GUI 用 Python 自带的 Tk，丑的部分用自绘控件补，「放一个文件就能跑」是第一优先级。

## 十、十八个版本，一张表收尾

| 版本 | 问题 | 解法 |
|---|---|---|
| v0.4 | 叉掉面板后横幅不再弹 | 1×1 全透明隐形宿主窗口永远登记，横幅独立于面板 |
| v0.6 | 不知道谁收不到、自己收到两条 | 20 秒在线探测区分「在线」与「收不到我的」；三路齐发加包 id 去重 |
| v0.7 | Windows 防火墙拦入站 | 启动自检缺规则自动提权补上，9 秒复查 |
| v1.1 | 更新清单键名不匹配，静默失败 | 客户端兼容两种键名 |
| v1.2 | 云端推送与定时检查写同一临时文件互相截断 | 并发竞态修复，下载不再互相截断 |
| v1.3 | 清单与包版本错位，每次启动重装 | 版本单一真源加 24 小时记账，包内构建标记拒装 |
| v1.4 | 主程序从未被静态检查，错误被吞 | 扫描补上 .pyw，竞态加锁，版本三处自动同步 |
| v1.5 | 两版消息串台 | 端口、分组、报文、清单、自启键五件套隔离 |
| v1.6 | 横幅实际不置顶（系统层级 0） | 窗口登记后再设置顶，层级升到 19 |
| v1.7 | 更新交接时新旧进程双双退出 | 新实例轮询确认接班（0.5 秒一次、最多 16 次）才退 |
| v1.8 | 启动闪出空壳窗口 | 隐藏提前到构造函数，端口被占立刻藏 |

行动清单，想做一个自己的局域网小工具时照着查：

1. 广播协议选 UDP 就够了，但必须配「谁在线、谁收不到」的可视化诊断，送达问题的第一现场都在接收端。
2. 自动更新上线前，先确认版本号只有一个源头；客户端要对「装了没升级」记账，防死循环。
3. 核对你的静态检查工具的实际覆盖范围，别让主文件成为法外之地。
4. 任何涉及新旧交接的流程（更新、重启、迁移），设计成显式确认，不靠时序假设。

最后收个尾。回看这十八个版本，事故集中在两类地方：一类是「消息能不能送到」，防火墙、诊断、去重；另一类是「软件能不能自我维护」，版本号、交接、窗口层级。真正写一个能跑的工具，一天就够了；让它在所有人的电脑上稳定地跑，才是剩下十七个版本的全部内容。**桌面软件的功夫，都在屏幕之外。**
