# 说句话而已，为什么要加微信好友？我一天写了个免注册私聊工具

> 群里认识了个聊得来的人，想私发一个链接。点开微信，流程是：加好友、等通过、再解释一句"我是群里那个谁"。二手交易想问一句"还在吗"，先得交出去一个好友位。帮朋友装完软件想发个序列号，犹豫一下还是算了。说一句话的代价，被"加好友"这个动作抬得太高。这个小麻烦憋久了，就成了下面这个项目。

## 一、结论先行

这个工具叫**传呼台**（relay-chat），2026-11-06 立项，当天写完 v1.0.0；隔天安装包在真 Windows 桌面构建验收，随后双平台包上架下载站。一句话说清它是什么：**跑在自己服务器上的极简聊天工具——输个昵称进门，看见服务器上的人，点谁就跟谁私聊；有人发消息，系统角落立刻弹一张横幅。**

传呼台这个名字，借的是 BP 机时代的意象：你想找人说句话，给传呼台报个呼号，对方机上就跳出一行字。不需要加谁为好友，报上呼号就能被找到。

三个设计决定先摆出来：

1. **免注册免好友**：知道服务器地址、输个昵称就能进，昵称先到先得；
2. **服务器只中继不留底**：消息转交完就忘，聊天记录只存你本机，服务器不记访问日志；
3. **原生横幅**：Windows 弹右下角避任务栏，macOS 弹右上角避菜单栏，点一下直达会话。

一天能做完，结论有三条。第一，靠的不是打字快，是砍得狠——动代码之前先写了一份"不做什么"清单。第二，零第三方依赖不是炫技，是给自己少一类故障。第三，最容易翻车的不是聊天本身，而是 macOS 上"弹横幅"这一个动作，后面单开一节讲。

## 二、痛点：临时联系人被"好友"绑架

微信的好友关系，本质是一种正式登记。打个比方：加好友像去派出所落户，拉群像办酒席，而"就想问一句话"需要的，只是楼下传达室递一张留言条。临时联系人恰好卡在中间——不够格落户，也犯不着办酒席，于是这句话就一直没发出去。

传呼台给的答案，是把"联系"和"关系"分开。服务器上的人互相都看得见，发消息不需要任何一方点"同意"。你看到谁在线，点开就能说；对方不在线，留言暂存在服务器，他一上线自动补投（每人最多留 200 条、最多留 7 天）。

定位也说清楚：给熟人小圈子用，几人到几十人。它不是要替代微信，是补上"临时说句话"这个场景。

## 三、一天做完的秘密：先写"不做什么"

动手写代码之前，我先写了一份叫 PHILOSOPHY 的文档，一半篇幅在列"边界外"，也就是明确不做的事：

- 不做群聊、大厅、频道；
- 不做文件、图片、语音、视频，v1 只传文字；
- 不做账号体系：没有注册、改密、找回；
- 不做端到端加密；
- 不做已读回执、撤回、表情回应、@ 提醒；
- 不做托盘图标；
- 不做自动更新。

这些不是偷懒，每条都有理由。举两个例子。不做托盘图标，是因为实现它要么引第三方库，要么写一堆平台专用代码——为一颗小图标背上两类风险，不值。不做自动更新，来自上一个项目的教训：更新逻辑比功能本身更容易出事，装包出问题能把好好的软件更新坏。所以传呼台想升级，就去下载页拿新安装包，人工换。

砍完之后，v1 真正承诺的只剩八件事：看见人、加备注（备注只存本机，对方看不到）、一对一私聊、离线留言、弹横幅、本机聊天记录、失败看得见、关窗后常驻。**需求每少一条，要写的代码、要测的路径、要踩的坑，就跟着少一截。一天做完的底气，全在这份清单上。**

## 四、为什么敢零依赖：三个文件，一把锁

技术上最大的取舍是**零第三方运行时依赖**：客户端和服务器只用 Python 标准库，不装任何第三方包。理由写在文档里：依赖是别人随时能改的东西，少一个就少一类故障。打个比方：装修只用自己的工具箱，锤子坏了自己知道怎么修；样样找邻居借，邻居一搬家你就停工。

于是整个项目收敛成三个文件：

```text
server/relay_server.py    中继服务器：收消息、转发、暂存离线留言
client/chat_client.pyw    客户端：后台线程 + 系统横幅 + 本地服务
client/webui/index.html   聊天界面：单文件，零构建，内嵌样式和脚本
```

消息可靠性没有因为简单而打折。机制三句话：事件带序号，客户端存好才确认；没确认的，服务器重发；每条消息有编号，接收方按编号去重，重发也不会变两条。类比挂号信：签收才算送达，没签收邮局再送一遍。断线有提示并自动重连；发不出去的消息标红留在原地，点一下重发。

服务器的并发也不玩花活：每个在线用户一个线程，所有状态在一把锁下，按几十人规模设计。文档原话是"不需要更聪明的并发"——对规模诚实，比堆技术体面。

## 五、macOS 横幅：一天里最磨人的一段

需求只有一句话：别人发消息，右上角弹张小卡片，别打断手头的事。就这一句话，在 macOS 上撞出一串系统行为，逐个拆。

**坑一：弹横幅会抢走你的键盘。**每映射一个新窗口，macOS 都会把整个应用"激活"一次。真机实测：你正在访达里打字，横幅一弹，焦点直接跳到传呼台，你打的字进了它的输入框。解法是**窗口池**：启动时预建 4 个窗口，全部藏好缩成 1×1 像素；弹横幅只是把其中一个调出来，改改透明度和位置，不再新建窗口。测试里专门有一条："弹横幅时不得映射新窗口"。

**坑二：横幅要同时躲开菜单栏和程序坞。**固定留 40 像素只够避菜单栏——程序坞竖在屏幕右边时，横幅会压上去。解法是直接问系统要真实可用区域（AppKit 的 visibleFrame），程序坞在哪儿就避开哪儿。

**坑三：窗口有"户口"。**预建的窗口只属于创建时的桌面，你切到别的桌面或进了全屏应用，横幅就看不见了。解法是给窗口打上"跨桌面、全屏可见"的标记。

**坑四：点横幅回不去聊天窗。**系统命令只能"激活应用"，浏览器还开着别的窗口时，到最前面的并不是聊天窗。解法是用 AppleScript 点名，把传呼台那个窗口提到最前。

还有几处零碎的：置顶标记必须在窗口真正显示之后再设，之前设会被系统悄悄丢掉；横幅字号改用像素而不用磅——同一个字号，Windows 上比 macOS 大三分之一，卡片实测被撑到 197 像素高。

## 六、红队审计：一个半截字符能撂倒整个聊天

写完不等于能上线。我请了一个独立红队（只读代码、专门攻击的另一个 agent）来拆这个系统，它抓出一个最高危（P0）问题，而且当场复现了。

问题藏在 JSON 转义里。emoji 在编码里占两个单元，发消息的人可以构造一条只带前半个单元的文本，形如 `\ud83d`——相当于把"喜"字撕成两半，只把左半边装进信封。后果是三连击：服务器给收件人推送时，序列化这半截字符直接失败，收件人的消息流断掉；判定掉线的线程跟着挂掉，名单上所有人从此永远"在线"；服务器重启时转存未确认的消息，坏数据跟着走，再炸一次，别人的消息陪着丢。

一个人发一条坏消息，代价是全服务器聊天瘫痪加丢消息。修法四条：进门时拒收编码不了的字符；序列化失败回复 500 但不掐连接；关掉单个用户的失败不影响别人；消息转存离线前先把坏数据滤掉。配套 5 项"毒数据"测试，先红后绿。

这轮红队一共报了 17 项问题（P0 一项、P1 两项、P2 七项、P3 七项），全部处理——修得值的修掉，修了不划算的如实写进文档，专门开了一节"消息会在什么情况下丢"。测试从 85 项一路加到 113 项，另有 26 项真浏览器界面全流程。收尾还做了一次变异抽查：往 18 个关键逻辑里故意注入错误，18 处测试全部变红——抓不住错误的考卷，是假考卷。

## 七、上线与安装

服务器部署很朴素：一台阿里云 ECS，systemd 常驻，程序只听本机 8420 端口，nginx 把 `toolsfox.top/relay` 反代进去。两个细节值得记：长轮询一次挂起 25 秒，nginx 必须关掉响应缓冲，不然消息会被攒着不发；访问日志整个关掉——服务器承诺不留"谁何时连过"的记录。真客户端经 HTTPS 冒烟通过，收发延迟 0.1 到 0.9 秒。

客户端双平台安装包都在下载站：

```text
Windows: https://toolsfox.top/downloads/RelayChat-Setup.exe
macOS:   https://toolsfox.top/downloads/RelayChat-macOS.zip
```

装完三步上手：打开程序，输个昵称（服务器地址默认已填好）；名单里点一个人开始私聊；关掉窗口后程序还在后台，横幅照弹，点任务栏或 Dock 图标叫回来。

信任模型也如实交代，三条都写在文档里。**陌生人能进**——进门无门槛是产品选择，想收紧就在服务器上设一个进门密码重启。**昵称先到先得**——第一次用某个昵称时，服务器发一个令牌绑在你的设备上，别人知道你昵称也冒充不了你；代价是换电脑昵称带不走。**服务器看得到消息内容**——传输走 HTTPS，转发是明文，这条成立的前提是服务器是你自己的；不记日志是自律，不是密码学保证。

已知限制也直说：macOS 包没有开发者签名，防火墙开着时换新版要点一次"允许"；横幅只出现在主屏；Windows 真机的人眼复核还在待办清单上。

## 八、总结表

最后收个尾。这一天真正做完的不是"一个聊天工具"，而是一次取舍练习：**功能列表决定一个软件有多大，"不做"清单决定它能不能一天做完。需求每砍掉一条，要写的代码、要测的路径、要踩的坑就少一排——边界画得越狠，上线来得越快。**
