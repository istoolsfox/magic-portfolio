# 中文网页字体优化指南：子集化、切片与按需加载

## 一、为什么要优化中文网页字体？

中文字体文件通常比较大，因为它们需要包含大量汉字的字形数据。

例如，一个网页使用了一套 8 MB 的中文字体，但实际页面只用到了几百个不同的汉字。如果直接引用完整字体，浏览器可能需要下载远超实际需求的数据。

这会增加：

- 首屏加载时间
- 网络传输量和流量成本
- 字体加载延迟
- 页面文字从系统字体切换为目标字体时的闪烁感

对于使用 Vibe Coding（通过自然语言让 AI 编写代码）生成的网站，字体优化是上线前值得检查的一项性能工作。

注意：首屏白屏不一定是字体导致的，也可能与 JavaScript、CSS、网络请求或页面渲染有关。

## 二、什么是字体子集化？

英文：**Font Subsetting**

子集化就是从完整字体文件中提取指定字符的字形，生成一个只包含所需字符的较小字体文件。

字体文件通常包含：

- 汉字
- 英文字母
- 数字
- 标点符号
- 其他特殊字符

假设页面只用到“欢迎来到我的网站”以及正文中的部分汉字，那么没有必要始终向用户发送完整字体中的所有字形数据。

子集化可以删除用不到的字形，从而缩小字体文件。

### 示例

原始字体：

- 完整字体：8 MB
- 实际需要的字符：几百个
- 子集化之后：可能只有几百 KB

以上数字仅用于说明原理，实际结果取决于原始字体、字符数量、字体格式和压缩方式。

### 子集化的优点

1. 减少字体文件体积。
2. 降低首次下载字体的网络开销。
3. 减少不必要的数据传输。
4. 改善网页的字体加载体验。

### 需要注意

子集化之后，如果网页出现了没有包含在子集中的新汉字，该字符可能会回退到系统字体。

因此，正式项目必须考虑标题、正文、按钮、动态内容、错误提示以及其他可能出现的字符。

## 三、什么是字体切片？

英文：**Font Splitting**

字体切片是把字体拆分成多个较小的字体文件，并根据字符范围让浏览器按需加载。

例如，一个字体包含 1,000 个不同的汉字，可以将这些字符分配到多个文件中。

- 切片 A：一部分汉字
- 切片 B：另一部分汉字
- 切片 C：其他汉字
- 更多切片：其余字符

如果首屏只用到切片 A 中的部分字符，浏览器就有机会只下载相关切片，而不是下载全部字体文件。

### 子集化与切片的区别

| 技术                       | 核心作用                     |
| -------------------------- | ---------------------------- |
| 子集化 Font Subsetting     | 删除不需要的字符             |
| 切片 Font Splitting        | 将字符分配到多个字体文件     |
| 按需加载 On-demand Loading | 只加载当前页面实际需要的资源 |

子集化关注“保留哪些字”，切片关注“把字分到哪些文件”。

切片并不保证一定减少全部文件的总体积。它主要是让用户不必一次下载所有字体数据。

如果切片过多，也可能增加 HTTP 请求数量和调度开销，因此需要合理控制切片策略。

## 四、相关英文技术与工具

### 1. fontTools

Python 字体处理库。

官方文档：https://fonttools.readthedocs.io/

它可以读取、检查、修改和处理字体文件，也支持字体子集化。

### 2. pyftsubset

`fontTools` 中用于字体子集化的命令行工具。

主要用途：

- 按指定字符提取字体
- 删除未使用的字形
- 生成较小的字体文件
- 配合构建脚本自动处理字体资源

### 3. cn-font-split

中文网页字体拆分工具。

这类工具主要用于中文字体的切片处理，并可根据具体版本提供 CSS 配置或其他构建辅助功能。

使用时应查看对应项目的官方文档，确认支持的字体格式、字符收集方式和切片配置。

### 4. WOFF2

全称：Web Open Font Format 2。

它是适合网页传输的压缩字体格式，现代主流浏览器普遍支持。

WOFF2 主要解决字体文件的传输体积问题，本身不会自动判断网页需要哪些汉字。

### 5. @font-face

CSS 字体声明规则，用来告诉浏览器字体文件在哪里，以及应该如何使用它。

### 6. unicode-range

CSS 字体字符范围声明。

它可以告诉浏览器某个字体文件包含哪些 Unicode 字符，从而配合多个字体切片实现按需加载。

### 7. font-display

CSS 字体显示策略，用来控制网页在字体尚未加载完成时如何显示文字。

例如 `font-display: swap` 允许浏览器先使用备用字体显示文字，等目标字体加载完成后再切换。

这可以减少文字长时间不可见的情况，但可能出现字体切换。

## 五、字体优化的典型工作流程

```text
原始字体文件
TTF / OTF
    |
    v
收集网页实际需要的字符
    |
    v
字体子集化
pyftsubset
    |
    v
生成子集字体
    |
    v
转换或输出 WOFF2
    |
    v
可选：进一步切片
    |
    v
生成 CSS @font-face
配置 unicode-range
    |
    v
网页按需加载字体
    |
    v
检查加载速度和显示效果
```

这只是常见流程，并非所有项目都必须逐个执行每一步。某些工具可以集成字符提取、子集化、切片和 CSS 生成。

## 六、pyftsubset 命令示例

假设已经下载了一个字体文件：

```
SourceHanSansSC-Regular.otf
```

希望只保留指定的字符，可以执行：

```bash
pyftsubset SourceHanSansSC-Regular.otf \
  --text="欢迎来到我的网站首页" \
  --output-file="site-subset.woff2" \
  --flavor=woff2
```

参数说明：

| 参数                          | 作用                  |
| ----------------------------- | --------------------- |
| `SourceHanSansSC-Regular.otf` | 输入的原始字体        |
| `--text`                      | 指定需要保留的字符    |
| `--output-file`               | 指定输出文件路径      |
| `--flavor=woff2`              | 指定输出为 WOFF2 格式 |

安装工具：

```bash
python -m pip install fonttools brotli
```

如果系统没有 `pyftsubset` 命令，可以检查 Python 环境和命令行 PATH 配置。

### 命令示例的局限

上述命令只保留字符串中明确出现的字符。

正式网站往往还包含大量正文、导航、动态数据、数字、标点和错误提示。只使用少量示例文字进行子集化，容易造成缺字。

实际项目需要收集完整字符集，或采用可以根据网页内容自动生成切片的方案。

另外，必须确认原字体的许可证允许修改和网站分发。

## 七、为什么它可以提升首屏性能？

字体文件会通过网络下载。

当文件较大、网络较慢时，浏览器可能需要更长时间才能取得并使用目标字体。

子集化可以减少单个字体文件的数据量。

切片可以减少首屏必须加载的字体数据量。

WOFF2 可以进一步降低字体传输体积。

合理的 `font-display` 配置可以改善字体加载期间的文字显示体验。

三者配合，可以降低字体资源对网页首屏性能的影响。

### 需要关注的指标

- 字体文件大小
- 字体请求数量
- 首屏字体加载时间
- 页面文字是否出现闪烁
- 首屏渲染速度
- 网络传输量
- 是否存在缺字或字体回退

字体优化并不意味着一定能解决白屏。如果首屏是整个页面都无法显示，还应排查 JavaScript 执行、CSS 加载和主线程阻塞等问题。

## 八、Vibe Coding 网站上线前的优化建议

### 第一步：检查现有字体

确认项目引用的是系统字体、远程字体，还是本地字体文件。

在浏览器开发者工具的 Network 面板中筛选 `Font`，查看字体请求和文件大小。

### 第二步：确定是否真的需要自定义中文字体

如果使用系统字体就能满足设计需求，可以直接使用系统字体，避免额外下载字体文件。

### 第三步：生成字体子集

如果必须使用特定的中文字体，可以使用 `pyftsubset` 或其他工具处理字体。

### 第四步：按需切片

中文内容较多的网站可以考虑字体切片，并通过 `unicode-range` 映射字符范围。

### 第五步：配置 CSS

示例：

```css
@font-face {
  font-family: "SiteFont";
  src: url("/fonts/site-subset.woff2") format("woff2");
  font-display: swap;
}

body {
  font-family: "SiteFont", sans-serif;
}
```

这是单个字体文件的基础示例。如果使用多个切片，需要根据实际字符范围生成对应的 `@font-face` 规则。

### 第六步：优化关键字体加载

首屏确实需要的关键字体，可以考虑合理预加载。

不要无差别预加载全部切片，否则可能反而增加首屏网络竞争。

### 第七步：检查最终效果

重点检查：

- 中文是否缺字
- 标点是否正常
- 动态内容是否显示正确
- 字体回退是否明显
- 首屏是否更快
- 请求数量是否过多

## 九、技术选型总结

| 需求                       | 建议技术                              |
| -------------------------- | ------------------------------------- |
| 只保留需要的字符           | `pyftsubset`                          |
| 批量处理字体               | `fontTools`                           |
| 中文字体切片               | `cn-font-split` 等相关工具            |
| 减少网页字体传输体积       | WOFF2                                 |
| 将字体声明给浏览器         | CSS `@font-face`                      |
| 让浏览器识别切片字符范围   | `unicode-range`                       |
| 改善字体加载期间的文字显示 | `font-display`                        |
| 检查实际加载情况           | Chrome DevTools Network / Performance |

## 十、一句话记忆

- **子集化：删掉用不到的字。**
- **切片：把保留的字分装到多个文件中。**
- **WOFF2：使用适合网页传输的字体格式。**
- **unicode-range：告诉浏览器每个字体文件负责哪些字符。**
- **按需加载：让用户只下载当前需要的字体资源。**

对于 Vibe Coding 生成的网站，建议把字体优化放进上线前的构建流程，而不是等到线上首屏加载缓慢时再处理。
