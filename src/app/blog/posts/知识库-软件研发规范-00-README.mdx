# 软件研发规范集（工程实践向）

## 二、如何使用

1. **启动一个新项目**：`02` 定架构风格 → `03` 做系统设计与容量估算 → 用附录 ADR 模板记录关键决策；流程上的立项/需求走软考集 `01`/`02`。
2. **写代码前**：`01` 定设计原则基调，`06`/`07` 先定 API 契约和数据库模型。
3. **写代码时**：`08` 约束代码风格，`10` 落实安全编码，`09` 同步写测试。
4. **提交时**：`11` 走 Git 流程，`12` 互评，附录 CR 检查单自查。
5. **联调/上线前**：`05` 过性能与高可用检查，`13` 补齐日志/指标/告警，附录上线检查单过一遍。
6. **系统变复杂时**：回 `04` 补缓存/队列/限流等分布式手段，每次架构动作用 ADR 记录。

## 三、贯穿全集的十条军规

1. **简单优先**：先做对，再做快；能简单就不要聪明（KISS）。
2. **契约先行**：API 与数据模型先定契约再并行开发。
3. **高内聚低耦合**：模块按业务能力划分，依赖单向、无环。
4. **面向接口**：依赖抽象，实现可替换。
5. **一切皆可回滚**：发布、迁移、配置变更必须有回退方案。
6. **不信任任何输入**：外部输入一律校验；外部调用一律设超时、重试、兜底。
7. **测试是设计工具**：不可测的代码就是设计不好的代码。
8. **可观测内建**：没有日志/指标/追踪的系统等于盲飞。
9. **安全左移**：安全不是上线前的检查项，而是编码时的习惯。
10. **决策留痕**：重要技术决策写 ADR，让人能回答"当年为什么这么设计"。

## 四、裁剪原则

- 规范服务于交付，不是教条。个人小项目可只执行 08（编码）+ 11（Git）+ 附录自查单。
- 违反规范需要在 PR/ADR 中说明理由，"有意识的偏离"优于"无意识的不合规"。
- 各文档相对独立、可单独引用；与软考集的交叉引用见各文首"关联文档"。
