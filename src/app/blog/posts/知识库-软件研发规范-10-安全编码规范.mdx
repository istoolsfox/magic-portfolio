# 10 安全编码规范

> 原则：安全左移——设计期威胁建模，编码期守基线，上线前过检查单（附录 A）。

## 1. 威胁建模最小版

新功能设计时过一遍 STRIDE 速查：

| 威胁 | 自问 | 常见缺口 |
|------|------|----------|
| 伪装（Spoofing） | 身份怎么验证？token 能伪造吗 | 弱签名、无过期 |
| 篡改（Tampering） | 数据流转中谁能改 | 未校验签名、客户端可信 |
| 抵赖（Repudiation） | 关键操作有留痕吗 | 无审计日志 |
| 信息泄露（Info Disclosure） | 响应/日志里有没有敏感数据 | 越权读、日志带手机号 |
| 拒绝服务（DoS） | 无成本调用能打垮系统吗 | 无限流、无分页上限 |
| 越权（Elevation） | 水平/垂直越权检查了吗 | 只验登录不验归属（IDOR） |

## 2. 输入处理

- **不信任任何外部输入**：HTTP 参数、header、文件上传、第三方回调、消息队列消息，一视同仁；
- 校验三要素：类型、范围/长度、格式（白名单正则）；**拒绝优于清洗**，清洗优于转义；
- 文件上传：白名单扩展名+MIME 双检、重命名存储、独立域名/目录、禁止执行权限、限制大小；
- 富文本输出前按上下文转义（HTML/URL/JS 属性），模板引擎自动转义不许关。

## 3. 注入三防

| 注入 | 防线 |
|------|------|
| SQL 注入 | **一律参数化查询/ORM**（见 07 §6）；动态表名/排序字段用白名单映射，不拼接 |
| 命令注入 | 不拼 shell；必须调用时用参数数组形式（`subprocess.run([...], shell=False)`）+ 输入白名单 |
| SSRF | 用户提供的 URL 一律校验：只允许 http(s)、禁内网段/环回/云元数据地址（169.254.169.254）、解析后的 IP 再验一次（防 DNS rebinding） |

## 4. 认证与会话

- 密码存储：**bcrypt/argon2**，禁止 MD5/SHA1/明文；登录失败限速（按账号+IP）；
- 会话 token：随机足够长（≥128bit 熵）、设过期、登出即失效（服务端可吊销优先于纯 JWT）；JWT 用非对称签名或强密钥，禁 `alg:none`；
- Cookie 安全属性：`HttpOnly` + `Secure` + `SameSite=Lax`（默认）；
- 多因素与登录通知按业务敏感度引入。

## 5. 授权（越权是最高频翻车点）

- **默认拒绝**：每个端点显式声明所需权限，未声明即拒绝；
- **水平越权（IDOR）**：访问资源必须校验归属——`get_order(order_id, owner=user_id)`，永远带属主条件，禁止裸 ID 查询；
- 垂直越权：普通用户调管理端点 → 403；管理端点独立路由前缀 + 统一守卫，不靠前端藏入口；
- 越权测试进集成测试用例（用户 A 的 token 访问用户 B 的资源必须 404/403）。

## 6. 密钥与配置安全

- 密钥（API key、DB 密码、JWT secret）只放环境变量/密钥管理服务，**永不进代码库**（`.env` 进 `.gitignore`；历史泄露视为已泄露，立即轮换）；
- 代码库里禁止出现任何真实密钥；CI 加 secret 扫描（gitleaks/trufflehog）；
- 密钥支持轮换（双密钥过渡期），不做死绑定；不同环境不同密钥，生产密钥最小人数可见。

## 7. 敏感数据与隐私

- 分级：密钥类 > 身份类（身份证/手机号/地址）> 行为类（浏览记录）；每级有对应的存储/传输/展示/日志策略；
- 传输全站 HTTPS（TLS ≥1.2），内网服务间也建议 mTLS 或至少不跨不可信网络明文；
- 展示脱敏：手机号 `138****1234`；日志脱敏强制——**日志系统按"会进第三方/会被广泛查阅"假设设计**，密钥、token、密码、完整身份证永不打日志；
- 最小收集：不因为"以后可能有用"收集个人数据；保留期明确（到期删除/匿名化）。

## 8. 依赖与供应链

- 新依赖三问（同 02 §5）+ 额外一问：这个包足够主流吗（下载量/维护者）？冷门包是供应链投毒高发区；
- 锁文件（lockfile）入库，CI 跑漏洞扫描（pip-audit/npm audit/govulnconfig），高危（Critical/High）当日处理；
- 不用已停止维护的依赖大版本；升级走常规 PR 流程（有测试兜底）。

## 9. Web 通用防线（框架默认开启，禁止关闭）

- CSRF：写操作校验 CSRF token 或依赖 SameSite+Bearer（纯 token header 方案天然免疫）；
- 安全响应头：`Content-Security-Policy`、`X-Content-Type-Options: nosniff`、`X-Frame-Options`/`frame-ancestors`、`Referrer-Policy`；
- 错误页不泄露版本/堆栈；目录列表关闭；
- 限流（见 04 §6）+ 验证码应对自动化滥用。

## 10. 安全事件响应约定

1. 发现/被告知漏洞：先止血（下线功能/封禁入口/轮换密钥），再修复；
2. 评估影响面（哪些数据/用户），按合规要求处置与告知；
3. 复盘写进项目文档：根因、为什么防线没拦住、新增自动化检查；
4. 安全修复同 bug 一样：先写复现测试，再修复，回归确认。

## 11. 检查单

- [ ] 所有外部输入有类型/范围/格式校验？
- [ ] SQL 全参数化，动态字段白名单？命令执行无拼接？取 URL 有 SSRF 防护？
- [ ] 密码 bcrypt/argon2？token 有过期与吊销？Cookie 三属性齐？
- [ ] 每个资源访问校验属主（IDOR 用例在测试里）？
- [ ] 密钥零入库，CI 有 secret 扫描，轮换方案存在？
- [ ] 日志/响应/错误页无敏感信息与内部细节？
- [ ] 依赖有锁文件与漏洞扫描，高危当日清？
- [ ] 安全响应头齐、CSRF 有对策、限流在位？
