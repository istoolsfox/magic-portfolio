## A.2 ADR（架构决策记录）模板

文件名：`docs/adr/NNN-<kebab-case-标题>.md`，一条决策一个文件，append-only（被推翻标 Superseded，不删）。

```markdown
# ADR-NNN：<决策标题>
- 状态：Proposed | Accepted | Superseded by ADR-XXX | Deprecated
- 日期：YYYY-MM-DD
- 决策人：<名单>

## 背景
<面临什么问题/约束，为什么现在要决策>

## 候选方案
| 方案 | 优点 | 缺点 |
|------|------|------|
| A | | |
| B | | |

## 决策
<选了什么>

## 理由
<为什么选它，关键权衡是什么>

## 放弃理由
<没选的方案为什么没选（半年后最有价值的部分）>

## 影响
<需要跟进的改造、迁移、培训成本>

## 复审条件
<出现什么信号时重新评估本决策>
```

## A.3 设计文档要点模板

完整模板见 [03-系统设计方法论](/blog/%E7%9F%A5%E8%AF%86%E5%BA%93-%E8%BD%AF%E4%BB%B6%E7%A0%94%E5%8F%91%E8%A7%84%E8%8C%83-03-%E7%B3%BB%E7%BB%9F%E8%AE%BE%E8%AE%A1%E6%96%B9%E6%B3%95%E8%AE%BA) §2，最低要求九节：背景与目标（含**不做什么**）→ 需求与约束（非功能带数字）→ 总体设计（架构图）→ 详细设计（API/数据模型/时序）→ 关键决策（链 ADR）→ 容量与性能（估算）→ **失败模式分析** → 上线与回滚 → 开放问题。

## A.4 PR 描述模板

```markdown
## 做什么 / 为什么
<1-3 句；关联 issue：Closes #123>

## 改动范围
- <模块A>：<改了什么>
- <模块B>：<改了什么>

## 怎么测的
- 单测：test_xxx（边界：…）
- 集成/E2E：<跑过什么>
- 手工验证：<步骤与截图>

## 风险与回滚
- 风险：<对什么有影响，观察什么指标>
- 回滚：<一步做什么>

## 自查
- [ ] lint/format 过，测试全绿
- [ ] 无调试残留、无密钥
- [ ] 文档/契约/changelog 已同步
```

## A.5 事故复盘模板（配合 13 §6）

```markdown
# 事故复盘：<标题>（YYYY-MM-DD）
- 级别：P1/P2 | 状态：草稿→定稿
## 时间线（发现→响应→定位→修复→恢复，各节点精确到分钟）
## 影响面（用户数/时长/资损/数据影响）
## 根因（直接原因 → 深层原因 → 为什么防线没拦住）
## 做得好的 / 做得差的（无指责，对事）
## 行动项
| # | 行动 | 类型（自动化/流程/文档） | 责任人 | 期限 | 状态 |
```

## A.6 快速参考：十条军规（全集浓缩）

1. 先做对，再做快（KISS）
2. 契约先行（API/DB 先评审再开发）
3. 高内聚低耦合，依赖单向无环
4. 依赖抽象，实现可替换
5. 一切皆可回滚
6. 不信任输入，不裸调用外部
7. 不可测 = 设计差
8. 可观测内建
9. 安全左移
10. 决策留痕（ADR）
