# 软件设计与工程管理规范集

> 来源提炼：《系统集成项目管理工程师教程（第3版）》（软考中级）
> 目的：在开发软件时，可参照本套文档作为「标准规范」执行，符合软件设计原则与工程化管理要求。
> 版本：v1.0

## 一、这套文档是什么

本套文档将原教程（616 页）提炼为一套**可直接落地执行的软件设计与工程管理规范**。它不是教材的简单摘要，而是按「做软件的标准动作」重新组织：从立项、需求、设计、编码、测试、部署交付，到配套的项目管理、配置/变更管理、文档管理与质量保证。

适用对象：软件研发团队、项目经理、架构师、开发/测试工程师。

## 三、如何使用

1. **新建项目**：按 `01` 确认生命周期与过程框架 → 按 `10` 立项 → 按 `02` 做需求。
2. **设计阶段**：`03` + `07` + `08` 给出设计规范与架构约束。
3. **实现阶段**：`04` 约束编码与配置管理；`09` 落实安全基线。
4. **验证阶段**：`05` 定义测试；`13` 定义质量目标。
5. **上线阶段**：`06` 定义部署与交付；`11` 管理上线变更。
6. **全程**：`12` 管理文档；`10` 管理进度/成本/风险/干系人。

> 各文档相对独立，可单独引用；相互之间有交叉引用关系，需保持一致。

## 四、设计原则总纲（贯穿全文）

1. **工程化**：系统化、规范化、可度量的方法应用于软件开发全过程。
2. **高内聚、低耦合**：模块划分的基本准则。
3. **面向对象 7 原则**：单一职责、开闭、里氏替换、依赖倒置、接口隔离、组合复用、迪米特法则。
4. **需求驱动**：一切设计以 SRS 为源头；需求变更必须走受控流程。
5. **基准管理**：计划、配置基线、变更以「基准」为准绳。
6. **质量内建**：将质量融入过程和成果中（而非事后检查）。
7. **裁剪适配**：根据项目环境对规范进行裁剪，不机械套用。

## 五、文档质量分级（供交付物分级参考）

| 级别 | 名称 | 适用场景 |
|------|------|----------|
| 1级 | 最低限度文档 | 开发量 \< 1 人·月，自用程序 |
| 2级 | 内部文档 | 未与其他用户共享资源的专用程序 |
| 3级 | 工作文档 | 同一单位若干人联合开发 |
| 4级 | 正式文档 | 正式发行、普遍使用的软件产品（遵守 GB/T 8567） |

> 合规要求：正式对外交付的软件文档建议达到 4 级（遵守《计算机软件文档编制规范》GB/T 8567）。
