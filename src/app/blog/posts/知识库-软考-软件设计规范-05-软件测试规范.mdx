# 05 软件测试规范

> 来源：《系统集成项目管理工程师教程（第3版）》第5章

## 1. 测试的目标与意义

- 测试是交付前必须完成的重要步骤：使用人工或自动手段运行/测定软件系统，检验是否满足规定需求，弄清预期与实际结果的差别；
- 目的是**确保软件质量**，验证软件是否做了用户期望的事；
- 测试要**贯穿整个软件开发过程**，保证整个过程高质量；
- 软件正确性证明尚未根本解决，测试仍是发现缺陷的主要手段；
- 依据标准：《计算机软件测试规范》GB/T 15532。

## 2. 测试方法

### 2.1 静态测试
程序不在机器上运行，依靠分析/检查源程序语句、结构、过程来检查错误。通过对 SRS、设计说明书、源程序做结构分析与流程图分析找错。
- 对文档的静态测试：以检查单形式进行；
- 对代码的静态测试：**桌前检查、代码走查、代码审查**；
- 经验：可有效发现 30%~70% 的逻辑设计与编码错误。

### 2.2 动态测试
在计算机上实际运行程序，将运行结果与预期比较，分析运行效率与健壮性。常用**白盒测试**与**黑盒测试**。

#### 白盒测试（结构测试）
- 主要用于单元测试；把程序看作透明白盒，按内部逻辑结构设计测试用例；
- 检测主要执行通路是否按设计说明设定运行；
- 方法：控制流测试、数据流测试、程序变异测试等；
- 静态测试实现白盒（人工检查代码逻辑）也属白盒范畴；
- 最常用技术是**逻辑覆盖**，覆盖标准：语句覆盖、判定覆盖、条件覆盖、条件/判定覆盖、条件组合覆盖、修正的条件/判定覆盖、路径覆盖。

#### 黑盒测试（功能测试）
- 把程序看作不透明黑盒，不考虑内部结构与算法，根据 SRS 设计测试用例，检查功能是否按规范运行；
- 用例设计方法：等价类划分、边界值分析、判定表、因果图、状态图、随机测试、猜错法、正交试验法。

## 3. 测试类型（GB/T 15532）

| 测试类型 | 对象/依据 | 目的与要点 |
|----------|-----------|-----------|
| 单元测试 | 可独立编译/汇编的程序模块、构件或 OO 类 | 依据详细设计说明书；从模块接口、局部数据结构、重要执行通路、出错处理通路、边界条件测试 |
| 集成测试 | 组装后的模块 | 依据概要设计文档；验证结构组装的正确性与接口问题；白盒+黑盒结合；前提：模块均通过单元测试 |
| 确认测试 | 软件 | 验证功能、性能和其他特性与用户需求一致 |
| 系统测试 | 完整、集成的计算机系统 | 真实系统环境下检测；内容含功能、性能、健壮性、安装/反安装、UI、压力、可靠性及安全性测试；重点功能+性能；需多轮回归测试；结束标志：覆盖率达标且缺陷全部归零 |
| 配置项测试 | 软件配置项 | 依据 SRS（含接口需求规格说明）；检验配置项与 SRS 一致性；前提：已通过单元+集成测试 |
| 回归测试 | 变更后的软件 | 测试变更部分的正确性、对变更需求的符合性、原有功能性能不受损害 |

## 4. 面向对象的测试

目标与传统一致，但策略不同：
- **测试焦点从模块移向类**；
- **测试视角扩大到分析与设计模型**；
- OO 三大特征（封装、继承、多态）带来测试困难：
  - 封装性：需考虑信息隐蔽对测试的影响、对象状态与类的测试序列；
  - 继承性：需考虑继承对测试充分性的影响及误用错误；
  - 多态性：需考虑动态绑定对测试充分性的影响、抽象类测试及误用影响。

## 5. 软件调试（排错）

- 测试成功标志是发现了错误；调试根据错误迹象确定原因和准确位置并改正；
- 常用策略：**蛮力法、回溯法、原因排除法**。

## 6. 测试过程与准入条件

通用测试准入条件（建议）：
- 相关文档（SRS、设计文档）已评审并受控；
- 待测对象已通过上一级测试（集成测试前通过单元测试；配置项测试前通过单元+集成测试）；
- 测试环境已就绪并受控；
- 缺陷管理机制已建立。

测试结束标志：
- 已满足测试目标规定的需求覆盖率；
- 所发现的缺陷已全部归零（或按约定达到可接受水平并评审通过）。

## 7. 测试检查单

- [ ] 是否制定了测试计划并覆盖需求跟踪矩阵？
- [ ] 单元测试是否覆盖模块接口、边界、出错处理？
- [ ] 集成测试是否验证接口正确性？
- [ ] 系统测试是否含功能、性能、压力、安全性、UI？
- [ ] 需求变更后是否执行回归测试？
- [ ] 缺陷是否全部记录、归零并评审？
- [ ] 是否满足各级测试的准入条件？
