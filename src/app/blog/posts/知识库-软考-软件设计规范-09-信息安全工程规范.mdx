# 09 信息安全工程规范

> 来源：《系统集成项目管理工程师教程（第3版）》第8章

## 1. 信息安全管理

### 1.1 保障要求（安全管理建设5项原则）
1. 总体策划，确保安全的总体目标和所遵循的原则；
2. 建立相关组织机构，明确责任部门，落实具体实施部门；
3. 做好信息资产分类与控制（员工安全、物理环境安全、业务连续性管理）；
4. 使用技术方法解决通信与操作安全、访问控制、系统开发与维护；
5. 实施安全检查与审计，评估安全措施执行情况和实施效果。

### 1.2 三大基础保障
网络安全与管理至少成立**一个安全运行组织**、制定**一套安全管理制度**、建立**一个应急响应机制**：
- 安全运行组织：主管领导（核心）、信息中心（实体）、业务应用部门（使用者）；
- 安全管理制度：明确安全职责、制定细则，做到**多人负责、任期有限、职责分离**；
- 应急响应机制：由管理人员和技术人员共同参与，提出应急计划与程序，提供技术支持、通告、分析及培训。

### 1.3 管理内容（参考 ISO/IEC 270 系列）
| 控制域 | 主要内容 |
|--------|----------|
| 组织控制 | 信息安全策略、角色与职责、职责分离、管理职责、威胁情报、身份管理、访问控制、信息分类与标签、信息传输、供应商信息安全、ICT供应链安全、云服务安全、信息安全事件管理、业务连续性、法律合规、知识产权、隐私保护、独立审查 |
| 人员控制 | 筛选与背景调查、劳动合同/协议、安全意识教育与培训、惩戒程序、离职变更后责任、保密协议、远程工作、安全事件报告机制 |
| 物理控制 | 物理安全边界、入口控制、安全监控、防物理与环境威胁、设备选址保护、存储介质管理、布线安全、设备维护与安全处置 |
| 技术控制 | 终端设备保护、特殊访问权限管理、访问限制、源代码保护、身份验证、容量管理、恶意代码防范、技术漏洞管理、配置管理、信息删除、数据屏蔽、数据泄露预防、信息备份、日志、监控、时钟同步、网络安全与隔离、密码使用、**安全开发生命周期**、安全编码、安全测试、环境分离、变更管理 |

> 与软件开发直接相关：**开发生命周期安全、安全架构与工程原理、安全编码、安全测试、开发/测试/生产环境分离**。

## 2. 信息安全体系与等级保护

### 2.1 管理体系
对信息系统生存周期全过程实施符合安全等级责任要求的管理：
落实安全管理机构与人员 → 制定安全规划 → 开发安全策略 → 实施风险管理 → 制订业务持续性与灾难恢复计划 → 选择实施安全措施 → 保证配置/变更安全 → 安全审计 → 监控检查处理安全事件 → 安全意识教育 → 人员安全管理。

安全管理机构建设参考步骤：配备安全管理人员 → 建立安全职能部门 → 成立安全领导小组 → 主要负责人出任领导 → 建立保密管理部门。

### 2.2 网络安全等级保护（2.0）
- 《信息安全等级保护管理办法》将信息系统安全保护等级分为 **5 级**；
- 依据标准：《信息安全技术 网络安全等级保护基本要求》GB/T 22239 等；
- 等级保护 2.0 核心：将风险评估、安全监测、通报预警、应急处置、检测评估等纳入制度；覆盖网络基础设施、信息系统、网站、数据资源、云计算、物联网、移动互联网、工控系统、公众服务平台、智能设备等。

## 3. 信息安全系统

### 3.1 安全机制
实现安全保护所采用的技术手段（加密、认证、访问控制、审计等）。

### 3.2 安全服务
OSI 开放系统互联安全体系包括 **5 类安全服务**：鉴别、访问控制、数据机密性、数据完整性和抗抵赖性。

### 3.3 信息安全体系架构模型（WPDRC）
WPDRC 模型包括多个环节与要素，用于描述信息系统的安全防护体系（防护、检测、响应、恢复、监控等能力协同）。

## 4. 安全工程体系架构

### 4.1 安全工程基础
将安全工程融入系统工程的开发、运行与维护过程，保证安全需求得到识别、实现与验证。

### 4.2 ISSE（信息系统安全工程）过程
将安全需求转化为安全设计并落实到系统中，覆盖：识别安全需求 → 设计安全方案 → 实现 → 测试验证 → 运维保障。

### 4.3 ISSE-CMM（信息安全系统工程能力成熟度模型）
用成熟度模型衡量组织安全工程能力，从"执行已定义过程、使用数据管理过程、量化确定过程能力"等公共特性定义成熟度等级，指导组织持续改进安全工程能力。

## 5. 安全开发检查单

- [ ] 是否制定并发布了信息安全策略并定期评审？
- [ ] 是否成立安全管理组织并明确职责（多人负责、职责分离）？
- [ ] 是否建立应急响应机制与业务连续性/灾难恢复计划？
- [ ] 开发、测试、生产环境是否分离并分别防护？
- [ ] 是否落实安全编码、安全测试、代码安全审查？
- [ ] 是否对源代码、开发工具、软件库的访问进行管控？
- [ ] 是否落实身份验证、访问控制、数据屏蔽与脱敏？
- [ ] 是否符合等级保护要求（定级、备案、测评、整改）？
- [ ] 是否覆盖供应商与 ICT 供应链信息安全？
- [ ] 是否建立日志、监控、漏洞管理机制？
