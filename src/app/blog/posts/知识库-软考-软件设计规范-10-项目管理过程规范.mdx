# 10 项目管理过程规范

> 来源：《系统集成项目管理工程师教程（第3版）》第9~14章

## 1. 项目与项目管理基础

### 1.1 项目基本要素
- **项目**：为创造独特的产品、服务或结果而进行的临时性工作；
- **项目管理**：将知识、技能、工具与技术应用于项目活动，以满足项目要求；
- **项目成功的标准**：在时间、成本、范围与质量约束内，满足干系人期望并创造价值；
- 项目、项目集、项目组合与运营管理的关系：项目组合（选择/优先级）→ 项目集（协调一组相关项目）→ 项目 → 运营；
- **项目运行环境与组织系统**：影响项目执行的内部/外部因素（组织文化、治理、组织结构等）；
- **项目管理和产品管理**：产品生命周期与项目生命周期相互关联。

### 1.2 项目生命周期与项目阶段
- 定义：项目从开始到结束所经历的一系列阶段（一组有逻辑关系的活动集合），以可交付成果完成为结束标志；
- 生命周期类型：预测型（瀑布）、迭代/增量、适应型（敏捷）、混合型；
- 阶段通常以里程碑为节点，阶段末评审（阶段关口）决定是否进入下一阶段。

### 1.3 项目立项管理
```
项目建议与立项申请 → 项目可行性研究（技术/经济/社会法律/运行环境） → 项目评估与决策 → 立项批准
```

### 1.4 项目经理的角色
对项目全过程经营负责，正式权力由项目章程取得；在变更中：响应需求、评估影响与应对方案、将需求转化为资源要求供授权人决策、依据评审结果调整基准并监控实施。

## 2. 项目管理五大过程组

| 过程组 | 作用 |
|--------|------|
| 启动过程组 | 定义新项目或现有项目新阶段，授权项目/阶段开始 |
| 规划过程组 | 明确项目范围、优化目标，为实现目标制订行动计划 |
| 执行过程组 | 完成项目管理计划中确定的工作，满足项目要求 |
| 监控过程组 | 跟踪、审查、调整项目进展与绩效，识别变更并启动相应变更 |
| 收尾过程组 | 正式完成或结束项目、阶段或合同 |

- 一个过程组的输出通常成为另一个过程组的输入，或成为可交付成果；
- 各过程组在项目阶段中按需重复开展，直到达到该阶段完工标准。

## 3. 项目管理 12 条原则

1. 勤勉、尊重和关心他人（诚信、关心、可信、合规）；
2. 营造协作的项目团队环境（团队共识、组织结构、过程）；
3. 促进干系人有效参与；
4. 聚焦于价值；
5. 识别、评估和响应系统交互；
6. 展现领导力行为；
7. 根据环境进行裁剪；
8. 将质量融入过程和成果中；
9. 驾驭复杂性；
10. 优化风险应对；
11. 拥抱适应性和韧性；
12. 为实现目标而驱动变革。

## 4. 十大知识领域

| 知识领域 | 含义 |
|----------|------|
| 项目整合管理 | 识别、定义、组合、统一和协调各过程组的各个过程和活动 |
| 项目范围管理 | 确保项目做且只做所需的全部工作以成功完成项目 |
| 项目进度管理 | 管理项目按时完成所需的各个过程 |
| 项目成本管理 | 使项目在批准预算内完成：规划、估算、预算、融资、筹资、管理、控制 |
| 项目质量管理 | 把组织质量政策应用于规划、管理、控制项目和产品质量 |
| 项目资源管理 | 识别、获取和管理所需资源 |
| 项目沟通管理 | 确保项目信息及时恰当地规划、收集、生成、发布、存储、检索、管理、控制、监督、处置 |
| 项目风险管理 | 规划风险、识别风险、风险分析、规划应对、实施应对、监督风险 |
| 项目采购管理 | 从团队外部采购或获取所需产品、服务或成果 |
| 项目干系人管理 | 识别影响或受项目影响的人员团队组织，分析期望与影响，制定策略调动参与 |

## 6. 各过程组重点工作（落地要点）

### 6.1 启动
- 制定项目章程（授权）；
- 识别干系人；
- 召开项目启动会议；
- 关注价值和目标。

### 6.2 规划（核心子过程）
- 范围：规划范围管理、收集需求、定义范围、创建 WBS；
- 进度：规划进度管理、定义活动、排列活动顺序、估算持续时间、制订进度计划；
- 成本：规划成本管理、估算成本、制定预算；
- 质量：规划质量管理；
- 资源：规划资源管理、估算活动资源；
- 沟通：规划沟通管理；
- 风险：规划风险管理、识别风险、定性/定量分析、规划风险应对；
- 采购：规划采购管理（含合同类型与内容）；
- 干系人：规划干系人参与。

### 6.3 执行
指导与管理项目工作、管理项目知识、管理质量、获取资源、建设团队、管理团队、管理沟通、实施风险应对、实施采购、管理干系人参与。

### 6.4 监控
监控项目工作、实施整体变更控制、控制质量、确认范围、控制范围、控制进度、控制成本、控制资源、监督沟通、监督风险、控制采购、监督干系人参与。

### 6.5 收尾
- **结束项目或阶段**：结束项目/阶段过程，审查以往阶段文件、确认范围产生的验收文件及合同，确保达到全部项目要求后才正式结束；
- **项目验收**：验收测试（按合同约定的系统环境，确保功能与非功能满足需求）、试运行、终验（最终验收标志项目结束与售后开始；双方撰写验收报告并提请双方主管认可）；
- **项目移交**：依据立项文件/合同识别并整理向客户方移交的成果；依据上线发布/运维移交规定整理向运维团队移交的成果；**需同时移交过程资产，不能只交最终成果**；
- **项目总结**（管理/行政收尾）：收集项目记录、分析成败、收集教训、存档供组织使用。总结内容：项目目标、技术绩效、成本绩效、进度计划绩效、项目沟通、识别与解决问题、意见和改进建议。总结文件须经全体确认后存入组织过程资产。

## 7. 项目文件与组织过程资产

- 项目文件：风险登记册、责任分配矩阵、变更日志等；
- 组织过程资产：可复用代码、组件、用例、度量数据、优秀实践、经验教训、风险问题解决经验等，供未来项目复用。

- [ ] 是否建立了沟通与汇报机制？
