# 12 信息与文档管理规范

> 来源：《系统集成项目管理工程师教程（第3版）》第15章

## 1. 概念

- **信息（文档）**：某种数据媒体和其中所记录的数据，描述人工可读的东西，具有永久性，可由人或机器阅读；
- **信息和文档管理**：对信息及文档进行收集、整理、处理、储存、传递与应用等一系列工作的总称；
- 目的：为项目管理人员及决策者提供所需的各种信息和数据，支持统计分析处理。

## 2. 信息系统信息的分类

| 类别 | 内容（示例） |
|------|--------------|
| 用户信息 | 个人/组织基本信息、账号信息、信用信息、行为数据信息 |
| 业务信息 | 按行业（金融、能源、交通）；按业务特点（研发、生产、维护） |
| 经营管理信息 | 市场营销信息、经营信息、财务信息、并购/融资信息、产品信息、运营/交付信息 |
| 系统运行信息 | 系统配置信息、监测数据、备份数据、日志数据、安全漏洞信息 |

## 3. 信息系统文档分类

对信息系统开发项目，文档一般分为：

### 3.1 开发文档（描述开发过程本身）
- 可行性研究报告和项目任务书；
- 需求规格说明；
- 功能规格说明；
- 设计规格说明（程序和数据规格说明）；
- 开发计划；
- 软件集成和测试计划；
- 质量保证计划；
- 安全和测试信息。

### 3.2 产品文档（描述开发过程的产物）
- 培训手册；
- 参考手册和用户指南；
- 软件支持手册；
- 产品手册和广告。

### 3.3 管理文档（记录项目管理信息）
- 各阶段进度及进度变更记录；
- 软件变更情况记录；
- 开发团队职责定义；
- 项目计划、项目阶段报告；
- 配置管理计划。

## 4. 文档质量分级

| 级别 | 名称 | 适用场景 | 内容要求 |
|------|------|----------|----------|
| 1级 | 最低限度文档 | 开发量 \< 1 人·月，开发者自用程序 | 程序清单、开发记录、测试数据、程序简介 |
| 2级 | 内部文档 | 未与其他用户共享资源的专用程序 | 1级 + 程序清单内足够注释帮助安装使用 |
| 3级 | 工作文档 | 同一单位若干人联合开发，或可被其他单位使用 | — |
| 4级 | 正式文档 | 正式发行、普遍使用的软件产品；关键性程序或重复管理应用性质程序 | 遵守 GB/T 8567《计算机软件文档编制规范》 |

## 5. 信息（文档）管理规则和方法

### 5.1 文档书写规范
无论文本、图形、表格，都应遵循统一书写规范：符号使用、图标含义、注释行使用、注明文档书写人及书写日期等。例如程序开始用统一格式包含程序名称、程序功能、调用关系、程序设计人等信息。

### 5.2 图表编号规则
对开发中使用的图表进行有规则编号，方便查找。编号采用**分类结构**：
- 第1位：生命周期法各阶段；
- 第2位：各阶段的文档；
- 第3、4位：文档内容；
- 第5、6位：流水码。

> 通过编号可判断图表出自哪一阶段、哪个文档、文档哪部分内容及第几张图表。

### 5.3 文档目录编写标准
文档目录包含：文档编号、文档名称、格式或载体、份数、每份页数或件数、存储地点、存档时间、保管人等。

- 文档编号：分类结构，采用类似图表编号规则；
- 文档名称：书写完整规范；
- 格式或载体：原始单据/报表、磁盘文件、磁盘文件打印件、大型图表、重要文件原件、光盘存档等。

### 5.4 文档管理制度
- 建立文档相关规范（书写规范、图表编号规则、文档目录编写标准）；
- 文档借阅记录登记制度；
- 文档使用权限控制规则。

## 6. 软件开发项目文档清单建议

| 阶段 | 应产出文档 |
|------|-----------|
| 立项 | 可行性研究报告、项目任务书、立项申请 |
| 需求 | 需求规格说明书（SRS）、需求跟踪矩阵、用户需求文档 |
| 设计 | 概要设计说明书、详细设计说明书、数据库设计、接口设计、架构设计文档 |
| 实现 | 开发计划、源代码、构建说明、配置管理计划 |
| 测试 | 测试计划、测试用例、测试报告、缺陷记录 |
| 部署交付 | 部署说明、用户手册、培训手册、参考手册、验收报告 |
| 管理 | 项目计划、项目阶段报告、进度/成本记录、变更日志、项目总结 |

## 7. 文档管理检查单

- [ ] 是否对文档进行分类（开发/产品/管理）并明确责任人？
- [ ] 是否遵循统一的文档书写规范？
- [ ] 图表与文档是否按分类结构编号？
- [ ] 是否建立文档目录与存档记录？
- [ ] 是否明确文档借阅与权限控制规则？
- [ ] 是否根据项目规模确定文档质量等级？
- [ ] 关键文档（需求、设计、测试、发布）是否纳入配置管理？
