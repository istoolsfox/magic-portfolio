# 13 质量与过程改进规范

> 来源：《系统集成项目管理工程师教程（第3版）》第5章、第9章、第12~13章

## 1. 质量管理概述

### 1.1 质量管理原则
- 项目管理 12 原则之一：**将质量融入过程和成果中**（质量内建，而非事后检查）；
- 项目质量管理：把组织的质量政策应用于规划、管理、控制项目和产品质量，以满足干系人期望；
- 质量管理是所有人的共同职责（项目经理、团队、发起人、管理层、客户）；敏捷项目中全程由全体成员执行，传统项目中通常是特定团队成员职责。

### 1.2 三大质量管理过程
| 过程 | 过程组 | 作用 |
|------|--------|------|
| 规划质量管理 | 规划 | 识别项目及其可交付成果的质量要求和标准，并书面描述如何证明符合要求 |
| 管理质量 | 执行 | 把质量政策用于项目，将质量管理计划转化为可执行的质量活动；提高实现质量目标可能性，识别无效过程与质量低劣原因，促进过程改进 |
| 控制质量 | 监控 | 监测并记录质量活动执行结果，评估绩效并推荐必要变更 |

## 2. 质量管理计划与质量测量指标

- **质量管理计划**：定义项目与产品质量的可接受水平，描述如何确保可交付成果和过程达到该水平；描述不合格产品处理方式及所需纠正措施；
- **质量测量指标**：可量化的质量衡量标准（如缺陷率、MTBF、响应时间、覆盖率等）；
- 管理质量过程把质量标准与测量指标转化为**测试与评估文件**，供控制质量过程使用。

## 3. 管理质量主要工具与技术

| 类别 | 工具 |
|------|------|
| 数据收集 | 核对单（结构化核实一系列步骤是否执行） |
| 数据分析 | 备选方案分析、文件分析、过程分析（把过程分解成环节找出最值得改进处）、根本原因分析 |
| 决策 | 多标准决策分析（决策矩阵） |
| 数据表现 | 亲和图、因果图（鱼刺图/石川图，分析导致某一结果的一系列原因）、流程图、直方图、矩阵图、散点图 |
| 审计 | 质量审计（识别无效过程与改进机会，独立评价是否遵从规则标准） |
| 其他 | 面向X的设计、问题解决、质量改进方法 |

## 4. 控制质量主要工具与技术

| 类别 | 工具 |
|------|------|
| 数据收集 | 核对单、核查表、统计抽样（从目标总体中选取部分样本用于检查）、问卷调查 |
| 数据分析 | 绩效审查、根本原因分析 |
| 数据表现 | 因果图（识别缺陷与错误可能造成的结果）、控制图（确定过程是否稳定、是否具有可预测绩效；含规格上限/下限与控制界限）、直方图、散点图 |
| 测试与产品检查 | 测试、产品检查（验收审查） |

> 控制图用于确定过程是否稳定或具有可预测绩效，最常用于跟踪。

## 5. 质量成本与质量改进方法

- 质量成本：一致性成本（预防、评估）与非一致性成本（内部失败、外部失败）；合理权衡以降低总成本；
- 持续改进方法：PDCA（计划-执行-检查-处理）循环；通过过程分析、根本原因分析、质量审计发现改进点；
- 经验教训登记册：记录质量经验教训，供后期与未来项目使用。

## 6. 软件质量特性

软件非功能需求（质量属性）应纳入需求与测试范围：
易用性、可维护性、效率（性能）、可靠性、安全性、可移植性、可测试性等；
质量功能部署（QFD）将需求分类为常规需求、期望需求、意外需求，提升满意度（详见 02 需求工程规范）。

## 7. 软件过程能力成熟度

### 7.1 概念
- **软件过程能力**：组织基于软件过程、技术、资源和人员能力达成业务目标的综合能力（治理能力、开发与交付能力、管理与支持能力、组织管理能力）；
- **成熟度**：组织在提升软件产品开发/服务能力过程中，各发展阶段的软件能力成熟度；
- 依据标准：T/CESA 1019《软件过程能力成熟度模型》（CSM）。

### 7.2 CSM 模型结构
由 **4 个能力域、20 个能力子域、161 个能力要求**组成：
| 能力域 | 能力子域 |
|--------|----------|
| 治理 | 战略与治理、目标管理 |
| 开发与交付 | 需求、设计、开发、测试、部署、服务、开源应用 |
| 管理与支持 | 项目策划、项目监控、项目结项、质量保证、风险管理、配置管理、供应商管理 |
| 组织管理 | 过程管理、人员能力管理、组织资源管理、过程能力管理 |

### 7.3 成熟度等级（5级）
| 等级 | 结果特征 | 行为特征 |
|------|----------|----------|
| 1级：初始级 | 能实现初步的软件交付和项目管理活动；过程和结果具有不确定性 | 项目没有完整管理规范，依赖个人主动性和能力 |
| 2级：项目规范级 | 项目基本可按计划实现预期结果 | 依据选择和定义的管理规范执行基础过程；组织按规范提供支持保障 |
| 3级：组织改进级 | 组织范围内稳定实现预期项目目标 | 在2级基础上持续改进；建立并改进组织标准过程和过程资产；项目贡献过程资产 |
| 4级：量化提升级 | 组织范围内量化管理和实现预期目标 | 使用统计分析技术管理；建立过程绩效基线与模型；分析关键过程能力、预测结果 |
| 5级：创新引领级 | 通过创新实现业务目标持续提升、引领行业 | 在4级基础上优化革新；创新提升竞争力；经验作为行业最佳案例推广 |

> 高等级是在低等级充分实施的基础上进行的。

## 8. 质量与过程改进检查单

- [ ] 是否制定质量管理计划与质量测量指标？
- [ ] 是否定义质量成本并做平衡？
- [ ] 是否将质量活动融入开发过程（而非事后检查）？
- [ ] 是否开展质量审计与根本原因分析？
- [ ] 是否使用控制图、因果图等工具监控质量？
- [ ] 是否将质量经验教训纳入登记册？
- [ ] 是否用成熟度模型评估并持续改进组织过程能力？
- [ ] 质量改进是否形成闭环（PDCA）？
