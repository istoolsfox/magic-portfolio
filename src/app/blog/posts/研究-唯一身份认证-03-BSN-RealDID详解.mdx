# 03 BSN RealDID 详解——中国的链上唯一身份路径

> 一句话结论：RealDID = 国家级"身份唯一性来源"（公安部一所 CTID）+ "凭证防篡改层"（BSN 区块链服务网络）的组合。实名锚定与唯一性由政府身份库保证，链只负责让凭证可验证、隐私可控、不依赖某一家公司。这是在中国做"链上唯一身份"唯一合规的现实路径。

## 一、三层结构：先分清 BSN、CTID、RealDID

### 1. BSN（区块链服务网络）——"链的互联网"

- 2018 年立项、2020-04 正式开通商用，由国家信息中心牵头，中国移动、中国银联等参与 [实锤，官方公开资料]。
- 定位：不是一条链，而是**跨云跨链的基础设施网络**——像"互联网"一样把不同区块链（联盟链、开放联盟链）统一接入，开发者按接口调用，不用自己搭链。
- 中国"禁币不禁链"政策的旗舰工程：全部为许可链/开放联盟链，无加密货币。

### 2. CTID（网络可信身份认证平台）——"唯一性来源"

- 运营方：**公安部第一研究所**（居民身份证的研制与管理机构之一）。
- 机制：基于居民身份证，签发"网证"式的网络可信身份凭证——把"你是谁"的唯一性锚定在公安人口库上，网络服务方验证时**拿不到你的完整身份证信息**，只能拿到"核验通过/不通过"的结果。
- 关键点：**唯一性在这里解决**（一人一号，几十年户籍制度背书），不在链上解决。

### 3. RealDID（BSN 实名 DID 服务）——两者融合

- 2023-12 上线，由 BSN 发展联盟、CTID 数字身份链平台运营方、中国移动设计院联合发布 [二手，行业报道]。
- 给每个用户生成**分布式数字身份标识（DID）**：形如 `did:bsn:xxxx` 的字符串 + 一对本地私钥。
- 用户体验：注册/登录网站时用 DID 地址+私钥（扫码/签名），**不再暴露手机号和密码**；但监管侧保留"实名可追溯"（DID 背后锚定 CTID 实名属性）。
- 设计哲学一句话：**对商家匿名，对监管实名**。

## 二、技术拆解：一个 DID 凭证的生死流程

1. **签发**：用户到接入 CTID 的入口实名认证（刷脸+身份证）→ CTID 数字身份链为该用户签发 DID 文档（含公钥、验证方法、实名属性的哈希指针）。
2. **持有**：私钥在用户端（手机/密钥库），平台不经手。
3. **出示**：用户登录第三方应用时，用自己的私钥对挑战签名 → 应用验证签名 + 查 DID 文档状态（是否有效、是否注销）。
4. **验证**：验证方通过 BSN 开放接口核验，无需对接公安系统，也拿不到明文身份。
5. **轮换**：私钥丢了可走实名通道补办换绑（密钥可换、身份不换）——这是 docs/04"密钥当身份证"思想的国家级实现。

DID 的标准格式来自 W3C DID Core（docs/04 有标准清单）。

## 三、政策时间线

| 时间 | 事件 |
|---|---|
| 2020-04 | BSN 正式开通 |
| 2023-12 | RealDID 上线（BSN + CTID） |
| 2024-02 | 国家信息中心 × 公安部一所签合作协议，推进分布式数字身份研究应用 [二手] |
| 2025-10 | 发改委专家文章：RealDID 定位为"可信数据空间"的基础设施 [二手] |
| **2026-06** | **网信办发布《促进分布式数字身份互通互认应用规定（征求意见稿）》**：定义分布式数字身份="基于区块链等分布式技术、支持用户自主管理身份信息，由标识符、密钥、可验证凭证、可验证声明组成" [实锤，官方征求意见稿] |

2026-06 的征求意见稿是本轮最重要的信号：**DID 从"某个平台的服务"上升为"国家要推动互通互认的基础设施"**——类似当年"身份证电子化"的路径。

## 四、与 World ID 对照（两条哲学相反的路）

| 维度 | BSN RealDID | World ID |
|---|---|---|
| 唯一性来源 | 公安人口库（政府签发） | 虹膜查重（公司硬件采集） |
| 隐私哲学 | 对商家匿名、对监管实名 | 对所有人匿名（ZK），无实名锚定 |
| 信任根 | 国家 | 一家美国公司 + 开源协议 |
| 硬件要求 | 低（现有实名入口即可） | 高（Orb 专用设备） |
| 跨国可用性 | 出不了国门 | 主权国家多不接纳 |
| 合规性（中国） | ✅ 唯一正路 | ❌ 不可用 |

两者其实互补：RealDID 解决"唯一性+实名锚定"，World ID 路线贡献了"ZK 凭证+硬件查重"的工程范式。

## 五、对个人的现实意义

1. 中国任何"链上身份"创业/研究都要在这套体系之上做应用层，绕开它=不合规。
2. 未来政务登录、金融开户、互联网实名可能逐步迁移到 DID 形态（征求意见稿的互通互认方向）。
3. 研究价值：它是"政府当唯一性背书 + 区块链当凭证层"这个理论模型的最大规模实践样本。
