# 02 · 调研：空洞骑士 Modding 生态

> 调研日期：2026-09-23。目的：确认「AI 陪玩」需要的底层能力（读状态/发指令/多玩家实体/跨平台）在空洞骑士上是否都有技术底座。
> 置信度标注：[实锤]=直接读过一手页面；[二手]=搜索结果转述、有链接未细读；【待核实】=凭记忆或未验证。

## 结论（先看这个）

1. **该有的能力全都有先例，不需要发明底层技术**：
   - 读游戏状态 → LiveSplit 自动分段器读内存多年、DebugMod 全套调试功能；
   - 操控/改状态 → DebugMod（传送、无敌、noclip）、ItemChanger；
   - 同屏第二个玩家 → **HKMP 多人联机 mod**，甚至有独立服务器；
   - mod 分发管理 → Lumafly/Needlelight 一键装 300+ mod。
2. **技术路线清晰**：空洞骑士是 Unity 游戏、Mono 运行时（非 IL2CPP）→ 可以用 C# 注入 mod，游戏内嵌 WebSocket/HTTP 服务给外部 AI 当接口。
3. **macOS（Apple Silicon）大概率可行**：HK 的 Mac 版是 Mono x64，BepInEx 有 macOS 版，HKMP 独立服务器明确支持 Mac——但「Mac 上跑 mod 的稳定性」没有足够一手证据，**列为 M0 spike 的第一验证项**，备选方案是 Windows 机器或虚拟机。
4. 《空洞骑士：丝之歌》（Silksong）modding 已启动（BepInEx 系，DebugMod 已有移植版），但生态早期；**本项目先做 HK1，架构上留出移植空间**。

## 1. 游戏本体与技术栈

| 事实 | 内容 | 置信度 |
|------|------|--------|
| 开发商 | Team Cherry，单机买断制，无反作弊、无在线验证强度 → mod 零封号风险 | [二手，常识+搜索未反证] |
| 引擎/运行时 | Unity，**Mono 运行时（非 IL2CPP）** → C# mod 注入可行 | [实锤：hk-modding 生态全部基于 C# 注入这一事实本身] |
| 当前版本 | 1.5.x（HKMP README 明确推荐「Hollow Knight 1.5」的 mod） | [实锤] |
| 平台 | Steam/GOG/WeGame 等，含 Windows/macOS/Linux 版 | [二手] |
| 续作 | 《空洞骑士：丝之歌》（Silksong）已发售，2025-09 前后 | 【待核实：具体日期】 |

**关键点**：HK1 是 Unity Mono 意味着 mod 就是普通 C# DLL，能直接引用游戏的 `Assembly-CSharp.dll`，hook 任意游戏类（玩家控制器、血量管理、场景管理等）。这是比「视觉+按键」强一个量级的接口基础。

## 2. Modding 框架与工具链

| 组件 | 说明 | 置信度 |
|------|------|--------|
| **Hollow Knight Modding API**（github.com/hk-modding/api） | HK1 生态的主加载器/API，基于 MonoMod（运行时 hook），MIT，337 stars，文档站 hk-modding.github.io/api/；HKMP 即基于它构建 | [实锤：读过仓库 README] |
| **BepInEx 5** | 通用 Unity Mono 注入框架，HK 社区现代方案的一部分；丝之歌生态的标准加载器（Thunderstore 有 BepInExPack Silksong） | [二手：Nexus/搜索转述] |
| **Lumafly**（TheMulhima/Lumafly，原 Scarab+） | 现役 HK mod 管理器，300+ mods 一键安装；Scarab（fifty-six/Scarab）是其前身 | [二手：官方页+搜索] |
| **Needlelight**（Aarav2709/Needlelight） | 基于 Lumafly 的新一代管理器，同时支持 HK 与丝之歌，自动装 BepInEx，可带/不带 mod 启动 | [二手：Steam 社区帖] |
| 社区入口 | hk-modding.org（链接汇总）、Hollow Knight Modding Discord、文档站 | [二手] |

**两条框架线的关系**【待核实细节】：HK1 大量 mod（含 HKMP）仍挂在 Modding API 上；丝之歌走 BepInEx。我们的 mod 若想两边通吃，应按 BepInEx + Modding API 兼容层设计，M0 时确认。

## 3. 对本项目最有价值的四个 mod

### 3.1 DebugMod —— 「AI 能操控游戏」的可行性证明
- 仓库：github.com/fifty-six/HollowKnight.DebugMod [实锤]
- 能力：游戏内可切换 UI，提供无敌、noclip（穿墙）等作弊与调试功能 [实锤]；传送、存档状态等调试能力 [二手]
- 丝之歌已有移植版（Thunderstore / Nexus，HK-Speedrunning 维护，F2 唤出）[二手]
- **意义**：它证明外部代码可以随意读写玩家状态、位置、碰撞——AI 演示形态（形态 B）的所有底层动作它都有原型，我们要做的是把这些能力包成「语义动作」给 LLM 调用。

### 3.2 HKMP —— 「同屏第二玩家」的技术底座
- 仓库：github.com/Extremelyd1/HKMP，LGPL-2.1，558 stars，736 commits [实锤]
- 功能：主机/客户端联机（LAN 或互联网）、PVP（可逐项配置各类法术/技能伤害）、皮肤系统、队伍系统、头顶名牌、地图图标共享、kick/ban 管理命令 [实锤]
- 独立服务器：**Windows/Linux/Mac 均支持**（Linux/Mac 需 Mono），社区有 Docker 镜像 [实锤]
- 依赖：基于 hk-modding/api 构建，Lumafly 可一键安装，适配 HK 1.5 [实锤]
- **插件系统**：HKMP 有 addon（插件）体系，可注册服务端/客户端扩展、自定义网络包【待核实：细节凭记忆，需读仓库 docs/ 确认】
- **没有现成的 bot API** [实锤：README 无此内容] → AI 作为「第二玩家」需要我们写 HKMP addon（把 AI 实体的输入/状态接进 HKMP 的同步协议），这是形态 C 的核心工程量。

### 3.3 LiveSplit 自动分段器 —— 「读状态」的多年先例
- 速通社区用它实时读内存做自动计时分段（场景切换、boss 血量、死亡检测）【待核实：具体仓库/实现，本次未深挖】
- **意义**：陪玩需要的感知信号（进场景、开 boss、玩家死亡、受伤）全是速通社区玩剩下的，方案有参照。

### 3.4 ItemChanger / Randomizer / 地图 mod（一句话带过）
- 改物品/随机化/地图可视化类 mod 生态成熟 [二手]，证明「改游戏状态」层完全可行；陪玩做「彩蛋投放」「进度追踪」时可以借力。

## 4. 平台问题：macOS（Apple Silicon）可行性

| 事实 | 内容 | 置信度 |
|------|------|--------|
| 游戏 | HK Mac 版为 x64 Mono 构建，Apple Silicon 经 Rosetta 2 运行 | [二手] |
| BepInEx | 官方提供 macOS x64 版本，Mono 游戏可用 | [二手] |
| HKMP | 独立服务器明确支持 Mac（Mono） | [实锤] |
| 风险 | HK mod 社区主流目标是 Windows；个别 mod 在 Mac 不稳；Rosetta 下性能待测 | [二手+常识] |

**决策建议**：M0 spike 直接在本机（macOS arm64）验证「游戏+Lumafly+DebugMod+自写 mod」全链路；若不稳，备选 ①Windows 物理机/虚拟机（Parallels/CrossOver，注意 Mono 注入在转译层的兼容性）②云 Windows。**mod 的 WebSocket 服务+bridge 跑在本机 mac 上没有平台问题**（纯网络通信），只有「游戏本体+mod 注入」这一段受平台影响。

## 5. 待验证清单（汇总，M0/M1 逐项销账）

1. 本机 macOS arm64 + Rosetta 跑 HK1 + Lumafly + DebugMod 的稳定性（帧率、崩溃率）
2. Modding API 与 BepInEx 在 HK1 上的共存/选型结论
3. HKMP addon API 的真实形态（读仓库 docs/ 与示例代码）
4. Unity Mono 下「向玩家注入虚拟输入」的推荐姿势（hook `HeroController` 输入 vs 模拟按键事件）【类名待核实】
5. mod 内嵌 WebSocket 服务的性能（.tick 频率、与游戏主线程的关系）
6. 游戏 1.5.x 具体小版本号与各 mod 兼容矩阵
