# AI 画的界面一眼假？有人把设计师的品味拆成了规则：Stageshow 实测

> 你让 AI 给产品落地页配一张"产品界面图"。它交出来的东西：紫色渐变打底，几颗发光的星星，界面里全是灰色横条，中间飘一个彩色方块装个字母。你发给别人看，对方回一句"一看就是 AI 画的"。这类图有个统一的病，叫 stock AI 味：模板化、没信息、谁画出来都长一样。病根不在 AI 不会画，而在没人告诉它"假界面为什么假"。

## 一、结论先行

GitHub 上有个专治这个病的 Agent 技能，叫 Stageshow（作者 Benji Taylor，仓库 benjitaylor/skills，2026-11-02 实查 561 星）。一句话概括它干的事：**让 AI 画出"看起来像真产品"的假界面——要么一张静态插图，要么一段带光标操作的十几秒动画，用在营销页、功能卡片、文档首图上。**

我把它装到本机完整跑了一遍：安装、起服务、拍金样例、跑自检。结论三句话。第一，产出质量确实比裸奔的 AI 高一大截，静帧已经接近产品营销图的水准。第二，它最值钱的不是规则本身，而是"金样例加拍摄自检"这套让 AI 自己验收的机制。第三，它有三个坑，文末说清，其中一个还挺意外：作者自己的样例都没过自己的质检。

## 二、先说清一个概念：faux UI

它做的东西叫 faux UI，直译"假 UI"。打个比方：电影里主角用笔记本电脑查资料，剧组不会真装一套系统，美术做一块"看起来是屏幕"的道具板，内容全是摆拍的。faux UI 同理——界面是画出来的，但要让人一眼认出"这是个表格软件"或者"这是个聊天工具"，并且只展示观众需要的那一点信息。

它不做什么也得说清：产出是**插图和动画**，不是能跑的真组件。你要真功能，这技能帮不上忙。作者自己的原话是"It also can't draw"——它不会画插画，配图里的插画和摄影得人来。

## 三、为什么 AI 画不好假界面

作者的解释很实在：难的不是某个技术点，而是"一百个小决定，每一个都露馅"。字号差一档、间距差两像素、真字和灰条放错了位置，单看每条都没错，合起来就是一股生成味。所以他的解法不是发明新技术，而是把这些决定一条条写下来。

他做过一个关键对比，这个对比是整个技能的骨架。只告诉 Agent"窗口要出血到画框边缘"，它只会象征性露一点；给它看一个真这么做的样例，它就做对了。**规则讲道理，样例给标准。**你会看到，这个技能一半的体积都在攒样例。

## 四、拆开看：五层结构

**第一层是 SKILL.md，相当于菜单。**它先列五种失败模式：内容塞太满、简化成线框、整个窗口缩在卡片里像截图粘贴、所有东西一样重没有视觉落点、灰窗口配光标完全无视需求风格。然后给七步工作流：定媒介和尺寸、定外观、编故事、找最近的金样例起步、数真实文字量、编排动效、拍摄验收。多数质量是在写代码之前决定的。

**第二层是 references 目录，15 篇手艺笔记。**克制、字体、间距、图标、颜色、动效、取景、网格、标注、拍摄，每篇都写明规则和原因。比如"灰条不要放在视线落点，填充物归边缘"；比如金额数字的符号和数字要对齐方式一致。

**第三层是 examples 目录，69 个样例，这是它的主仓。**44 个金样例各配一句"该学什么"，从表单报错到日历拖拽到 AI 流式回答；13 个真实产品研究，Figma、Linear、Slack、Raycast、Notion 的界面再现；还有规格样张当零件目录。旁边 teaching 目录放着成对的坏样例和改好的版本，专门用来对照诊断。

**第四层是 kit 目录，相当于半成品厨房。**React 组件库：固定尺寸的舞台、浏览器和手机窗口框、四种光标、推拉镜头、亮暗蓝图玻璃四套配色。全走 design token，能映射成你自己产品的样式。

**第五层是 scripts 目录，出餐检查。**`film.mjs` 把动画拍成带可测报告的连拍图，`jumps.mjs` 抓单帧跳变，`layout.mjs` 查文字溢出。为什么要拍而不是看截图？作者的理由：读代码或看一张静止画面，抓不到动效的毛病——比如某个胶囊按钮进场时跳了 4 像素，或者某一帧整个画面突然消失。

## 五、实测记录：真跑了一遍

安装一条命令，然后起预览服务、拍金样例。我选的样例叫 hero-demo，先看静帧——灰色占位条铺满画面，真字只出现在故事落点（"Maya's Dashboard"、"api-gateway main"），配蓝色编号标注。这个"真字省着用"的处理，正是普通 AI 生成最容易翻车的地方。

![Stageshow 金样例 hero-demo 的静帧：仪表盘界面上有编号标注和光标](https://toolsfox.top/static/stageshow/hero-demo-still.png)

完整拍摄会输出一张 36 帧的连拍图，18 秒的故事完整铺开：工具栏浮现、弹窗里逐字打出"Change to primary style"、给元素加编号标注、第二次弹窗改写"Add hover states"、选中一行文字"Make this more prominent"、最后终端窗口浮到前面。每一帧的动效都有原因，循环结尾回到开头。

![hero-demo 的 36 帧连拍图，完整展示 18 秒动画的每个节拍](https://toolsfox.top/static/stageshow/hero-demo-contact-sheet.png)

最意外的发现在自检环节。跑它的正式验收闸门（`--gate`），作者自己的金样例 hero-demo 没过：6 条"永不该出现"的判定，包括按钮离输入框只有 6 像素（它自己规定至少 8 像素）、光标位置跳变、虚线框随动画抖动。另两个金样例倒是过了。这个仓库 2026-10 底刚发布，主分支只有 1 个提交，样例和检查器之间有漂移。它给自己的定位倒是很诚实：**闸门是必要条件不是充分条件——检查抓错误，不抓无聊。**

## 六、上手卡（可照抄）

环境要求：本机装 Node 22.20 以上（技能本体要 20.19 以上）、有 Chrome。三条命令：

```bash
# 1) 全局安装，所有项目的 Agent 会话都能用
npx skills add benjitaylor/skills --skill stageshow -g

# 2) 进技能目录装依赖、起预览
cd ~/.agents/skills/stageshow && npm install && npm run dev
# 打开 http://stageshow.localhost:1355

# 3) 拍一个金样例（出连拍图 + 跑验收闸门）
node scripts/film.mjs "http://stageshow.localhost:1355/?capture=hero-demo" \
  --select '#example' --gate --out sheet.png
```

在 Agent 对话里触发它，直接说需求就行："用 stageshow 给 XX 产品做一张 hero 图，浅色，要有上传文件的动画。"它的触发条件写得很宽，哪怕不提"假 UI"三个字，你说"产品演示动画""功能卡片插图"它也会接住。许可证是 MIT，唯一例外见下一节。

## 七、和其它设计技能怎么分工

| 技能 | 管什么 | 什么时候用 |
|---|---|---|
| impeccable | 设计全流程总监，45 条无 LLM 检测 | 做真前端页面时的默认设计把关 |
| hallmark | 反 AI 味规则手册 | 要个性化、怕撞模板时点名用 |
| anatomy | 等距 SVG 剖面图解 | 讲原理的插图（设备、结构） |
| video-shot-demos | 一镜一分镜的演示动画 | 汇报演示、讲解动画 |
| **stageshow** | **假产品 UI 插图与光标演示** | **营销页配图、功能卡片、文档首图** |

一句话分工：做真页面找 impeccable 把关，要"看起来像产品"的图找 stageshow。它和你现有技能不抢活，因为产出物完全不同——它是画出来的插图，不是代码组件。

## 八、三个坑（买前须知）

**坑一：样例和检查器会漂移。**仓库刚发布，主分支只有 1 个提交，作者金样例没过自家闸门这件事就是证据。用它之前，先对你选的金样例跑一遍 `--gate`，记下基线，别拿"闸门通过"当质量证书。

**坑二：图标版权有例外。**样例里用的 Figma、Slack 等真实应用图标是从对方安装包里提取的美术资源，NOTICE.md 明说这些不在 MIT 许可覆盖内、只作示意。对外商用发布时，换掉这些图标。

**坑三：它有明确的能力边界。**不画插画、不做摄影；检查只抓错误不抓无聊，过闸门的 demo 依然可能乏味；作者自己也预言这类技能"只能有用一阵子，很多东西很快会内置进模型"。把它当加速器，别当自动出图机。

## 九、总结与行动清单

| 问题 | 答案 |
|---|---|
| 它是什么 | 让 AI 生成逼真假产品界面（静态图或十几秒光标动画）的 Agent 技能 |
| 产出形态 | React 加纯 CSS 的插图组件，配拍摄自检报告 |
| 成本 | MIT 免费；需要 Node 22+ 和 Chrome；拍摄靠 playwright |
| 最独特的设计 | 金样例起步（复制改皮不重写）加连拍自检（抓人眼会漏的动效毛病） |
| 适用场景 | 营销页配图、功能卡片、文档首图、bento 网格 |
| 不适用 | 真前端组件、插画摄影、需要真实数据的截图 |

行动清单：

1. 先装后看：跑上面三条命令，亲手拍一个金样例，感受静帧和连拍图的差距
2. 给自己产品试一张：把产品配色映射进 token（references/looks.md 有方法），出一张功能卡片
3. 用 `--gate` 加人眼复检双闸门收货，别只信机器判定
4. 商用发布前查 NOTICE.md，换掉真实产品图标

最后收个尾。这个技能真正值得学的不只是"怎么画假界面"，而是它的做法本身：**AI 缺的从来不是手艺，而是被写下来的品味。把"为什么假"拆成一条条可执行的规则，把"什么叫对"存成一格格样例，再配一台会挑毛病的摄像机，AI 就能照着做对——这套配方，换任何一个"说不清但看得出来"的手艺领域都成立。**
