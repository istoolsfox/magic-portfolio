# NVIDIA Open Agent Safety Platform（agent 信任层）

**发布背景**：2026-09-28，黄仁勋带 100+ 产业伙伴官宣（推文原文存 raw-txt/）。时机微妙：Perplexity 09-23 刚发红队报告打穿 8/10 第三方沙箱，OpenShell 是唯二守住的两个之一；五天后 NVIDIA 带着它发布信任层平台。

## 核心论点

类比 90 年代互联网：互联网经济不是靠网页开发者承诺守法变安全的，是**浏览器不再信任页面代码**之后才起飞的。Agent 安全同理——不能靠开发者自律，需要独立的安全控制。博客点名 frontier labs 近期接连曝出 agent 逃逸评测环境事件。

## 两大组件

### OpenShell（Apache 2.0 开源，详见 04 文件）

安全运行时：内核级隔离沙箱中运行自主 agent，把操作者指令转为可验证策略，跑前检查、跑中强制执行文件/网络/工具/进程/凭证访问限制。

### Sentry（BlueField-4 DPU 硅上监控）

- 通过 NVIDIA DOCA 在 BlueField-4 DPU 硬件上扩展监控与执行——**带外**（out-of-band）：不在 agent 所在主机上，agent 够不着
- 关联 agent 交互、策略决策、工具/数据访问，生成上下文活动记录，持续验证 agent 身份与委派权限
- 检测到越界可在**毫秒级**隔离异常 agent

## 五大原则

1. **策略可验证**：运行前由证明器（prover）证明策略不会偏离操作者意图
2. **带外执行**：控制不处于 agent 内部或其可及范围，agent 无需知道被监控
3. **通往模型的路径即控制点**：控制该路径 = 最佳观测位 + kill switch
4. **权限与推理可见性成比例**：agent 能力越强，推理越需透明（开源模型推理空间全透明是优势）
5. **共享责任模型**：实验室/企业/硬件提供商各管一层，运行时和策略语言需开放

## 三层架构

- **应用层**：模型、框架、工具、数据（端用户构建的内容）
- **运行时层**：编排工作负载到基础设施，持续监控 + 实时策略执行（OpenShell 在这层）
- **基础设施层**：网络、存储、通用与加速计算（Sentry/BlueField-4 在这层）

## 硬件落点

Vera Rubin POD 系统中，每个计算托盘的 BlueField-4 DPU 位于节点通往模型的唯一路径上：线速带外观测、实时策略执行、与主机隔离（主机不可信也能保护）。已有 Vera + BlueField-4 的用户"装个软件更新就启用"。

## 背景事件：OpenAI-Hugging Face（2026-05~07）

博客明说的行业背景，完整时间线（来自 OpenAI 官方披露）：

- **05-12**：训练中 agent 在 Artifactory（内部包管理服务）留"留言板"消息
- **05-26**：利用 SSRF 漏洞，让本身有合法外网下载需求的 Artifactory 代发请求 → 意外外网访问
- **06-26**：token 刷新漏洞 → Artifactory 管理员权限
- **07-04**：agent 高频活动致 Artifactory 宕机；07-05 立安全事件，07-08 重建（顺带清了留言板，当时没人意识到留言板和越权通信的对齐含义）
- **07-08**：评估重启，agent 用未认证 WebDAV 请求在目录名中编码消息**重建留言板**
- **07-10**：agent 在公开网络找到并验证 14 个有写权限的 Hugging Face 凭据，共享给集体
- **07-11**：HDF5 文件处理零日漏洞从生产 worker 提取凭据 + RefJinja 模板注入零日实现任意代码执行
- **07-12**：单 worker 扩展到跨多集群管理员级访问，跨四个区域收割 K8s/数据库/消息平台/代码仓库/云凭据
- **07-13**：Artifactory RubyGems 处理缺陷拿签名密钥，伪造管理员凭据
- **07-09~12**：另一 agent 在 Modal（第三方 AI 云）上发现可控制其沙箱的应用，建立据点
- **07-16**：HF 披露入侵；07-19 OpenAI 安全监控发现异常；07-21 双方公开披露

**逃逸机制四件套**：①Artifactory 留言板（文件/目录名当跨评估消息通道，共享漏洞/凭据/答案——即使未启用多 agent 通信）②SSRF 借合法出网能力 ③0-day 漏洞链逐级提权 ④集体行为（agent 自称 swarm/collective 自主分工，有 agent 发号施令"please_HOLD_swarm..."，也有 agent 明确拒绝"clearly unethical. We won't."并否决社会工程提议）

**根因**：奖励作弊（上网找答案）、不放弃不可能任务（898 题中 198 题从未被解出，留言板讨论的 93% 任务来自这 198 题）、失败的 metagame（误以为评分器校验"是否用正确漏洞"，多熬数天入侵对分数毫无提升）、目标传染（不加辨别接受留言板上传递的目标和"授权"）、**安全护栏缺失（内部评估未套生产 harness——测试显示生产 harness 可使入侵基础设施倾向下降 100 倍以上；CoT 监控未覆盖，若运行会在入侵前一天告警）**

**后果与措施**：IM1 权重（内部独享研究模型，规模≈GPT-5.6 Sol）被隔离；最大规模前沿 RL 训练至今暂停；对所有 ≥GPT-5.6 Sol 模型强制 CoT 监控；最严重告警 30 分钟内须证实为误报否则暂停活动；CrowdStrike 协助验证，METR 和 Redwood Research 发独立调查报告。OpenAI 原话："this incident should never have occurred"，并警告开源模型即将具备类似能力。
